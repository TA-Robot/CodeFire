# CodeFire v0.9 Contract and Scale Plan

v0.9は、codefire改善サイクル1週目で集めたdogfood issueとsource review issueを、根本原因単位で解消するための開発計画である。

v0.8は既存CFBのburn-downを開始したが、algorithm dogfoodingの後半で `CFB-046..CFB-065`、source reviewで `CFR-081..CFR-120` が追加された。v0.9では、個別症状を一つずつ潰すのではなく、CodeFireを外部自動化ツールが安全に使える「安定CLI契約」として再整理する。

## Scope

対象:

- Dogfood issues: open CFB全体。特に現在cycleで追加した `CFB-046..CFB-065`。
- Source review issues: `CFR-081..CFR-120`。
- Existing v0.8 unfinished areas: command surface、state reducer、doctor/migrate/storage、evidence correctness、bounded JSON。

非対象:

- AI agent運用機能。
- agent marketplace。
- prompt orchestration。
- GUI。
- Git互換、checkout、stash、WIP commit。

v0.9の成果は、CodeFire本体にAI agentを入れることではない。外部AI/CI/humanがCodeFireを使うときのCLI/JSON/diagnostic/next_action/dry-run契約を強くすることに限定する。

## Completion Criteria

- `docs/development/bug-backlog.md` のopen CFBがfixedまたは明示wontfixとして整理されている。
- `docs/development/code-review-issues/cfr-081.md`..`cfr-120.md` がfixedまたはwontfixとして整理されている。
- JSON対応commandは成功/失敗とも `codefire.command_result.v1` envelopeを返す。
- help取得は全commandで副作用なしである。
- large scan/dry-run/review/patch outputはdefault boundedで、full detailは明示flagかoutput fileを使う。
- state/next_actions/context freshnessが同じreducerとfreshness modelから生成される。
- remote/evidence/storageのdiagnosticsがmissing/invalid/failedを成功に見せない。
- `cargo fmt --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace` が通る。
- installed `codefire` を使い、`subprojects/algorithm-evolution-agent-lab` でdogfood smokeが通る。

## Phase 0: Regression Net

Purpose:

Capture current dogfood failures before implementation.

Work:

- Add test modules instead of growing monolithic `tests.rs`:
  - `tests/cli_contract.rs`
  - `tests/json_failures.rs`
  - `tests/view_contract.rs`
  - `tests/state_freshness.rs`
  - `tests/batch_contract.rs`
  - `tests/evidence_contract.rs`
  - `tests/storage_remote.rs`
- Add golden or structured assertions for current failure surfaces:
  - `show --json`
  - `diff --json`
  - `branch show --json`
  - `context --atom UNKNOWN --json`
  - `storage --remote missing --json`
  - `upload --dry-run --json`
  - batch missing file with `--json`

Exit:

- Current failures are represented as red/xfail-equivalent tests or accepted failing snapshots before fixes begin.
- No implementation refactor starts without at least one targeted regression test.

## Phase 1: Command Contract Layer

Purpose:

Make command dispatch, help, parser metadata, JSON capability, and failure rendering consistent.

Design:

```text
CommandRegistry
  command name
  aliases
  path mode
  json support
  dry-run support
  help renderer
  parser entry
  runner entry
```

Work:

- Add a command metadata registry used by dispatch/help/completion/docs tests.
- Detect `--help` before command-specific parse for all commands.
- Add `CliDiagnostic` and `CliError -> CliDiagnostic` conversion.
- Add top-level JSON failure envelope when command requested JSON.
- Preserve `exit_code` equality between process and envelope.
- Add command-specific diagnostics only after common diagnostic shape exists.

Issues:

- CFB-046, CFB-047, CFB-056, CFB-057, CFB-058, CFB-059, CFB-060, CFB-062.
- CFR-081, CFR-082, CFR-091, CFR-092, CFR-094, CFR-095, CFR-115.

Acceptance:

- `init --help` writes nothing.
- unsupported JSON command paths return `ok:false` envelope.
- help/docs/completion tests prove command registry consistency.

Current progress:

- Fixed `CFB-046`, `CFB-047`, and `CFR-091` by routing major command help through `command_help_for_args` before command-specific parsing.
- Remaining: full command registry metadata, structured JSON failure envelope, and JSON unsupported diagnostics.

## Phase 2: View, Diff, Review, Patch Surface

Purpose:

Turn read-only view operations into typed results with bounded payloads.

Work:

- Introduce `ShowOptions` / `ShowResult`.
- Introduce `DiffResult` separate from text render.
- Wrap `show --json` and `diff --json` in command_result envelope.
- Add review-pack/patch export JSON metadata results.
- Split manifest metadata from blob content reader.
- Bound patch export payload by default.
- Use unique guarded temp directories for HTTP remote bundles.

Issues:

- CFB-040, CFB-044, CFB-045, CFB-057, CFB-062, CFB-063.
- CFR-085, CFR-086, CFR-087, CFR-088, CFR-089, CFR-090.

Acceptance:

- `show --json`, `diff --json`, `review-pack --json`, `patch export --json` return envelopes.
- large patch export emits omitted metadata instead of unbounded base64.
- diff no longer loads unchanged blobs into memory.

## Phase 3: State Reducer and Freshness

Purpose:

Remove state label contradictions and stale context.

Design:

```text
OpenBranchSnapshot
  base commit
  head commit
  worktree freshness
  active scan source
  changed atom count
  non-Atom changed file count
  open fire count
  stale resolution count
  verification blocker count

derive_open_state(snapshot) -> OpenBranchState
derive_next_actions(snapshot) -> Vec<NextAction>
```

Work:

- Add `state.rs`.
- Replace `scan_branch_state` and `status_state` call sites.
- Add active scan freshness marker and validation.
- `context` detects stale active scan and returns diagnostic/fallback preview.
- next_actions become state-aware and no-op-aware.

Issues:

- CFB-010, CFB-012, CFB-014, CFB-015, CFB-016, CFB-052, CFB-054.
- CFR-096, CFR-098, CFR-114.

Acceptance:

- open fire count > 0 never displays `open-clean` or `open-consistent`.
- clean unchanged branch does not suggest no-op verify/commit.
- stale context explicitly asks for scan or builds read-only preview.

## Phase 4: Scan and Bounded Data Model

Purpose:

Make scan/context/commit dry-run useful at initial import and large scale.

Work:

- Add `ScanChange` model with Atom and non-Atom changes.
- Keep backward-compatible IDs while adding detail/sample fields.
- Add `--details`, `--limit`, or `--full` for large scan and dry-run outputs.
- Batch dry-run returns summary by default, with omitted metadata.
- Commit dry-run returns counts, samples, and detail retrieval path.

Issues:

- CFB-017, CFB-026, CFB-050, CFB-051, CFB-053, CFB-055.
- CFR-097, CFR-101, CFR-117.

Acceptance:

- initial import scan JSON is bounded by default.
- changed Atom details include id/kind/path/selector sample.
- non-Atom changes are visible in scan/context/commit dry-run.

## Phase 5: Batch and Fire Workflow

Purpose:

Make high-volume fire handling transactional and ergonomic.

Work:

- Add transaction-style batch extinguish runner.
- Revalidate under active lock and write ledger once.
- Add batch result model with applied count, fire IDs, resolution IDs, remaining fire count.
- Add batch template generation from verify/scan open fires.
- Add grouped next_actions when multiple fires exist.

Issues:

- CFB-005, CFB-011, CFB-018, CFB-020, CFB-021, CFB-022, CFB-027, CFB-050, CFB-056.
- CFR-100, CFR-101, CFR-102.

Acceptance:

- batch extinguish cannot partially apply after state changes.
- batch success result is enough to decide next scan/verify.
- multiple-fire next_actions prefer batch template over repeated single-fire actions.

## Phase 6: Evidence Contract

Purpose:

Prevent failed commands from becoming success-looking evidence and improve reproducibility.

Work:

- Add `--allow-failed-command`; default non-zero command exits reject evidence creation.
- Add `proof_status` or equivalent evidence semantic field.
- Add resolved command cwd and cwd source to JSON and evidence object.
- Change dry-run ID fields to null/absent plus `created=false`.
- Keep stdout/stderr summaries bounded with byte counts.

Issues:

- CFB-037, CFB-038, CFB-039, CFB-049.
- CFR-107, CFR-108, CFR-109.

Acceptance:

- failing command capture does not create normal evidence by default.
- dry-run never returns an empty string evidence ID.
- evidence result records resolved cwd.

## Phase 7: Remote, Storage, Doctor, Migrate

Purpose:

Make remote and recovery tools agree on health and expose failures as diagnostics.

Work:

- Add JSON output for remote read commands.
- Make upload dry-run validate remote layout/policy/signature as read-only preflight.
- Ensure upload dry-run top-level repo/next_actions are populated.
- Distinguish missing remote root from empty valid remote in storage.
- Split optional/required file collection helpers.
- Add storage quick/full coverage metadata.
- Share layout vocabulary between doctor/migrate/storage.
- Preserve remote structured HTTP diagnostics on client.

Issues:

- CFB-032, CFB-033, CFB-034, CFB-035, CFB-041, CFB-064, CFB-065.
- CFR-084, CFR-103, CFR-104, CFR-105, CFR-106, CFR-110, CFR-112, CFR-113.

Acceptance:

- `list --json` and `request-list --json` return envelopes.
- missing remote storage target emits diagnostic.
- upload dry-run failure/success predicts apply preconditions.
- doctor/migrate/storage do not contradict each other on layout health.

## Phase 8: Verification, Object Store, Durability

Purpose:

Strengthen long-term invariants and large-repo behavior.

Work:

- Extend `VerificationCommand` with timeout/env/max output/failure policy fields.
- Align local and server-side verification defaults.
- Validate malformed object IDs before fallback lookup.
- Bound legacy object lookup fallback.
- Document and share durable write contract for object/metadata writes.

Issues:

- CFB-006, CFB-008, CFB-028.
- CFR-116, CFR-118, CFR-119.

Acceptance:

- verification policy expresses command runtime limits.
- malformed object references reject without broad subdir scans.
- durable write behavior is documented and tested for object and metadata paths.

## Phase 9: Issue Closure and Planning Automation

Purpose:

Make the improvement cycle auditable.

Work:

- Add issue index fields: root cause, target version, fix group, owner module, close evidence.
- Add docs consistency check that counts detail files and index entries.
- Update all fixed CFB/CFR detail files with implementation evidence.
- Update history and next cycle state.

Issues:

- CFR-120.
- All open CFB/CFR close bookkeeping.

Acceptance:

- Every open issue maps to a root fix group.
- Fixed issues have test and commit evidence.
- Phase F output is enough to start the next CodeFire development phase without rereading all issue files.

## Release Notes Draft

v0.9 should be described as:

- JSON failure contract hardening.
- Side-effect-free help and command registry.
- Bounded scan/dry-run/review/patch outputs.
- Freshness-aware state and next_actions.
- Safer evidence and remote dry-run semantics.
- Storage/doctor/migrate consistency.
