# CodeFire v1.0 Contract Validation Plan

v1.0は、codefire改善サイクル2週目で集めたdogfood issueとsource review issueを、CodeFireの「外部tool向け契約」と「内部永続化不変条件」の両面から解消するための開発計画である。

v0.9はCLI/JSON契約の整理を開始した。cycle 2では、同じ問題がさらに深い層で見つかった。具体的には、help/parser/metricsのcapability管理不足、next_actions schema drift、operation plan envelopeの弱さ、verification/explainのblocking semantics不一致、sealed commit/root validation不足、storage/context/migrationのlarge repo観測性不足である。

v1.0では、個別症状を直接潰すのではなく、以下の共通基盤を先に作る。

- Command capability registry。
- Unified command result envelope。
- Unified next action schema。
- State-aware verification/explain/action classification。
- Root type registry and commit certificate validation。
- Transactional operation plan model。
- Layout/health/observability registry。

## Scope

対象:

- Dogfood issues: open CFB全体。特にcycle 2で追加した `CFB-066..CFB-085`。
- Source review issues: open CFR全体。特にcycle 2で追加した `CFR-121..CFR-160`。
- v0.9 carryover: `CFB-046..CFB-065` と `CFR-081..CFR-120` のうち未完了のcontract/scale項目。
- Repository health: install、doctor、migrate、storage、remote dry-run、HTTP client。

非対象:

- AI agent運用機能。
- marketplace。
- prompt orchestration。
- GUI。
- Git完全互換。
- hosted service機能。

v1.0の成果は、CodeFire本体にAI agentを入れることではない。外部AI/CI/humanがCodeFireをtoolとして使うとき、help、JSON、exit code、next_actions、dry-run、evidence、commit validation、health checkが一貫して信頼できる状態を作る。

## Completion Criteria

- `docs/development/bug-backlog.md` のopen CFBがfixedまたは明示wontfixとして整理されている。
- `docs/development/code-review-issues/cfr-081.md`..`cfr-160.md` がfixedまたはwontfixとして整理されている。
- JSON対応commandは成功/失敗/dry-run/validation failureのすべてで `codefire.command_result.v1` envelopeを返す。
- 全public commandの `--help` が副作用なしで成功する。
- `--path`, `--json`, `--metrics`, `--dry-run` はcommand registryで対応可否が宣言され、黙って無視されない。
- `next_actions` は全commandで同じrequired fieldsを持ち、path/open_dir contextを失わない。
- verification、explain、context、next_actionsが同じblocking/non-blocking classificationを使う。
- sealed commit validationがrequired roots、root payload shape、certificate/verification consistencyを検証する。
- storage/context/migration/fire dry-runなどlarge output surfaceがboundedで、省略件数と再取得導線を返す。
- install後にactive binary path/version/help fingerprintを確認できる。
- `cargo fmt --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace` が通る。
- installed `codefire` を使い、`subprojects/algorithm-evolution-agent-lab` のdogfood smokeが通る。

## Phase 0: Issue Registry and Regression Net

Purpose:

Make all open issues executable as a close plan before large refactors begin.

Work:

- Add machine-checkable issue mapping for CFB/CFR:
  - `root_fix`
  - `target_version`
  - `owner_module`
  - `close_evidence`
  - `status`
- Add docs consistency test or script that verifies:
  - every CFB detail file is in `bug-backlog.md`
  - every CFR detail file is in `code-review-issues-2026-06-06.md`
  - every open issue maps to a root fix in this plan
- Add focused regression tests for current cycle 2 failures:
  - `migrate/context/explain --help`
  - `branch list --metrics --json`
  - `explain verify-failure --json`
  - `storage --quick --json`
  - `link --batch --dry-run --json`
  - `commit --json`
  - `context --changed --limit 2 --json`

Exit:

- All current CFB-066..085 and CFR-121..160 have a test, fixture, or explicit source-level close criterion.
- No implementation phase starts with unmapped open issues.

## Phase 1: Command Capability Registry

Purpose:

Stop parser/help/metrics/path/JSON support from drifting command by command.

Design:

```text
CommandSpec
  name
  aliases
  category
  path_mode
  supports_json
  supports_metrics
  supports_dry_run
  help_renderer
  parser
  runner
```

Work:

- Add `command_registry.rs`.
- Move `command_help_for_args` to registry-driven lookup.
- Encode `--path`, `--json`, `--metrics`, `--dry-run` support in `CommandSpec`.
- Make unsupported common options return JSON failure envelope when JSON was requested.
- Add `--key=value` support through common option parser.
- Update completion/help docs from registry data.
- Add install fingerprint check for active binary path/version/help after `install.sh`.

Issues:

- CFB-066, CFB-071, CFB-079, CFB-083, CFB-084, CFB-085.
- CFR-126, CFR-131, CFR-132, CFR-138, CFR-139, CFR-150.

Acceptance:

- Every public command supports `command --help` without side effects.
- `--metrics` is either implemented or rejected with structured unsupported option error.
- `--path=value` works for repo/open target commands that support path.
- install warns when the newly installed prefix is shadowed by an earlier PATH entry.

## Phase 2: Envelope and Operation Plan Contract

Purpose:

Make success, failure, validation failure, and dry-run output share one automation contract.

Work:

- Add `CommandEnvelopeBuilder`.
- Stop inferring top-level `repo` from payload field names; pass execution context directly.
- Normalize operation plan schema:
  - `repo_root`
  - `open_dir`
  - `branch`
  - `operation`
  - `validation_status`
  - `next_actions`
  - `created`
- Hoist plan next_actions to top-level envelope after schema validation.
- Distinguish applied result from apply plan so successful `commit --json` does not show apply-next-action.
- Wrap raw JSON commands such as `trace-graph` in envelopes.

Issues:

- CFB-057, CFB-058, CFB-059, CFB-060, CFB-062, CFB-065, CFB-067, CFB-070, CFB-080, CFB-084.
- CFR-081, CFR-085, CFR-086, CFR-087, CFR-110, CFR-113, CFR-154, CFR-155, CFR-160.

Acceptance:

- JSON requested failures never print plain text only.
- top-level `repo` is populated for repo/open commands.
- dry-run next_actions are available both in `data.plan.next_actions` and top-level `next_actions`.
- applied results do not include apply-plan actions.

## Phase 3: Unified NextAction and Blocking Semantics

Purpose:

Make next_actions executable, path-safe, and consistent with verification severity.

Design:

```text
NextAction
  kind
  reason
  command
  args
  target
    repo_root
    open_dir
    atom_id?
    fire_id?
  safety
  priority
  omitted_recovery?
```

Work:

- Replace module-local next_action JSON with shared type.
- Keep legacy aliases only behind compatibility fields.
- Make bounded next_actions report `omitted_by_kind` and command to retrieve the same action family with higher limit.
- Make `--blocking-only` filter diagnostics and next_actions consistently.
- Make explain text rendering use shared action renderer.

Issues:

- CFB-068, CFB-069, CFB-074, CFB-075, CFB-081.
- CFR-127, CFR-140, CFR-141, CFR-142, CFR-143, CFR-144, CFR-151, CFR-152, CFR-153, CFR-154.

Acceptance:

- scan/status/verify/context/explain/storage/migrate/doctor next_actions share one schema.
- path/open_dir is present for executable repo commands.
- passed verification with non-blocking warnings does not produce blocker language or blocking actions.
- omitted actions have an exact recovery command.

## Phase 4: Commit Root Registry and Certificate Validation

Purpose:

Make sealed commits self-validating and robust enough for remote transfer and future GC.

Work:

- Add root type registry:
  - root name
  - required by schema version
  - expected object type
  - payload validator
  - legacy policy
- Require `resolution_ledger` in current commit schema.
- Validate `atom_index`, `trace_graph`, `fire_delta`, `policy` payload shape where present.
- Derive certificate result from verification object and validate consistency.
- Introduce commit transaction metadata or pending manifest for multi-object writes.
- Teach doctor to report incomplete commit transactions and orphan objects with operation IDs.

Issues:

- CFR-121, CFR-122, CFR-123, CFR-130, CFR-159.
- Carryover: CFR-014, CFR-118, CFR-119.

Acceptance:

- malformed root payloads are rejected at commit validation time.
- certificate/verification mismatch fails validation.
- commit crash/fault injection leaves diagnosable pending operation metadata.
- doctor can distinguish harmless orphan object from interrupted operation artifact.

## Phase 5: Fire, Link, and Batch Transaction Model

Purpose:

Make fire/link operations safe under concurrency and useful at scale.

Work:

- Re-read and revalidate fire ledger under lock before applying manual fire operations.
- Split fire semantic identity from occurrence identity.
- Normalize manual fire display ID/UID with scan fire conventions.
- Change validation dry-run failure to top-level validation failure.
- Bound fire operation plan item details with counts/sample/truncated fields.
- Add path-aware next_actions to fire/link plans.
- Reuse batch transaction runner for link/fire/extinguish operations.

Issues:

- CFB-076, CFB-077, CFB-078.
- CFR-124, CFR-125, CFR-145, CFR-146, CFR-158.
- Carryover: CFR-100, CFR-101, CFR-102.

Acceptance:

- invalid dry-run cannot be mistaken for apply-ready success.
- concurrent manual fire creation does not duplicate display IDs.
- no-source-change manual fire cleanup can return to clean state without no-op commit pressure.
- fire/link dry-run remains bounded for large fire sets.

## Phase 6: Bounded Context, Storage, and Evidence Observability

Purpose:

Make CodeFire usable on large repos and readable by AI tools without losing important omitted information.

Work:

- Add `total_count`, `returned_count`, `omitted_count` by category in context.
- Make branch context include branch head, open fires, recent changes, and trace summary.
- Add atom traversal omitted metadata and recovery next_action.
- Make storage quick mode infer object type when possible.
- Replace largest-object vector sort with bounded top-N heap.
- Add `requested_cwd`, `resolved_cwd`, `cwd_source` to evidence dry-run and result.
- Keep stdout/stderr/evidence artifact summaries bounded with byte counts.

Issues:

- CFB-072, CFB-073, CFB-082.
- CFR-134, CFR-135, CFR-136, CFR-137, CFR-147, CFR-157.
- Carryover: CFR-105, CFR-106, CFR-107, CFR-108, CFR-109, CFR-117.

Acceptance:

- bounded context always reports omitted counts and retrieval route.
- storage quick reports useful object type or confidence metadata.
- evidence dry-run shows exactly where command capture will run.
- large object/context outputs have stable default upper bounds.

## Phase 7: Layout, Migration, Remote, and HTTP Health

Purpose:

Make recovery and remote commands agree on repo health and fail safely.

Work:

- Add shared layout registry used by init/doctor/migrate/storage.
- Make active state expected files and invariants explicit.
- Add doctor checks for missing active state files and state/open_fires contradictions.
- Add migration current target registry instead of hardcoded `v0.6`.
- Add quick/full/limit mode for migration JSON scanning.
- Bound HTTP client response body size.
- Validate HTTP request-merge dry-run source/target heads.
- Make remote read commands return envelopes and diagnostics.

Issues:

- CFB-061, CFB-064, CFB-071, CFB-084.
- CFR-128, CFR-129, CFR-132, CFR-133, CFR-148, CFR-149, CFR-156.
- Carryover: CFR-103, CFR-104, CFR-110, CFR-112.

Acceptance:

- doctor/migrate/storage do not contradict each other on required layout.
- missing remote or invalid remote preflight is not silent success.
- HTTP response body limit is enforced before allocation growth.
- request-merge dry-run validates branch heads or explicitly marks offline validation.

## Phase 8: Close Evidence, Install, and Dogfood Gate

Purpose:

Close issues with implementation evidence and prove the installed binary is the one being dogfooded.

Work:

- Update each fixed CFB/CFR detail file with:
  - fixed status
  - implementation summary
  - test command
  - commit hash
  - dogfood evidence
- Update backlog/index counts.
- Install CodeFire and verify active binary path.
- Run algorithm dogfood smoke.
- Record any new findings as the next cycle input rather than mixing them into v1.0 close evidence.

Verification commands:

```bash
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
bash -n install.sh
./install.sh --prefix /home/devuser/.cargo
which codefire
codefire --version
codefire --help
cd subprojects/algorithm-evolution-agent-lab
codefire status --path . --json
codefire scan --path . --json --metrics
codefire context --changed --path . --limit 2 --json
codefire verify --path . --details --blocking-only --json --metrics
codefire explain verify-failure --path . --json
codefire storage . --quick --json
codefire doctor . --json
codefire migrate check . --json
```

Exit:

- v1.0 target issues are fixed/wontfix with close evidence.
- installed binary dogfood smoke passes.
- codefire改善サイクル state is updated to Phase B/C for the next loop.

## Release Notes Draft

v1.0 should be described as:

- Command capability registry and side-effect-free help for all public commands.
- Unified command result envelope for success, failure, dry-run, and validation failure.
- One next_actions schema with path-safe executable actions.
- Correct blocking/non-blocking verification and explain semantics.
- Strong sealed commit root and certificate validation.
- Transaction-aware fire/link/commit operations.
- Bounded context/storage/evidence output for large repos.
- Shared layout, migration, doctor, storage, remote, and HTTP health contracts.
