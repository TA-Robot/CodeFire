# CodeFire v0.7 Issue Improvement Plan

v0.7は、`docs/development/code-review-issues-2026-06-06.md` に登録した `CFR-001..CFR-080` をすべて改善対象にするhardening releaseである。

## Scope

- 対象: CodeFire本体のRust CLI/core/store/remote/diff/signature/installer/docs。
- 対象issue: `CFR-001..CFR-080`。
- 非対象: AI agent運用機能、agent marketplace、prompt orchestration。
- 完了条件: 各CFRが `fixed` または明示的な `wontfix` になり、該当する仕様・テスト・履歴が更新されていること。

## Batch 1 Result

Status: implemented and verified.

- `CFR-005`: clean scan now prints explicit `Changed atoms: none` and `Open fires: none`.
- `CFR-006`: successful verify output now includes the same major counters as failure output.
- `CFR-010`: `write_json_atomic` now uses unique temp paths with `create_new`.
- `CFR-031`: HTTP request parsing now rejects bodies above `MAX_HTTP_BODY_BYTES`.
- `CFR-032`: HTTP request parsing now rejects truncated bodies before JSON parsing.
- `CFR-047`: link batch append now uses unique temp paths with `create_new`.
- `CFR-058`: `CODEFIRE_TLS_INSECURE` only enables insecure TLS for explicit truthy values.
- `CFR-067`: empty remote idempotency keys are ignored instead of being treated as present keys.
- `CFR-077`: `cf+http` / `cf+https` remote URLs now require exact path segment counts.

## Batch 4 Result

Status: implemented and verified.

- `CFR-019`: explicit `cf-atom:` content hashes now cover the marker block through the line before the next explicit marker, so Python/Rust body changes update Atom hashes even when the marker line is unchanged.
- `CFR-020`: Atom ID validation now uses shared `is_valid_atom_id` for Markdown headings and explicit `cf-atom:` comments. Invalid explicit IDs fail with artifact/line diagnostics, while legacy Python reference `CODE:<path>::<symbol-kind>:<symbol>` IDs remain valid.
- `CFR-021`: Markdown Atom extraction now tracks backtick/tilde fenced code blocks and ignores heading-like text inside fences while preserving normal heading extraction outside fences.
- `CFR-022`: core links/policy limited YAML parsers now reject unsupported root keys, fields, list forms, and indentation with line-numbered config diagnostics instead of silently ignoring them.
- `CFR-023`: new trace links use bounded `LINK-sha256-<32hex>` IDs, and stale resolution checks retain compatibility with legacy raw link IDs and hashes.
- `CFR-024`: required link checking now builds an Atom kind map and `(from, type, target_kind)` link count index once, avoiding per-Atom/per-rule full link scans.

## Batch 6 Result

Status: implemented and verified.

- `CFR-030`: HTTP client connect/read/write timeout is now bounded by `CODEFIRE_HTTP_TIMEOUT_MS` or 30000ms default.
- `CFR-033`: HTTP server request handling now uses bounded per-connection handler threads, server-side stream timeouts, and a regression test that proves a slow connection does not block the next request.
- `CFR-034`: HTTP upload server tmp directory is unique per request and cleanup only removes that request directory.
- `CFR-035`: Remote generation allocation now requires a `RemoteGenerationLock` guard backed by `generation.lock`, and parallel allocation is tested for duplicate-free monotonic generations.
- `CFR-068`: Remote idempotency records are hash-only and no longer persist full payloads or signature/request metadata.
- `CFR-069`: Storage report reads `gc.idempotency_retention_seconds` and warns on expired remote idempotency records with count/bytes/oldest metadata.
- `CFR-070`: Remote idempotency replay no longer reuses saved operation plans; replay results expose replay metadata instead.
- `CFR-078`: HTTP endpoint parser supports bracketed IPv6 authority and rejects malformed IPv6 authority.
- `CFR-079`: HTTP server request parser allow-lists methods/version and rejects invalid/unsafe paths before dispatch.

Verification:

```bash
cargo test -p codefire-cli --bin codefire-rs http::tests -- --nocapture
```
