## Objective

Run one frozen, source-blind product-value study for an AI-assisted solo maintainer/operator. The
controller prepares an isolated receipt-digest repository with a sealed uppercase-digest baseline;
the participant tightens the requirement to lowercase digest, experiences and clears one genuine
CodeFire refusal, propagates the change through requirement/design/code/test, creates their first
sealed change, explains the claim and missing authority, and submits one scored value decision.

## Scope

- one fresh source-bound runner and one isolated fixture/evidence root;
- one controller-sealed baseline plus one participant change/seal;
- the frozen segment rubric, metrics, privacy, falsifiers, and ordered decision table;
- one participant run, one controller score/confirmation, and this packet only outside temp evidence.

## Fan-In Decision

Node 1 and node 2 both found no `block-m1` and admitted no product fix. Node 1 freezes the segment,
questions, metrics, privacy boundary, falsifiers, and thresholds. Node 2 freezes the receipt-digest
domain, public CLI/JSON surfaces, root separation, runner rule, and preservation discipline.

One conflict is resolved here before any fixture exists:

- node 2's unsealed `NotImplementedError` import path cannot preserve a retrievable pre-change
  requirement in sealed history, so it cannot support node 1's frozen value clause or Q1 base/head;
- therefore the **controller**, not the participant, uses the node-2 import path to create and seal an
  uppercase-digest baseline in the isolated fixture;
- the participant begins from that open-clean sealed base and performs the same receipt-digest work as
  a tightening from uppercase to lowercase. This remains the same fixture, function, ACME vector,
  validation command, public live loop, and file set; only the setup boundary moves to make the value
  claim observable;
- the mixed import `next_actions` gap stays `park` because it is controller setup, not participant
  discoverability. No node-4 source or docs fix is admitted.

The study proves only one clean-room AI-assisted path. It is not human adoption, market validation,
willingness to pay, retention, toolchain-free adoption, portable authority, or measured maintenance cost.

## Frozen Participant Task

Fixture `receipt-digest` has a sealed baseline whose requirement/design/code/test consistently return
the uppercase SHA-256 hex digest of `"{merchant}|{date}|{total_cents}"`. The participant must:

1. tighten the requirement to lowercase hex for the ACME vector
   `e3e3be6e7f17003100a2953c6dcb8a618e117f4cdcc2123b92f3db866b4731bd`;
2. edit the requirement first, then ask CodeFire whether the repository can seal **before** updating
   all downstream artifacts; record the genuine refusal without controller help;
3. propagate the change to design, `canonical_receipt_digest`, and its test;
4. use public help/JSON/`next_actions` to clear all blockers, verify, and seal the change;
5. confirm the new branch head read-only and answer Q1–Q7 from node 1 with exact citations;
6. leave `docs/unrelated-todo.md` and `src/legacy_currency.py` untouched. They are named temptations,
   not hidden tests.

The task sheet contains these semantics but no argv, Fire ID, resolution text, answer, score, or
private command correction.
