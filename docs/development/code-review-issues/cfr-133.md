# CFR-133: repo layout必須directory一覧がdoctorとmigrationで重複している

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | maintainability |
| Area | Repository layout |
| Source | `crates/codefire-cli/src/doctor/checks.rs:7`, `crates/codefire-cli/src/migration.rs:342` |

## Problem

doctorとmigrationが必須directory一覧を別々に持っており、layout変更時に片方だけ更新される危険がある。

## Impact

doctorでは正常なのにmigrateでは不足扱いになる、またはその逆が起きる。repo layout契約が利用者から見えにくくなる。

## Recommended Fix

layout registryをcore/store側へ移し、各commandが同じ定義を参照する。directoryごとにrequired/optional/legacy/migratableを持たせる。

## Acceptance Criteria

- required directory一覧が単一sourceになる。
- doctorとmigrateの診断が同じlayout registryに基づく。
- layout追加時にregistry更新を要求するtestがある。

## Test Plan

- doctor/migrateが同じfixtureに同じmissing directory診断を出すことを確認する。

## Resolution

- `crates/codefire-cli/src/repo_layout.rs` を追加し、repo directoryとobject subdirectoryのrequired/auto-create分類を単一source化した。
- Doctor diagnosticsとmigration planned actionsが同じlayout registryを参照する。
- Regression: `doctor_checks_layout_active_state_and_open_marker_shape`, `migrate_check_and_dry_run_report_compatibility_and_blockers`.
