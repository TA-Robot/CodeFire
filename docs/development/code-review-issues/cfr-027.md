# CFR-027: diff出力にhunk化・context制限がない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | performance |
| Area | Diff |
| Source | `crates/codefire-cli/src/view/file_diff.rs:246` |

## Problem

`render_line_delta` はequal行を出さない一方、変更行は全て列挙し、hunk headerやcontext行数の概念がない。

## Why It Matters

レビューしにくく、変更量が大きいとログが巨大化する。

## Failure Mode / Review Hypothesis

入力規模が増えたときに処理時間またはメモリ使用量が急増する可能性がある。レビューしにくく、変更量が大きいとログが巨大化する。

## Code Evidence

- Primary source: `crates/codefire-cli/src/view/file_diff.rs:246`
- Observed implementation fact: `render_line_delta` はequal行を出さない一方、変更行は全て列挙し、hunk headerやcontext行数の概念がない。

## Recommended Fix

unified diff互換のhunk化、context行数、最大出力byte数を導入する。

## Implementation Notes

- Priority: 大規模repoや実験artifactが増える前に上限設計を入れる。
- First step: 最悪ケースの入力サイズを決め、修正前後の計算量と実測を比較する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: [CFR-025](cfr-025.md), [CFR-026](cfr-026.md)

## Acceptance Criteria

- `--context <n>` と最大出力制限がある。
- 省略時に何行省略したか表示する。
