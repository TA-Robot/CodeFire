# CFR-143: next_actions schemaがmoduleごとに重複して揺れている

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | maintainability |
| Area | Automation JSON |
| Source | `crates/codefire-cli/src/automation.rs:402`, `crates/codefire-cli/src/storage.rs:241`, `crates/codefire-cli/src/migration.rs:161` |

## Problem

automation本体のnext_actionsは `kind/reason/target` 系だが、storage/migration/doctor/explainなどは `id/description/context` 系の独自schemaを返す。

## Impact

AI toolがnext_actionsを汎用的に実行・表示できず、command別adapterが必要になる。

## Recommended Fix

`NextAction` structを共通型にし、全commandが同じserializerを使う。表示専用textは別fieldに分離する。

## Fix

Implemented in the global burn-down pass:

- `automation::next_action` is the shared serializer for top-level next actions.
- The serializer emits canonical `kind`, `command`, `reason`, and `target` fields.
- Compatibility aliases `id`, `description`, and `context` are preserved.
- `command_result_envelope` normalizes legacy next action payloads before bounding them.
- Representative tests assert common next action schema for doctor, storage, migration, and explain.

## Acceptance Criteria

- 全JSON resultのnext_actionsが同じrequired fieldsを持つ。
- legacy schemaが必要ならversioned fieldとして残る。
- schema driftをsnapshot testで検出する。

## Test Plan

- representative commandsのnext_actions JSON schema testを追加する。
