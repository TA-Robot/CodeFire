# CFR-155: plan result envelopeがrepo_root以外のrepo fieldを読まない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | ux |
| Area | JSON envelope |
| Source | `crates/codefire-cli/src/main.rs:1317`, `crates/codefire-cli/src/main.rs:3223` |

## Problem

`plan_result_envelope` はpayload内の `repo_root` だけをrepoとして拾うが、operation plan側は `repo` など別名fieldを使う経路がある。

## Impact

top-level repoがnullになると、AI toolが次commandにpathを継承できない。dry-runからapplyへの安全な遷移が弱くなる。

## Recommended Fix

operation plan schemaを統一し、repo/open_dir field名を共通化する。暫定的には `repo`, `repo_root`, `open_dir` をnormalizeしてenvelopeへ反映する。

## Acceptance Criteria

- dry-run resultのtop-level repoがnullにならない。
- plan schemaでrepo field名が統一される。
- legacy field名の扱いがtestされる。

## Test Plan

- `open --dry-run --json` でtop-level repoが入ることを確認する。
