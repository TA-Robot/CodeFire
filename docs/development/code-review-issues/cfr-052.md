# CFR-052: doctorがactive stateのJSON shapeを検証していない

## Problem

active state filesはJSONとして読めるかだけ確認し、schemaや必須fieldは見ない。

## Why It Matters

壊れた `fires.json` や `state.json` がJSONとしてvalidなら見逃す可能性がある。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件・並行実行・破損状態でCodeFireの整合性判断がずれる可能性がある。 壊れた `fires.json` や `state.json` がJSONとしてvalidなら見逃す可能性がある。

## Code Evidence

- Primary source: `crates/codefire-cli/src/doctor/checks.rs:226`
- Observed implementation fact: active state filesはJSONとして読めるかだけ確認し、schemaや必須fieldは見ない。

## Recommended Fix

active state用の型/schema validationを追加する。

- 破損時に修復/再scan next_actionを出す。

## Test Plan

- invalid active state shape doctor test。

## Resolution

- Fixed in v0.7: doctor now validates active state file shapes instead of only checking that they are syntactically valid JSON.
- `state.json` must contain a supported string `state`, optional `pending_merge_parent` must be a string, and `fires.json`, `resolutions.json`, `scan.json`, and `verification.json` are deserialized into their CodeFire core types.
- Invalid active state shape emits `invalid_active_state_shape` and drives the `reopen_branch_workspace` next action.
