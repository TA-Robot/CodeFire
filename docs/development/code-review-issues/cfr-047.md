# CFR-047: link batch appendの一時ファイル名が固定

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | correctness-risk |
| Area | Link batch |
| Source | `crates/codefire-cli/src/link_batch.rs:284` |

## Problem

`append_links` は `path.with_extension("yaml.tmp")` を使う。

## Why It Matters

並行link更新や異常終了時にtmp衝突、残骸、rename競合が起き得る。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件・並行実行・破損状態でCodeFireの整合性判断がずれる可能性がある。 並行link更新や異常終了時にtmp衝突、残骸、rename競合が起き得る。

## Code Evidence

- Primary source: `crates/codefire-cli/src/link_batch.rs:284`
- Observed implementation fact: `append_links` は `path.with_extension("yaml.tmp")` を使う。

## Recommended Fix

共通atomic write APIを使い、unique temp名とdirectory syncを入れる。

## Implementation Notes

- Priority: v0.6 hardeningで優先的に扱う。整合性、security、性能、または配布品質に直接影響する。
- First step: 最小fixtureで現状の境界挙動を固定してから修正する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: [CFR-048](cfr-048.md), [CFR-049](cfr-049.md)
