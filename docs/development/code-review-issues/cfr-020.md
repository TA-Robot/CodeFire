# CFR-020: Atom ID validationが経路ごとに違う

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | correctness-risk |
| Area | Atom extraction |
| Source | `crates/codefire-core/src/lib.rs:1180`, `crates/codefire-core/src/lib.rs:1222` |

## Problem

Markdown heading Atomは `is_valid_heading_atom_id` を通るが、明示 `cf-atom:` は空でない文字列なら受け入れる。

## Why It Matters

invalid Atom IDがcode/test側から混入し、linkやpolicyの前提を崩す可能性がある。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件や並行実行でCodeFireの整合性表示・保存結果がずれる可能性がある。invalid Atom IDがcode/test側から混入し、linkやpolicyの前提を崩す可能性がある。

## Code Evidence

- Primary source: `crates/codefire-core/src/lib.rs:1180`, `crates/codefire-core/src/lib.rs:1222`
- Observed implementation fact: Markdown heading Atomは `is_valid_heading_atom_id` を通るが、明示 `cf-atom:` は空でない文字列なら受け入れる。

## Recommended Fix

`AtomId` newtypeと単一validatorを導入し、全extractorで使う。

## Implementation Notes

- Priority: 機能追加の前後で一緒に片付ける。単独修正でも価値はあるが、関連領域の改修時にまとめると効率がよい。
- First step: 小さな再現fixtureを作って、現状の挙動を固定してから修正する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: [CFR-019](cfr-019.md), [CFR-021](cfr-021.md)

## Acceptance Criteria

- Markdown/code/testで同じAtom ID規則が適用される。
- 不正IDはdiagnostic付きで報告される。
