# CFR-120: source reviewで見つかったissue群をroot cause計画へ自動接続できない

## Summary

| Field | Value |

| Status | open |

## Problem

CFRは1 issue 1 fileで詳細化されているが、open CFRをroot cause、修正module、次version phaseへ機械的に接続するindex schemaが弱い。人間が読めば分かるが、次version plan作成時に重複排除や束ね方を手作業で行う必要がある。

## Why It Matters

codefire改善サイクルでは、dogfood issue 20件とsource review issue 40件を束ねて次version計画へ戻す。issue数が増えるほど、root cause mapがないと場当たり修正や重複issueが増える。

## Failure Mode / Review Hypothesis

同じ根本原因を持つJSON envelope issueがCFR/CFBに分散し、次version planで漏れたり重複修正されたりする。修正完了後のclose確認も手動で不完全になる。

## Code Evidence

- Primary source: `docs/development/code-review-issues-2026-06-06.md:1`
- Observed implementation fact: index is human-readable table中心。
- Related source: `docs/development/codefire-improvement-cycle.md:1`
- Observed implementation fact: cycle process requires root cause grouping and next version mapping.

## Recommended Fix

CFR/CFB indexに `Root Cause`, `Fix Group`, `Target Version`, `Owner Module`, `Close Evidence` の列またはmachine-readable sidecarを追加する。次version planはこのmappingをsource of truthとして生成/検証する。
