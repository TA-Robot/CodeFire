# CFR-086: `diff --json` がcommand_result envelopeではなくraw JSONを返す

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | maintainability |
| Area | Diff CLI |
| Source | `crates/codefire-cli/src/main.rs:351`, `crates/codefire-cli/src/view.rs:144` |

## Problem

`diff` はJSON optionを持つが、view layerで作ったdiff JSONをraw outputとして返す経路がある。`schema`、`command`、`ok`、`exit_code`、diagnostics、next_actionsを持つ標準envelopeとは一致しない。

## Why It Matters

diffはAI toolが変更影響を確認する主要commandである。raw JSONだと他commandと共通のエラー処理、metrics、next_actions、repo contextを扱えない。

## Failure Mode / Review Hypothesis

`diff --json` 成功時はraw JSON、失敗時はtext errorになる。automationはdiffだけ別adapterを必要とし、unknown branchやremote error時にstructured diagnosticを失う。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:351`
- Observed implementation fact: diff output string is printed directly.
- Related source: `crates/codefire-cli/src/view.rs:144`
- Observed implementation fact: diff function returns renderable `String`, not a typed result plus renderer.

## Recommended Fix

`DiffOptions` / `DiffResult` を導入し、file diff、semantic diff、omissions、limits、input commitishをtyped dataとして返す。JSON modeはenvelope、text modeはrendererへ分離する。

## Implementation Notes

- Priority: medium-high。review automationの基礎。
- First step: current `diff --json` shapeを固定し、新envelopeへのmigration testを追加する。
- Boundary: diff algorithm自体の改善とは分ける。
- Related issues: CFB-062, CFR-087, CFR-089.

## Acceptance Criteria

- `diff --json` が `codefire.command_result.v1` envelopeを返す。
- `data` にinput commitish、resolved commit IDs、file summary、semantic summaryがある。
- failure pathもstructured diagnosticを返す。

## Test Plan

- local diff、remote diff、unknown target diffのJSON testsを追加する。
- golden fixtureはtext renderer用とJSON contract用を分ける。
