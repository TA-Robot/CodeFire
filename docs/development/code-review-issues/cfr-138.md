# CFR-138: context parserが--path=などのequals形式に対応していない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | compatibility |
| Area | CLI parser |
| Source | `crates/codefire-cli/src/context.rs:49`, `crates/codefire-cli/src/context.rs:57` |

## Problem

context parserは `--path value` 形式を処理するが、他commandで使える `--path=value` や `--atom=value` 形式に揃っていない。

## Impact

AI toolやshell generatorが同じ引数構築ロジックを使い回せない。

## Recommended Fix

CLI parser helperを共通化し、long optionの `--key value` と `--key=value` を全commandで統一する。

## Fix

Implemented in the global burn-down pass:

- `context --path=...` is accepted.
- `context --atom=...`, `--fire=...`, `--depth=...`, and `--limit=...` are accepted.
- Parser coverage was updated in `parse_context_args_accepts_selectors_depth_path_and_json`.

## Acceptance Criteria

- contextの主要optionがequals形式で動く。
- parser consistency testで全commandのlong option対応を検証する。
- unsupported option errorに候補が出る。
