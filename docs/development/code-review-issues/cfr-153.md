# CFR-153: doctor next_actionsがautomation共通schemaを使っていない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | maintainability |
| Area | Doctor |
| Source | `crates/codefire-cli/src/doctor/report.rs:30`, `crates/codefire-cli/src/automation.rs:402` |

## Problem

doctor reportは独自の診断とnext action表現を持ち、automation共通schemaと統合されていない。

## Impact

doctorはrepo破損やmigration不足を修復する中心commandだが、schemaが揺れるため自動修復計画に変換しづらい。

## Recommended Fix

doctor issueとnext_actionを共通diagnostic/action modelに接続し、severity、target、command、safetyを統一する。

## Fix

Implemented in the global burn-down pass:

- Doctor next actions now use `automation::next_action`.
- Repair/inspection metadata is emitted under canonical `target`, with legacy `context` alias preserved.
- Regression coverage asserts the common next action schema for doctor corruption reports.

## Acceptance Criteria

- doctor JSONのnext_actionsが共通schemaになる。
- issueごとに修復可能/手動対応の区別が出る。
- doctor text outputも同じaction dataから生成される。

## Test Plan

- doctor issue fixtureでnext_actions schemaをassertする。
