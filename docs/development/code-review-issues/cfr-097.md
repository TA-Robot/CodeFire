# CFR-097: scan JSONの`changed_atoms`がID配列だけで詳細不足

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | ux |
| Area | Scan JSON |
| Source | `crates/codefire-cli/src/automation.rs:96`, `crates/codefire-core/src/lib.rs:170` |

## Problem

scan JSONの `changed_atoms` は文字列ID配列であり、Atom kind、path、selector、change reason、hash差分、関連fire countなどの情報がない。dogfoodingではshapeを誤読しやすい問題として現れた。

## Why It Matters

AI toolはscan後にどのdocs/code/testを開くべきか判断したい。IDだけでは追加context取得が必須になり、round tripが増える。大量変更時には優先順位づけも難しい。

## Failure Mode / Review Hypothesis

toolが `changed_atoms` をobject配列と仮定して失敗する、またはIDからpathを再解決できずcontextを広く取りすぎる。人間もJSONだけでは変更影響を把握しにくい。

## Code Evidence

- Primary source: `crates/codefire-cli/src/automation.rs:96`
- Observed implementation fact: `scan_data_json` serializes changed atom IDs directly.
- Related source: `crates/codefire-core/src/lib.rs:170`
- Observed implementation fact: core `ScanResult.changed_atoms` is `Vec<String>`.

## Recommended Fix

後方互換のため `changed_atom_ids` を明示しつつ、`changed_atoms_detail` またはversioned scan dataでAtom metadataを返す。core `ScanResult` もIDだけでなくsummaryを持つ構造へ移行する。

## Implementation Notes

- Priority: medium。
- First step: current shapeをdocsに明記し、detail追加testを設計する。
- Boundary: full source contentは入れず、metadataに限定する。
- Related issues: CFB-055.
