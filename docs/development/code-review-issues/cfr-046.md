## Problem

link batchは独自にJSON/限定YAMLをparseし、evidence/fire/extinguish batchにも類似parserがある。

## Why It Matters

batch形式追加時に仕様差分やエラー文言差分が増える。

## Failure Mode / Review Hypothesis

機能追加時に同じ仕様を複数箇所へ反映する必要があり、修正漏れや不変条件破壊につながる。 batch形式追加時に仕様差分やエラー文言差分が増える。

## Code Evidence

- Primary source: `crates/codefire-cli/src/link_batch.rs:335`
- Observed implementation fact: link batchは独自にJSON/限定YAMLをparseし、evidence/fire/extinguish batchにも類似parserがある。

## Recommended Fix

共通のlimited YAML/JSON batch parser helperを作り、schemaだけ各commandで定義する。

## Acceptance Criteria

- 各batch commandのunsupported構文の挙動が揃う。

## Test Plan

- batch parser contract tests。

## Resolution

- Fixed in v0.7: `crates/codefire-cli/src/limited_yaml.rs` centralizes limited YAML comment stripping, key/value parsing, scalar unquoting, and integer parsing for `link --batch`, `evidence add --batch`, `fire --batch`, and `extinguish --batch`.
- Command-specific parsers now keep only schema/section validation and pass their YAML context string into the shared helper, so unsupported syntax and scalar/comment handling share one implementation.
- Added limited YAML contract tests for quoted comments, escaped quotes, scalar unquoting, missing colon errors, and integer parsing errors.
