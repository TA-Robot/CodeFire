# CFR-023: trace link IDが生Atom ID連結で長大化・衝突曖昧化し得る

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |

## Problem

link IDは `LINK-{from}-{type}-{to}` で、escapeやdigestを使っていない。

## Why It Matters

長いAtom IDでlink IDも長大化し、区切り文字を含むIDでは人間にも機械にも分解が曖昧になる。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件や並行実行でCodeFireの整合性表示・保存結果がずれる可能性がある。長いAtom IDでlink IDも長大化し、区切り文字を含むIDでは人間にも機械にも分解が曖昧になる。

## Code Evidence

- Primary source: `crates/codefire-core/src/lib.rs:927`
- Observed implementation fact: link IDは `LINK-{from}-{type}-{to}` で、escapeやdigestを使っていない。

## Recommended Fix

link identityをcanonical JSON digestへ寄せ、表示用summaryと内部IDを分ける。

## Implementation Notes

- Fixed in v0.7: new trace links use `LINK-sha256-<32hex>` IDs derived from canonical `from` / `to` / `type` JSON instead of raw Atom ID concatenation.
- Link hash calculation still includes the emitted link ID, so changed link identity is reflected in sealed graph contents.
- Stale resolution checks index both the new digest ID/hash and the legacy raw `LINK-{from}-{type}-{to}` ID/hash for current links, preserving read compatibility with resolutions sealed before v0.7.
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: none identified in this review batch.
