# CFR-026: 類似度計算が巨大ファイルのLCSを無制限に使う

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | performance |
| Area | Diff |
| Source | `crates/codefire-cli/src/view/file_diff.rs:218`, `crates/codefire-cli/src/view/file_diff.rs:402` |

## Problem

`similarity_score` はline数上限なしで `lcs_pairs` を呼ぶ。

## Why It Matters

生成物や大きいログファイルが含まれるとCPU/メモリを消費しやすい。

## Failure Mode / Review Hypothesis

入力規模が増えたときに処理時間またはメモリ使用量が急増する可能性がある。生成物や大きいログファイルが含まれるとCPU/メモリを消費しやすい。

## Code Evidence

- Primary source: `crates/codefire-cli/src/view/file_diff.rs:218`, `crates/codefire-cli/src/view/file_diff.rs:402`
- Observed implementation fact: `similarity_score` はline数上限なしで `lcs_pairs` を呼ぶ。

## Recommended Fix

file size、line count、unique line countの上限を設け、超過時はhash/size based summaryに切り替える。

## Implementation Notes

- Priority: v0.6 hardeningで優先的に潰す。整合性、security、または大規模運用での破綻につながる。
- First step: 最悪ケースの入力サイズを決め、修正前後の計算量と実測を比較する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: [CFR-025](cfr-025.md), [CFR-027](cfr-027.md)

## Acceptance Criteria

- 大型fileでLCSを実行しないguardがある。
- `--no-rename-detection` なしでも安全な上限が効く。
