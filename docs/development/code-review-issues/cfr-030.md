# CFR-030: HTTP clientに接続・読み取りtimeoutがない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | security |
| Area | HTTP client |
| Source | `crates/codefire-cli/src/http.rs:111` |

## Problem

`TcpStream::connect` 後、read/write timeoutを設定していない。

## Why It Matters

remoteが応答しない場合、upload/request/applyが長時間停止し得る。

## Failure Mode / Review Hypothesis

悪意ある入力または遅い接続によって、remote/serverの可用性や署名境界が弱くなる可能性がある。remoteが応答しない場合、upload/request/applyが長時間停止し得る。

## Code Evidence

- Primary source: `crates/codefire-cli/src/http.rs:111`
- Observed implementation fact: `TcpStream::connect` 後、read/write timeoutを設定していない。

## Recommended Fix

connect/read/write timeout optionを導入し、default値を設定する。

## Implementation Notes

- Priority: 機能追加の前後で一緒に片付ける。単独修正でも価値はあるが、関連領域の改修時にまとめると効率がよい。
- First step: 入力上限、timeout、認証/署名境界を先にテストで固定する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: none identified in this review batch.

## Acceptance Criteria

- timeout時に専用exit codeまたは明確なdiagnosticを出す。
- CLI optionと環境変数で調整できる。

## Test Plan

- hanging server fixture test。

## v0.7 Resolution

- HTTP clientは `TcpStream::connect_timeout` を使い、read/write timeoutも同じdurationに設定する。
- default timeoutは30000ms。`CODEFIRE_HTTP_TIMEOUT_MS` に正の整数を指定すると調整できる。
- Regression: `http_timeout_uses_positive_env_override`。
