# CFR-113: upload dry-run envelopeのrepo/next_actionsがtop-levelで弱い

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | ux |
| Area | Remote upload JSON |
| Source | `crates/codefire-cli/src/main.rs:218` |

## Problem

`upload --dry-run --json` はplanをenvelopeに包むが、top-level `repo` や `next_actions` がplan内情報と一致しない、または空になる問題がdogfoodingで観測された。dry-run planはあるが、automationが次に実行するcommandを判断しにくい。

## Why It Matters

dry-runはAI toolが安全にremote mutationを計画する入口である。top-level metadataが弱いと、共通envelope consumerがcommandごとのplan内部を覗く必要がある。

## Failure Mode / Review Hypothesis

upload dry-run resultの `data.plan.repo` には情報があるが、top-level `repo` はnull、`next_actions` は空。toolは共通処理でrepo contextを取れず、upload applyへの導線も出ない。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:218`
- Observed implementation fact: upload dispatch uses `print_plan_result_json("upload", &result.plan)`.
- Related source: `crates/codefire-cli/src/main.rs:1230`
- Observed implementation fact: plan envelope derives repo/next_actions generically from plan.

## Recommended Fix

operation plan traitまたはtyped resultを導入し、top-level repo、target remote、branch、next_actionsをcommand-specificに生成する。generic plan wrapperに頼りすぎない。

## Implementation Notes

- Priority: medium。
- First step: upload dry-run JSON envelope contract testを追加する。
