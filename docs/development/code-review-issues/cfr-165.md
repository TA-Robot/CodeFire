# CFR-165: remote mutation/idempotency/GCが一つのpublication protocolを共有しない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | correctness-risk / security-risk |
| Area | Remote locks / Idempotency / GC |
| Source | RVC-026/030/044/050/056 |

## Problem

file/HTTP remote mutatorはidempotency lookupをresource lock前、result保存をmutation後に行うためsame-key raceと
mutation/result crash gapがある。reviewとapplyは異なるMR/branch lock orderで同じMRを更新し、Python remote GCは
branch mutationとは別lockでroot snapshot後のsweepを再検証しない。remote `FileLock`はcrash-staleする。applyは
さらにMRで承認した`source_head`ではなくcurrent source branch headを公開できる（CFR-174）。

## Code Evidence

- `remote.rs::{upload_branch,request_merge,review_merge_request,apply_merge_request}`。
- `main.rs::FileLock`のcreate-new/unlink lifecycle。
- Python `remote_gc_payload`の`gc.lock`とroot/sweep flow。
- remote testsはsequential replayとgeneration allocationを主に覆い、same-key/MR/GC crash raceを覆わない。
- installed CFR-164 binaryの決定的race evidenceは
  `/tmp/codefire-cfr165-counterexample._aq99nnn/results.json`。同一key・異なるreview payloadが両方successし、最終reviewは
  1件、先に成功した片方のreplayはidempotency conflictになる。
- file/HTTP/Python applyはMR `source_head`ではなくapply時のsource branch headを読むため、approval後の未review commitを
  targetへ公開できる。

## Root Cause and Deduplication

CFB-124/126、CFR-035/067-070、ADR-010はlocal/shared lockやrequest bindingを改善したが、remoteのvisibility point、
lock order、idempotency publication、GC snapshotが別protocolのままである。transport別patchに分断しない。

## Required Fix

- normalized request、resource set、expected preimage、postimage、idempotency resultを一つのdurable transactionへ束縛する。
- 全remote mutatorとGCのcanonical lock orderとkernel-backed stale recoveryを定義する。
- MR/branch/generation/idempotency/GC sweepのvisibility pointとretry reducerを共通化する。
- apply対象はMRのimmutable `source_head`へ固定し、current source branchをapproval subjectとして再解釈しない。
- phase/race/fault harnessをfile/HTTP transportへ適用する。

## Acceptance Criteria

- concurrent same-key same-payloadは一効果＋exact replay、different payloadはpre-write conflictになる。
- review/apply、upload/apply、GC/mutation interleavingがlost update、deleted reachable object、divergent MRを作らない。
- approval後にsource branchが進んでもapply headはMR `source_head`と一致し、未review commitを含まない。
- 各durable phaseのcrash後にexact retryが同じresultへ収束し、foreign transactionは保存して拒否する。
- lock owner diagnosticsはbounded/no-followで、crash-stale lockを安全に分類・回復する。

## Test Plan

- barrier-based concurrent mutator matrix、all-phase failpoints、GC root fingerprint race。
- file/HTTP semantic parityとidempotency result identity。
- object/branch/MR/generation/idempotency hash nonmutation assertions。

## Implemented Source Evidence

- `remote/{project,locks,publication,operations}.rs` separates contained authority, persistent
  project gates, generic recovery, and operation-specific write sets. File and HTTP upload,
  request-merge, review, and apply use the same reducer for keyed and unkeyed calls.
- Python file/HTTP writers use the interoperable gate/journal. New objects use 24-hex IDs while
  exact transfer/validation retains 12/24 compatibility. Actual Rust→Python and Python→Rust upload
  receipt replay preserves branch and generation bytes.
- Python GC stages a bounded canonical plan, exact roots/inventory/retention/audit evidence, a
  non-future trusted planning time, plan-owned delete quarantine, ordered progress, and exact JSON
  audit authority. Unknown/future state is preserved.
- Compound readers take the shared gate and reject pending publication. show/diff snapshot remote
  objects under the gate; legacy cross-project MR list fails closed until ordered review creates
  target-local subject escrow.
- Fault regressions cover publication/quarantine/progress gaps, GC plan/timestamp forgery and inode
  replacement, missing receipts, duplicate authorities, and cross-transport/runtime replay.
- Independent final source review reported no remaining close blocker.

## Retrospect

The root fix is the visibility protocol, not a transport-specific mutex: contained authority,
one reader/writer gate, one durable reducer, immutable MR subject/escrow, and transactional GC now
compose across Rust/Python and file/HTTP. Actual cross-runtime replay exposed and fixed Python's stale
12-hex new-object writer, demonstrating why digest-only fixtures were insufficient. No new blocker
was found; the frozen batch advances to CFR-166/CFB-134.
