# CFR-021: Markdown Atom抽出がコードフェンスを考慮しない

## Summary

## Problem

heading抽出は全行の `# ` を見るだけで、fenced code block内かどうかを追跡しない。

## Why It Matters

Markdown内サンプルコードの `# REQ-...` がAtomとして誤検出される可能性がある。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件や並行実行でCodeFireの整合性表示・保存結果がずれる可能性がある。Markdown内サンプルコードの `# REQ-...` がAtomとして誤検出される可能性がある。

## Code Evidence

- Primary source: `crates/codefire-core/src/lib.rs:1084`
- Observed implementation fact: heading抽出は全行の `# ` を見るだけで、fenced code block内かどうかを追跡しない。

## Recommended Fix

Markdown parserを導入するか、少なくともfenced code block状態を追跡する。

## Implementation Notes

- Fixed in v0.7: Markdown Atom extractor now tracks fenced code blocks opened by backtick or tilde fences.
- Up to three leading spaces before a fence marker are accepted, matching common Markdown fence indentation behavior.
- Heading-like text inside fenced blocks is ignored, while normal headings outside fences keep the previous scope/hash behavior.
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: none identified in this review batch.

## Acceptance Criteria

- 通常headingは従来通り抽出される。
