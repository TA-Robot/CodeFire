# CFR-055: storage reportが全fileを再帰走査する

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | performance |
| Area | Storage report |
| Source | `crates/codefire-cli/src/storage.rs:308` |

## Problem

`scan_objects` はobjects配下を毎回 `collect_files` してmetadata/read_jsonを実行する。

## Why It Matters

大きいremote/object storeでstorage reportが重くなる。

## Failure Mode / Review Hypothesis

入力規模が増えると処理時間、I/O、メモリ使用量が急増する可能性がある。 大きいremote/object storeでstorage reportが重くなる。

## Code Evidence

- Primary source: `crates/codefire-cli/src/storage.rs:308`
- Observed implementation fact: `scan_objects` はobjects配下を毎回 `collect_files` してmetadata/read_jsonを実行する。

## Recommended Fix

object index/cacheまたはquick summary modeを導入する。

## Implementation Notes

- Priority: 大規模repoや実験artifactが増える前に上限設計を入れる。
- First step: 最悪ケースのサイズを決め、修正前後の計算量と実測を比較する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: [CFR-056](cfr-056.md), [CFR-057](cfr-057.md)

## Acceptance Criteria

- quick modeがJSON parseなしに容量だけ返せる。
- full modeでは従来のtype別集計を維持する。

## Test Plan

- storage report quick/full test。

## Resolution

- Fixed in v0.7: `storage report --quick` / `--full` mode was added. Full mode remains the default and preserves type breakdown, largest object, artifact reference, invalid JSON, and remote reporting behavior.
- Quick mode skips object JSON parsing and returns file count, bytes, largest object files, and large-object warnings from metadata only. JSON output exposes `mode` and `skipped_checks`.
- Added quick/full regression coverage in `storage_report_counts_objects_by_type_and_warns_large_objects`.
