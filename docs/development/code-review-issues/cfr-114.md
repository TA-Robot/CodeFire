# CFR-114: contextがactive scan freshnessを検証しない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | correctness-risk |
| Area | Context |
| Source | `crates/codefire-cli/src/context.rs:177` |

## Problem

`context_snapshot` はactive scanが存在する場合、それを優先してcontext packを作る。open directoryのファイルがscan後に変更されていても、active scan freshnessを検証しないため、stale contextを返す可能性がある。

## Why It Matters

AI toolは `context --changed --json` を見て編集対象を判断する。stale contextは誤ったAtomやfireを提示し、docs-first開発の判断を誤らせる。dogfoodingでも scan後編集で古いchanged contextが見える問題が観測された。

## Failure Mode / Review Hypothesis

scan後にファイルを編集し、contextを実行すると、active scan由来の古いchanged_atomsが返る。toolは最新変更を見落とすか、もう存在しないfireを解消しようとする。

## Code Evidence

- Primary source: `crates/codefire-cli/src/context.rs:177`
- Observed implementation fact: context snapshot chooses active scan path when present.
- Related source: `crates/codefire-cli/src/context.rs:237`
- Observed implementation fact: context JSON includes selected data derived from snapshot.

## Recommended Fix

active scanにsource manifest hash、mtime/hash summary、scan timestamp、base commitを保存し、context時にfreshnessを確認する。staleならwarning diagnosticを出すか、read-only preview scanへfallbackする。

## Implementation Notes

- Priority: high。dogfoodで直接観測。
- First step: scan後にfile editしてcontext changedを実行するregression testを追加する。
- Boundary: contextはread-onlyを維持する。fallback previewはactive stateを書かない。
- Related issues: CFB-054, CFR-096.

## Acceptance Criteria

- stale active scanをcontextが検出する。
- JSONに `context_source=fresh_active|stale_active|preview` が出る。
- stale時のnext_actionにscan実行が出る。

## Resolution

`context_snapshot` now computes a read-only preview scan even when an active scan exists. If the active scan fingerprint differs from the preview, context uses the preview and reports `snapshot_source=stale_active_scan_preview`, `active_scan_fresh=false`, and `active_scan_stale_reason`.

Regression: `cargo test -p codefire-cli --bin codefire-rs context_pack_returns_atom_changed_and_fire_views -- --nocapture`.
