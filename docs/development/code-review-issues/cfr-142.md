# CFR-142: bounded_next_actionsのfallbackが常にstatus固定で文脈を失う

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Next actions |
| Source | `crates/codefire-cli/src/automation.rs:384`, `crates/codefire-cli/src/automation.rs:399` |

## Problem

next_actionsが空の場合のfallbackが常に `status --json` で、失敗commandや不足情報に応じた回復策にならない。

## Impact

AI toolが失敗後に同じ失敗を再試行しやすく、help、doctor、migrateなど本来の復旧導線に進めない。

## Recommended Fix

command resultに `recovery_context` を渡し、help、scan、doctor、migrate、openなど文脈別fallbackを生成する。

## Fix

Implemented in the global burn-down pass:

- `bounded_next_actions` no longer falls back blindly to `status --json`.
- Omission markers include `omitted_by_kind` and `first_omitted_targets`.
- The omission marker command is based on the first omitted action so automation can recover the omitted action class.
- JSON error next actions now provide contextual fallback for unsupported options and repository layout/open discovery failures.

## Acceptance Criteria

- unsupported optionなら該当command helpがnext_actionになる。
- repo layout failureならdoctor/migrateがnext_actionになる。
- fallback理由が `reason` として出る。

## Test Plan
