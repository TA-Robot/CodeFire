# CFR-048: link batch appendが既存YAML構造を保てない可能性がある

## Summary

| Field | Value |
|---|---|
| Status | fixed in v0.7 |
| Severity | medium |
| Type | correctness-risk |
| Area | Link batch |
| Source | `crates/codefire-cli/src/link_batch.rs:260` |

## Problem

既存textに `links:` がなければ末尾へ追加し、既存構造のparse/roundtripを行わない。

## Why It Matters

コメント、別section、インデント付き構造があるファイルで意図しない場所にlinksを追加する可能性がある。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件・並行実行・破損状態でCodeFireの整合性判断がずれる可能性がある。 コメント、別section、インデント付き構造があるファイルで意図しない場所にlinksを追加する可能性がある。

## Code Evidence

- Primary source: `crates/codefire-cli/src/link_batch.rs:260`
- Observed implementation fact: 既存textに `links:` がなければ末尾へ追加し、既存構造のparse/roundtripを行わない。

## Recommended Fix

link fileを構造としてparseし、書き戻し方針をADR化する。

## v0.7 Resolution

`link --batch` は既存 `codefire.links.yaml` のroot `links:` sectionを検出し、次のroot sectionより前へ新規linkを挿入するようにした。空ファイルは `version: 1` / `links:` を作成する。`links:` がないのに別root keyがある構造や、root `links:` が重複する構造は明示的にunsupported errorを返す。既存sectionへの挿入とunsupported構造のfixture testを追加した。
