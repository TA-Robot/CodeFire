# CFR-036: request nonce cacheの上限・GC方針が見えない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | security |
| Area | Signatures |
| Source | `crates/codefire-cli/src/signatures.rs:271` |

## Problem

request signature検証でnonce cacheを使うが、policy上限やGC失敗時の挙動がこの周辺から読み取りづらい。

## Why It Matters

nonce recordが増え続ける、またはreplay防止の運用状態が観測しづらい可能性がある。

## Failure Mode / Review Hypothesis

悪意ある入力または遅い接続によって、remote/serverの可用性や署名境界が弱くなる可能性がある。nonce recordが増え続ける、またはreplay防止の運用状態が観測しづらい可能性がある。

## Code Evidence

- Primary source: `crates/codefire-cli/src/signatures.rs:271`
- Observed implementation fact: request signature検証でnonce cacheを使うが、policy上限やGC失敗時の挙動がこの周辺から読み取りづらい。

## Recommended Fix

nonce cacheの保存先、TTL、最大件数、doctor診断、GCを明文化して実装境界を分ける。

## Implementation Notes

- Priority: 機能追加の前後で一緒に片付ける。単独修正でも価値はあるが、関連領域の改修時にまとめると効率がよい。
- First step: 入力上限、timeout、認証/署名境界を先にテストで固定する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
