# CFR-003: `status` と `scan` の状態算出が別実装になっている

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | correctness-risk |
| Area | State model |
| Source | `crates/codefire-cli/src/main.rs:1207`, `crates/codefire-cli/src/main.rs:4008` |

## Problem

`print_scan` は `changed_atoms` と `open_fires` から状態をその場計算する一方、`read_status` は registry の `state.last_known` を読む。

## Why It Matters

`open-clean` なのにopen fireあり、`open-consistent` なのにscan後burning、などの矛盾が発生しやすい。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件や並行実行でCodeFireの整合性表示・保存結果がずれる可能性がある。`open-clean` なのにopen fireあり、`open-consistent` なのにscan後burning、などの矛盾が発生しやすい。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:1207`, `crates/codefire-cli/src/main.rs:4008`
- Observed implementation fact: `print_scan` は `changed_atoms` と `open_fires` から状態をその場計算する一方、`read_status` は registry の `state.last_known` を読む。

## Recommended Fix

状態算出を単一関数へ集約し、`Status` と `ScanResult` の表示・JSONが同じ判定を使うようにする。

## Implementation Notes

- Priority: v0.6 hardeningで優先的に潰す。整合性、security、または大規模運用での破綻につながる。
- First step: 小さな再現fixtureを作って、現状の挙動を固定してから修正する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: [CFR-004](cfr-004.md), [CFR-005](cfr-005.md), [CFR-006](cfr-006.md)

## Acceptance Criteria

- open fire数が正なら `open-clean` を返さない不変条件をテストする。
- `status --json` と `scan --json` の状態語が同条件で一致する。

## Test Plan

- scan直後、verify直後、extinguish直後の状態遷移テストを追加する。

## v0.7 Resolution

- `scan_branch_state` と `status_state` で状態語を集約し、open fireがある状態で `open-clean` を返さないようにした。
- `scan --json`、`status --json`、context packのbranch stateは同じ判定を使う。
- Regression: `scan_and_verify_text_outputs_include_empty_summaries` とstate/JSON系既存テスト。
