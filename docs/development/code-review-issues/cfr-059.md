# CFR-059: TLS serverがclient authをサポートしない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | security |
| Area | TLS |
| Source | `crates/codefire-cli/src/http_tls.rs:42` |

## Problem

server configは常に `with_no_client_auth()` を使う。

## Why It Matters

閉域remoteでもmTLSによるclient identityを使えない。

## Failure Mode / Review Hypothesis

悪意ある入力、誤設定、共有環境での実行により、可用性・機密性・認証境界が弱くなる可能性がある。 閉域remoteでもmTLSによるclient identityを使えない。

## Code Evidence

- Primary source: `crates/codefire-cli/src/http_tls.rs:42`
- Observed implementation fact: server configは常に `with_no_client_auth()` を使う。

## Recommended Fix

request HMACとは別に、optional mTLS policyをfeatureとして設計する。

## Implementation Notes

- Priority: 公開remoteや共有環境で使う前にリスク評価し、可能なら早めに潰す。
- First step: 拒否すべき入力・許可すべき入力を先にテストで固定する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: [CFR-058](cfr-058.md), [CFR-060](cfr-060.md)

## Acceptance Criteria

- server configでclient CAを指定できる。
- mTLS required時に未認証clientを拒否する。
