# CFR-015: object type mappingが複数箇所に散っている

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | maintainability |
| Area | Object schema |
| Source | `crates/codefire-store/src/lib.rs:93`, `crates/codefire-cli/src/main.rs:3930` |

## Problem

object prefix/subdir mappingはstore crateにあり、repo layout作成はCLI側に同じtype群を文字列配列として持つ。

## Why It Matters

type追加時に片方だけ更新する事故が起きやすい。

## Failure Mode / Review Hypothesis

今後の修正で責務混在や差分衝突が増え、不変条件を守りにくくなる。type追加時に片方だけ更新する事故が起きやすい。

## Code Evidence

- Primary source: `crates/codefire-store/src/lib.rs:93`, `crates/codefire-cli/src/main.rs:3930`
- Observed implementation fact: object prefix/subdir mappingはstore crateにあり、repo layout作成はCLI側に同じtype群を文字列配列として持つ。

## Recommended Fix

store crateに `known_object_subdirs()` を公開し、layout作成もそれを使う。

## Implementation Notes

- Priority: 機能追加の前後で一緒に片付ける。単独修正でも価値はあるが、関連領域の改修時にまとめると効率がよい。
- First step: 責務境界を先に切り、動作変更を伴わない分割commitから始める。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: none identified in this review batch.

## Acceptance Criteria

- object subdir一覧が単一source of truthになる。
- 新object type追加テストがlayoutとstoreの両方を検証する。

## Test Plan

## v0.7 Resolution

- `known_object_subdirs()` を公開し、CLIの `ensure_repo_layout` はこの一覧を使う。
- Regression: `known_object_subdirs_are_single_source_of_truth` と `init_creates_python_compatible_repo_layout`。
