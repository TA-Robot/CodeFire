# CFR-127: explain verify-failureがnon-blocking warningをblockerとして数える

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | correctness-risk |
| Area | Explain |
| Source | `crates/codefire-cli/src/explain.rs:227`, `crates/codefire-cli/src/explain.rs:231` |

## Problem

`explain verify-failure` のblocker数計算が `trace_completeness_required` やdiagnosticの `blocking` fieldを見ず、non-blocking warningまでblockerとして数える。

## Impact

verifyはpassedなのにexplainが「blockerあり」と説明し、AI toolが不要な修正サイクルに入る。

## Code Evidence

- `crates/codefire-cli/src/explain.rs:227`: verification summaryからblocker数を再計算している。
- `crates/codefire-cli/src/explain.rs:231`: `missing_required_links.len()` を無条件に足している。

## Recommended Fix

verification diagnosticの `blocking` fieldをsource of truthにし、explain側で独自にblockerを再計算しない。

## Acceptance Criteria

- passed verificationにblocking diagnosticがない場合、explainはblocker 0と表示する。
- warningはwarningとして表示され、blockerに混ざらない。
- verification/explainのsummary生成ロジックが同じ分類を使う。

## Test Plan

- trace completeness optionalのmissing link fixtureでverify passed/explain blocker 0を確認する。
