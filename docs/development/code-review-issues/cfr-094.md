# CFR-094: link commandのhelp routingとJSON error contractが弱い

## Summary

| Field | Value |

| Status | open |

## Problem

`link` commandはbatch機能を持つが、help routingとerror handlingがtop-level registryに統合されていない。dogfoodingでは `link --help` が期待通りのsubcommand helpへ進まない系統の問題が観測された。

## Why It Matters

Trace LinkはCodeFireの中心概念であり、batch schemaやdry-runをAI toolが発見できることが重要である。helpとJSON errorが弱いと、docs-first開発でTrace Linkを安全に増やしにくい。

## Failure Mode / Review Hypothesis

`link --batch` のschemaやdry-run方法をtoolがhelpから取れず、manual YAML生成に頼る。parse errorもtextになり、どのitemが悪いかをstructuredに扱いにくい。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:609`
- Observed implementation fact: link command path parses directly from dispatch side.
- Related source: `crates/codefire-cli/src/link_batch.rs`
- Observed implementation fact: link batch implementation is module化済みだがcommand metadataはmain側に残る。

## Recommended Fix

`link` commandをmodule entryへ寄せ、help、batch schema summary、dry-run、JSON diagnosticsを同じsurfaceで提供する。`link --help` と `link --batch --help` を副作用なしにする。

## Implementation Notes

- Priority: medium。
- First step: help route testsを追加する。
- Boundary: Trace Link semanticsは変えず、CLI contract整理に限定する。

- link parse errorがJSON指定時にstructured diagnosticになる。
- batch schemaがdocsとhelpで一致する。
