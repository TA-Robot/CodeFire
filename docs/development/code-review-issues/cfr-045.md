# CFR-045: artifact hash計算にサイズ上限やstreaming policyがない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | performance |
| Area | Evidence artifacts |
| Source | `crates/codefire-cli/src/evidence.rs:266` |

## Problem

artifact fileをSHA-256計算するが、サイズ上限・warning・進捗方針が見えない。

## Why It Matters

巨大artifactを指定したときに操作が長時間ブロックし、メモリ/IO見積もりが難しい。

## Failure Mode / Review Hypothesis

入力規模が増えると処理時間、I/O、メモリ使用量が急増する可能性がある。 巨大artifactを指定したときに操作が長時間ブロックし、メモリ/IO見積もりが難しい。

## Code Evidence

- Primary source: `crates/codefire-cli/src/evidence.rs:266`
- Observed implementation fact: artifact fileをSHA-256計算するが、サイズ上限・warning・進捗方針が見えない。

## Recommended Fix

large artifact policyを導入し、閾値超過時は確認/警告/外部参照のみの扱いを選べるようにする。

## Implementation Notes

- Priority: 大規模repoや実験artifactが増える前に上限設計を入れる。
- First step: 最悪ケースのサイズを決め、修正前後の計算量と実測を比較する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: [CFR-044](cfr-044.md)

- hash計算がstreamingであることをテストする。
