# CFR-104: `collect_files` がmissing rootとempty directoryを区別しない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | correctness-risk |
| Area | Filesystem scan helper |
| Source | `crates/codefire-cli/src/storage.rs:685` |

## Problem

storage helperの `collect_files` はrootが存在しない場合に空Vecを返す。optional areaの集計では便利だが、required areaやremote rootではmissingとemptyの区別が必要である。

## Why It Matters

同じhelperを複数文脈で使うと、callerが「存在しない」と「存在するが空」を区別できない。doctor/migrate/storageのlayout判断がずれ、recovery toolingの信頼性が下がる。

## Failure Mode / Review Hypothesis

remote objects dirがmissingでもobject count 0として集計される。local active/idempotencyのoptional areaでは問題に見えないが、remote project全体ではhealth issueを隠す。

## Code Evidence

- Primary source: `crates/codefire-cli/src/storage.rs:685`
- Observed implementation fact: missing root is normalized to empty files.
- Related source: `crates/codefire-cli/src/storage.rs:502`
- Observed implementation fact: area scan consumes collected files as stats.

## Recommended Fix

`collect_files_optional` と `collect_files_required` を分けるか、`FileCollection { exists, files }` を返す。callerが文脈に応じてwarningを出せるようにする。

## Implementation Notes

- Priority: medium。
- First step: helper unit testでmissing/empty/nonemptyを分ける。
- Boundary: optional local storage areasの既存挙動は維持する。
- Related issues: CFR-103.

## Acceptance Criteria

- required scan pathではmissingがdiagnosticになる。
- optional scan pathではmissingを0として扱う意図がコード上明確になる。
- storage report testsがmissingとemptyを区別する。

## Test Plan

- storage helper unit testsとremote storage integration testsを追加する。

## Fix

Storage file collection is now split into optional and required paths. Local optional areas preserve the old zero-files behavior when absent, while remote required areas are validated before scan and reported as `remote_layout_invalid` if missing or not directories.
