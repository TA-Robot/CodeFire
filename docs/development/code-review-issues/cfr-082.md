# CFR-082: command help metadataがdispatchと分離して不完全になっている

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | ux |
| Area | CLI help |
| Source | `crates/codefire-cli/src/main.rs:763`, `crates/codefire-cli/src/main.rs:767` |

## Problem

`wants_help` と `subcommand_help` は `main.rs` 内の手書きtableであり、実際のcommand dispatch、parser、completionと同じmetadataを共有していない。dogfoodingでは `init --help` がrepo作成へ進む、`open --help` や `link --help` がusage errorになるなど、help routingの抜けが見つかった。

## Why It Matters

helpは人間だけでなく外部toolの能力検出にも使われる。parserとhelpが別々に増えると、未対応flagを案内したり、help取得で副作用が起きたりする。これはAI toolがCodeFireを安全に探索する上で大きな障害になる。

## Failure Mode / Review Hypothesis

新commandまたはsubcommandを追加しても `subcommand_help` に登録し忘れる。あるcommandはparse前help、別commandはparse後helpになり、`--help` の副作用なし保証がcommandごとに変わる。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:763`
- Observed implementation fact: help detection is a generic helper but routingは一部commandだけ。
- Related source: `crates/codefire-cli/src/main.rs:767`
- Observed implementation fact: help text table is handwritten and not generated from dispatch metadata.

## Recommended Fix

command registryを導入し、dispatch、help、completion、JSON capability、path option supportを同じmetadataから参照する。help requestは全commandでparser実行前に処理し、副作用なしを保証する。

## Implementation Notes

- Priority: v0.9 CLI contract cleanup。
- First step: `init --help`、`open --help`、`link --help`、`migrate --help` のno-side-effect testsを追加する。
- Boundary: clap等の依存追加は慎重に検討し、まず既存手書きregistryの集約で進める。
- Related issues: CFB-046, CFB-047.

## Acceptance Criteria

- 全top-level commandで `--help` が副作用なしに成功する。
- completion/help/dispatchのcommand listが単一sourceに近い形で保たれる。
- helpに載るflagとparserで受けるflagのdocs consistency testがある。
