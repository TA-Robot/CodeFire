# CFR-121: sealed commit validationがresolution_ledger rootを必須化していない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | correctness-risk |
| Area | Commit validation |
| Source | `crates/codefire-store/src/lib.rs:445`, `crates/codefire-store/src/lib.rs:467` |

## Problem

`REQUIRED_COMMIT_ROOTS` が `content_manifest` と `verification` だけを必須としており、commit時に生成される `resolution_ledger` がsealed commitの必須rootとして検証されない。

## Impact

fire解決履歴が欠けたcommit objectをvalidation済みとして扱う可能性がある。review、explain、history再構築が「存在しているはずの監査root」を前提にできない。

## Code Evidence

- `crates/codefire-store/src/lib.rs:445`: required rootsに `resolution_ledger` がない。
- `crates/codefire-store/src/lib.rs:467`: root validation側は `resolution_ledger` typeを認識している。

## Recommended Fix

commit schema versionごとの必須root setを定義し、現行formatでは `resolution_ledger` をrequiredにする。legacy commitはdoctor/migrateで明示診断する。

## Acceptance Criteria

- `resolution_ledger` 欠損の新形式commitをvalidationが拒否する。
- commit生成、doctor、remote uploadが同じrequired root定義を参照する。
- legacy扱いの診断とmigration方針が文書化される。

## Test Plan

- store単体テストで `resolution_ledger` 欠損commitを失敗させる。
- 実commit作成後のsealed validation成功をintegration testで確認する。
