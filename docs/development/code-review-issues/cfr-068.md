# CFR-068: idempotency recordにpayload全文を保存している

## Summary

| Field | Value |
|---|---|
| Status | fixed in v0.7 |
| Severity | medium |
| Type | security |
| Area | Remote idempotency |
| Source | `crates/codefire-cli/src/remote/idempotency.rs:120` |

## Problem

recordは `payload_hash` だけでなく `payload` 全体を保存する。

## Why It Matters

remote URL、actor、path、場合によっては署名metadataなどが長期保存される。

## Failure Mode / Review Hypothesis

悪意ある入力、誤設定、共有環境での実行により、可用性・機密性・認証境界が弱くなる可能性がある。 remote URL、actor、path、場合によっては署名metadataなどが長期保存される。

## Code Evidence

- Primary source: `crates/codefire-cli/src/remote/idempotency.rs:120`
- Observed implementation fact: recordは `payload_hash` だけでなく `payload` 全体を保存する。

## Recommended Fix

payload全文保存をpolicy化し、hash-only modeやredactionを用意する。

## v0.7 Resolution

remote idempotency recordをhash-only保存へ変更し、`payload` 全文を保存しないようにした。recordには `payload_hash`、`payload_mode: hash_only`、最小限の `result`、`created_at` だけを残す。保存recordにpayloadやplanが入らないことをremote mutator replay testで固定した。

## Implementation Notes

- Priority: 公開remoteや共有環境で使う前にリスク評価し、可能なら早めに潰す。
- First step: 拒否すべき入力・許可すべき入力を先にテストで固定する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
