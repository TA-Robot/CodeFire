# CFR-156: migrateのJSON object走査にlimitやquick modeがない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | performance |
| Area | Migration |
| Source | `crates/codefire-cli/src/migration.rs:361`, `crates/codefire-cli/src/migration.rs:380` |

## Problem

migration checkはrepo内JSON fileを再帰的に集めるが、巨大repo向けのlimit、quick mode、progress summaryがない。

## Impact

古い/壊れたrepoほどmigration checkが必要なのに、全走査で遅くなり運用に乗りにくい。

## Recommended Fix

quick check、full check、max files、sampling summaryを導入する。full modeではprogress/metricsを返し、途中打ち切りをJSONに明示する。

## Acceptance Criteria

- large repoでquick migration checkが短時間に終わる。
- full checkの走査件数と打ち切り有無がJSONに出る。
- max limit超過時のdiagnosticが出る。

## Test Plan

- synthetic large JSON tree fixtureでquick/fullの挙動を確認する。

## Resolution

- `migrate check` / `migrate dry-run` now accept `--quick` and `--full`.
- Quick mode skips object record integrity scanning, returns `scan_mode:"quick"`, `checked_objects:0`, and `skipped_checks:["object_record_integrity"]`.
- Full mode remains the default and reports `scan_mode:"full"` with checked object counts.
- Regression: `migrate_check_and_dry_run_report_compatibility_and_blockers`; algorithm dogfood `codefire migrate check --path . --json --quick` and `codefire migrate dry-run --path . --target-format current --json`.
