# CFR-073: missing required linksが常にerror severity

## Problem

`verification_diagnostics_json` はpolicyによらずmissing_required_linkをerrorにする。

## Why It Matters

`require_trace_completeness: false` のとき、non-blocking診断がblockingに見える。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件・並行実行・破損状態でCodeFireの整合性判断がずれる可能性がある。 `require_trace_completeness: false` のとき、non-blocking診断がblockingに見える。

## Code Evidence

- Primary source: `crates/codefire-cli/src/automation.rs:195`
- Observed implementation fact: `verification_diagnostics_json` はpolicyによらずmissing_required_linkをerrorにする。

## Recommended Fix

policy-aware severityをverification dataへ含める。

## Acceptance Criteria

- non-blocking missing linksはwarning/infoになる。
- blocking_only filterとseverityが一致する。

## Test Plan

- policy-aware verification diagnostics test。

## Resolution

- Fixed in v0.7: verification results now persist `trace_completeness_required`, and automation diagnostics use it to classify `missing_required_link`.
- When trace completeness is required, missing required links remain `severity: "error"` and `blocking: true`; when it is disabled, they become `severity: "warning"` and `blocking: false`.
- `verify --blocking-only --json` now filters diagnostics by `blocking`, so non-blocking missing links are excluded. Text `Blocking checks` and exit-code selection also respect the trace-completeness policy.
- Added unit and CLI-level regression tests for non-blocking missing required links.
