# CFR-041: `evidence add --from-command` にtimeoutがない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | correctness-risk |
| Area | Evidence capture |
| Source | `crates/codefire-cli/src/evidence.rs:327` |

## Problem

`capture_command` は `Command::new("sh").arg("-c").output()` を直接呼び、timeoutやkill処理を持たない。

## Why It Matters

証跡取得commandが停止するとCodeFire操作全体が無期限に止まる可能性がある。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件・並行実行・破損状態でCodeFireの整合性判断がずれる可能性がある。 証跡取得commandが停止するとCodeFire操作全体が無期限に止まる可能性がある。

## Code Evidence

- Primary source: `crates/codefire-cli/src/evidence.rs:327`
- Observed implementation fact: `capture_command` は `Command::new("sh").arg("-c").output()` を直接呼び、timeoutやkill処理を持たない。

## Recommended Fix

`--timeout` とpolicy defaultを追加し、timeout時はstdout/stderrの途中結果と終了理由をevidenceに保存する。

## Implementation Notes

- Priority: v0.6 hardeningで優先的に扱う。整合性、security、性能、または配布品質に直接影響する。
- First step: 最小fixtureで現状の境界挙動を固定してから修正する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
