# CFR-115: context/explainのunknown target errorがJSON contractへ乗らない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Context/Explain |
| Source | `crates/codefire-cli/src/context.rs:347`, `crates/codefire-cli/src/explain.rs` |

## Problem

`context --atom UNKNOWN --json` や `explain` の未知targetは、command内で対象解決に失敗した時にJSON envelope errorにならない経路がある。dogfoodingではunknown atom/fire系のerrorがplain textとして観測された。

## Why It Matters

context/explainはAI toolの読み取り系commandである。unknown targetは通常の操作で起こるため、structured diagnosticにして候補や再scan導線を返すべきである。

## Failure Mode / Review Hypothesis

toolが古いAtom IDを指定するとtext errorになり、候補取得やscan refreshへ進めない。JSON parser failureとして扱われ、root causeが失われる。

## Code Evidence

- Primary source: `crates/codefire-cli/src/context.rs:347`
- Observed implementation fact: selected atom IDs are resolved inside context module.
- Related source: `crates/codefire-cli/src/explain.rs`
- Observed implementation fact: explain command owns target parsing/resolution and needs common diagnostic path.

## Recommended Fix

context/explain target resolution errorをtyped diagnosticにし、JSON modeではCFR-081のfailure envelopeへ載せる。可能ならsimilar Atom IDsやavailable selector summaryをdataに含める。

## Fix

Implemented in the global burn-down pass:

- `context --json` wraps parse and target-resolution failures in `codefire.command_result.v1`.
- `explain --json` wraps unknown target failures in the same envelope.
- Unknown Atom/fire usage errors now emit diagnostic kind `unknown_target` with structured target kind/id.
- The failure envelope returns a `refresh_scan` next action.

## Implementation Notes

- First step: unknown atom/fire context JSON testsを追加する。
