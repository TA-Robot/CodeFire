# CFR-103: storage reportが存在しないremote rootを空remoteとして扱い得る

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | correctness-risk |
| Area | Storage remote |
| Source | `crates/codefire-cli/src/storage.rs:516`, `crates/codefire-cli/src/storage.rs:685` |

## Problem

remote storage scanはfile-backed remote URLを解決してremote dirsを走査するが、missing rootやinvalid layoutを明確なwarning/errorへしない経路がある。`collect_files` がmissing rootで空配列を返すため、存在しないremoteが「0 bytes」と見える可能性がある。

## Why It Matters

storage reportは容量だけでなくremote healthの初期診断にも使われる。missing remoteを正常な空remoteとして扱うと、remote URL typo、mount missing、権限問題を見落とす。

## Failure Mode / Review Hypothesis

`storage --remote file:///missing/project --json` がwarningなしで0 bytes remoteを返す。automationはremoteが存在すると誤認し、後続upload/listで別エラーに遭遇する。

## Code Evidence

- Primary source: `crates/codefire-cli/src/storage.rs:516`
- Observed implementation fact: remote storage scan collects stats for remote URLs.
- Related source: `crates/codefire-cli/src/storage.rs:685`
- Observed implementation fact: file collection helper returns empty list for missing root.

## Recommended Fix

remote root existenceとlayout validationをstorage scan入口で明示する。missing root、not directory、missing required remote dirsをwarningまたはblocking diagnosticとして返す。

## Implementation Notes

- Priority: high。dogfood CFB-061と直接関連。
- First step: missing remote URLのstorage JSON testを追加する。
- Boundary: `collect_files` のlocal optional area用途とremote required root用途を分ける。
- Related issues: CFB-061, CFR-104.

## Acceptance Criteria

- missing remote rootがwarning/diagnosticになる。
- empty but valid remoteとmissing remoteが区別される。
- next_actionsにremote URL確認またはdoctor相当の導線が出る。
