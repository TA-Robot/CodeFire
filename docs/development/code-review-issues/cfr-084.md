# CFR-084: remote read commandがJSON出力に対応していない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | ux |
| Area | Remote CLI |
| Source | `crates/codefire-cli/src/main.rs:243`, `crates/codefire-cli/src/main.rs:275` |

## Problem

remote `list` と `request-list` はtext renderingしか持たない。remote branchやmerge requestは自動化が判断材料として使う情報だが、`--json` で安定したmachine-readable outputを取得できない。

## Why It Matters

AI toolやCIがremote状態を調べるとき、text tableをparseする必要がある。remote projectは信頼境界でもあり、branch head、generation、MR status、source/targetなどをstructured dataで扱えないと検証や監査が弱くなる。

## Failure Mode / Review Hypothesis

remote branch listやMR listをもとに次のapply/review actionを組み立てるautomationが、text変更で壊れる。JSON未対応のためdogfood issueを自動登録する時も証拠取得が不安定になる。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:243`
- Observed implementation fact: remote branch list is printed as text.
- Related source: `crates/codefire-cli/src/main.rs:275`
- Observed implementation fact: request list is printed as text.

## Recommended Fix

`list --json` と `request-list --json` を追加し、remote project URL、items、diagnostics、next_actionsをenvelopeで返す。text rendererはJSON data modelから派生させる。

## Implementation Notes

- Priority: v0.9 remote contract。
- First step: existing text behaviorを保つtestとJSON追加testを分ける。
- Boundary: remote marketplaceやagent運用ではなく、既存remote read APIの整備。
- Related issues: CFB-064, CFR-081.

## Acceptance Criteria

- `codefire list <remote> --json` がbranch配列を返す。
- `codefire request-list <remote> --json` がMR配列を返す。
- remote read failureもJSON envelopeになる。
