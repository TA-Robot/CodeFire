# CFR-129: HTTP request-merge dry-runがhead検証なしで空head planを返す

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | correctness-risk |
| Area | Remote merge |
| Source | `crates/codefire-cli/src/remote.rs:388`, `crates/codefire-cli/src/remote.rs:399` |

## Problem

HTTP remoteの `request-merge --dry-run` がsource/target headやremote objectの存在検証を十分に行わず、空文字のheadを含むplanを返す。

## Impact

dry-runが「何をmergeするか」を検証しないplanになり、apply時に初めてremote errorになる。

## Code Evidence

- `crates/codefire-cli/src/remote.rs:388`: HTTP request-merge dry-run branchが独自planを返す。
- `crates/codefire-cli/src/remote.rs:399`: `source_head` と `target_head` が空文字列で埋められる。

## Recommended Fix

dry-runでもremote refsを問い合わせ、source/targetの存在とhead object到達性を検証する。offline dry-runは `validation_mode` を明示する。

## Acceptance Criteria

- 存在しないbranchのdry-runはvalidation failureになる。
- dry-run planにsource/target headが実値で入る。
- apply時とdry-run時の事前検証差分がdocsに明示される。

## Test Plan

- HTTP remote fixtureで存在しないbranchのdry-run失敗を確認する。
