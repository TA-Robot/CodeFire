# CFR-022: links/policy parserが限定的な手書きYAMLになっている

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | correctness-risk |
| Area | YAML parser |
| Source | `crates/codefire-core/src/lib.rs:315`, `crates/codefire-core/src/lib.rs:358` |

## Problem

`parse_links` と `parse_verification_policy` は行単位split、indent、prefix判定でYAML subsetを処理している。

## Why It Matters

有効なYAMLでも順序・quote・inline comment・list表現によって解釈差が起きやすい。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件や並行実行でCodeFireの整合性表示・保存結果がずれる可能性がある。有効なYAMLでも順序・quote・inline comment・list表現によって解釈差が起きやすい。

## Code Evidence

- Primary source: `crates/codefire-core/src/lib.rs:315`, `crates/codefire-core/src/lib.rs:358`
- Observed implementation fact: `parse_links` と `parse_verification_policy` は行単位split、indent、prefix判定でYAML subsetを処理している。

## Recommended Fix

ADRのlimited YAML方針を保つならschema validatorとエラー位置を強化する。依存許容なら `serde_yaml` 等へ移行する。

## Implementation Notes

- Fixed in v0.7: core links/policy parsers now share limited YAML comment stripping, indentation validation, and key/value parsing helpers.
- Unsupported root keys, nested entries outside supported sections, unsupported fields, tab indentation, and malformed list/key entries now return explicit config errors with line numbers.
- The accepted subset still intentionally covers the CodeFire schema only; it is not a full YAML parser.
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: none identified in this review batch.

## Acceptance Criteria

- unsupported YAML構文は黙って無視せず明示errorになる。
- policy/link parserのgolden fixtureが増える。
