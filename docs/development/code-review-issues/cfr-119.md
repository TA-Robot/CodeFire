# CFR-119: object store writeのfsync/rename方針がactive metadata writeと別々に進化しやすい

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | correctness-risk |
| Area | Durability helpers |
| Source | `crates/codefire-store/src/lib.rs:259`, `crates/codefire-cli/src/main.rs:4055` |

## Problem

object store writeとCLI metadata atomic writeは別crate/別helperで実装されている。v0.7でそれぞれ強化されたが、temp path、fsync、publish、directory sync、error分類の方針が別々に進化しやすい。

## Why It Matters

CodeFireの信頼性はobject writeとbranch/active metadata writeの両方に依存する。durability helperの仕様が分散すると、片方だけ修正され、crash consistencyの説明がdocsと実装でずれる。

## Failure Mode / Review Hypothesis

object storeはhard-link publishとdir syncを行うが、metadata writeは別方針になる。将来の修正で片方にfsync regressionが入り、doctorでは検出しづらいpartial stateが残る。

## Code Evidence

- Primary source: `crates/codefire-store/src/lib.rs:259`
- Observed implementation fact: object store owns immutable object publish.
- Related source: `crates/codefire-cli/src/main.rs:4055`
- Observed implementation fact: CLI owns JSON atomic write for metadata.

## Recommended Fix

durable write contractを `codefire-util` または専用crate/moduleに文書化し、object/metadataで共有できる部分を抽出する。少なくともtestsとdocsでwrite ordering/failure modelを揃える。

## Implementation Notes

- Priority: medium。
- First step: docsにdurable write contractを明記し、helper testsを棚卸しする。
- Boundary: OSごとの完全fsync保証は明記できる範囲に限定する。
- Related issues: CFR-010, CFR-011, CFR-012 fixed後の再発防止。

## Acceptance Criteria

- object/metadata writeのdurability contractが同じ文書にある。
- helper testsがtemp collision、partial write、directory sync best effortを覆う。
- 新規write pathは共通contractを参照する。

## Test Plan

- util/store/cli write helper testsを整理し、failure injection可能な範囲を追加する。
- docs/architectureにwrite orderingを追記する。
