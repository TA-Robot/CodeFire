# CFR-007: `--json` 出力が command envelope に統一されていない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | maintainability |
| Area | JSON output |
| Source | `crates/codefire-cli/src/main.rs:180`, `crates/codefire-cli/src/main.rs:292` |

## Problem

`scan`/`verify` は `command_result_envelope` を使うが、`extinguish --json` や `commit --json` はplanを直接出している。

## Why It Matters

AI toolがcommandごとに異なるJSON schemaを扱う必要があり、自動化が壊れやすい。

## Failure Mode / Review Hypothesis

今後の修正で責務混在や差分衝突が増え、不変条件を守りにくくなる。AI toolがcommandごとに異なるJSON schemaを扱う必要があり、自動化が壊れやすい。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:180`, `crates/codefire-cli/src/main.rs:292`
- Observed implementation fact: `scan`/`verify` は `command_result_envelope` を使うが、`extinguish --json` や `commit --json` はplanを直接出している。

## Recommended Fix

全commandのJSON出力を `codefire.command_result.v1` に統一し、従来planは `data.plan` に入れる。

## Implementation Notes

- Priority: v0.6 hardeningで優先的に潰す。整合性、security、または大規模運用での破綻につながる。
- First step: 責務境界を先に切り、動作変更を伴わない分割commitから始める。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: none identified in this review batch.

## Acceptance Criteria

- 全主要commandで `schema`, `command`, `ok`, `exit_code`, `data` を持つ。
- 互換性が必要なら `--raw-plan` 等で明示する。
