# CFR-106: storage quick/full modeの保証範囲がJSONに明示されない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | low |
| Type | ux |
| Area | Storage report |
| Source | `crates/codefire-cli/src/storage.rs:202` |

## Problem

storage reportはquick/full modeを持つが、JSON consumerに「このmodeでは何を検証していないか」を明示するcontractが弱い。quick resultをfull health checkとして誤用しやすい。

## Why It Matters

AI toolはstorage outputを見てremote healthやobject integrityを判断する。modeの検査範囲がmachine-readableに出ないと、quick modeの高速結果を過信する。

## Failure Mode / Review Hypothesis

quick modeでobject payload type mismatchが検出されず、automationが「storage clean」と判断する。実際にはfull modeでしか出ないwarningがある。

## Code Evidence

- Primary source: `crates/codefire-cli/src/storage.rs:202`
- Observed implementation fact: `storage_report_data_json` serializes report data but mode guarantees are not first-class enough.
- Related source: `crates/codefire-cli/src/storage.rs:118`
- Observed implementation fact: parser accepts mode flags.

## Recommended Fix

storage JSONに `mode`, `coverage`, `skipped_checks`, `requires_full_for` を追加する。quick modeでは検査していない項目を明示し、next_actionでfull modeを提案する条件を整理する。

## Implementation Notes

- Priority: low-medium。
- First step: quick/full JSON coverage fieldsのtestを追加する。
- Boundary: performance改善ではなくautomation interpretabilityの改善。
- Related issues: CFR-105.

## Acceptance Criteria

- quick/full modeがJSONで明示される。
- skipped checksがmachine-readable配列で出る。
- docsにmode別保証範囲がある。
