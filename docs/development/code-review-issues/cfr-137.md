# CFR-137: branch context selectorが空selectionを返して実質的なbranch要約にならない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Context |
| Source | `crates/codefire-cli/src/context.rs:347`, `crates/codefire-cli/src/context.rs:353` |

## Problem

context targetがbranchの場合、selectorが空の `ContextSelection` を返すため、branch headに紐づくatom/trace/fireの概要を十分に提供しない。

## Impact

branch contextがstatusとの差別化に失敗し、AI toolが追加commandを何度も試す。

## Recommended Fix

branch targetではactive scan、head commit roots、open fires、recent changes、trace completeness summaryを含める。

## Acceptance Criteria

- `context branch --json` がbranch固有のsummaryを返す。
- empty selectionの場合も理由とnext actionが出る。
- branch contextとstatus outputの責務がdocsで分かれる。

## Test Plan

- open branch fixtureでbranch contextがopen fires/recent commitを含むことを確認する。

## Resolution

Branch context now selects changed atoms plus source/target atoms for open fires instead of returning an empty atom selection. Context JSON also exposes `changed_count` and `open_fire_count` summary fields, so branch context is distinct from bare status.

Regression: `cargo test -p codefire-cli --bin codefire-rs context_pack_returns_atom_changed_and_fire_views -- --nocapture`.
