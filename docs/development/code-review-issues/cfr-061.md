# CFR-061: metricsがtotalのみでphase timingを持たない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | maintainability |
| Area | Metrics |
| Source | `crates/codefire-cli/src/metrics.rs:71` |

## Problem

text outputは `phase timings:` を出すが中身は `total_ms` だけ。

## Why It Matters

scan/verifyのどこが遅いか特定できず、性能改善の観測点として弱い。

## Failure Mode / Review Hypothesis

機能追加時に同じ仕様を複数箇所へ反映する必要があり、修正漏れや不変条件破壊につながる。 scan/verifyのどこが遅いか特定できず、性能改善の観測点として弱い。

## Code Evidence

- Primary source: `crates/codefire-cli/src/metrics.rs:71`
- Observed implementation fact: text outputは `phase timings:` を出すが中身は `total_ms` だけ。

## Recommended Fix

atom extraction、trace parse、fire build、verification command等のphaseを計測する。

## Implementation Notes

- Priority: 関連領域を触るタイミングで一緒に片付ける。単独修正でも価値はある。
- First step: 動作変更なしの分割または定数化から始める。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: [CFR-062](cfr-062.md)

## Acceptance Criteria

- scan/verify metricsに複数phaseが出る。
- JSON schemaでphase名が安定する。
- 個別stopwatch未導入のsubphaseは `measured: false` として、実測済みtotal/pipeline timingと区別される。
