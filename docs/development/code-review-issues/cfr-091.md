# CFR-091: `init` がparse-before-helpで副作用なしhelpを保証できない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | bug |
| Area | CLI init |
| Source | `crates/codefire-cli/src/main.rs:444`, `crates/codefire-cli/src/main.rs:1272` |

## Problem

`init` はhelp routingより先に通常parse/execute pathへ入り得る。dogfoodingでは `init --help` が `--help` というdirectory/repoを作る挙動として観測された。mutating commandのhelpは常に副作用なしでなければならない。

## Why It Matters

help取得は安全な探索操作であるべき。AI toolが能力検出で `command --help` を走らせた結果repositoryが作成されると、作業ディレクトリを汚し、後続のrepo discoveryも誤る。

## Failure Mode / Review Hypothesis

mutating commandで `--help` をpositional pathとして解釈し、filesystem writeが発生する。特に `init` はopen context不要で実行できるため、誤副作用のblast radiusが大きい。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:444`
- Observed implementation fact: init command arm performs parse/init flow.
- Related source: `crates/codefire-cli/src/main.rs:1272`
- Observed implementation fact: parse_init_args handles positional values but help intent is not represented as a typed result.

## Recommended Fix

全command共通でhelpをparser前に検出するcommand registryへ移行する。少なくとも `init` は `wants_help(args)` を最初に処理し、dry-run/JSON/help capabilityをparser resultに含める。
