# CFR-163: local authorityとpartial transitionが共通snapshot/recoveryを持たない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | correctness-risk |
| Area | Open state / Active state / Recovery |
| Source | RVC-012/024/027/028/037 |
| Decision | [ADR-015](../../../adr/ADR-015-verified-open-authority-and-active-transitions.md) |

## Problem

branch head、opened registry base、open marker、active stateを一つのvalidated subjectとして読む境界がなく、
status、doctor、dry-run、live mutationが異なるsubsetをauthorityにする。さらにcommitのpartial active resetと
Fire/Resolutionの複数file transitionは、途中失敗後に自動再開できるdurable postimage protocolを持たない。

## Counterexamples

- `/tmp/codefire-prepublish-audit.5ZGjwO`: branch headとopened baseを有効だが異なるcommitへした状態で
  status、doctor、commit dry-runは成功し、live commitはactive stateを書いた後にexit 20となる。
- `/tmp/codefire-audit-src.oPiaGB`: `resetting_active_state`途中のcommit retryは自動回復せず、markerを残して
  explicit inspectionを要求する。
- `batch.rs::run_extinguish_batch`は`fires.json`を書いた後に`resolutions.json`を書くため、二つ目のwrite失敗で
  active ledgerが不整合になる。

## Root Cause and Deduplication

CFB-120/121/124、ADR-009/010/011、open/close transactionは個別boundaryを強化したが、通常open consumerと
active multi-file transitionに共通authority snapshot/recovery contractがない。既存成果を再利用し、個別command
if文やdoctor専用validatorを増やさない。

## Required Fix

- branch/opened/marker/active/repository identityを検証した`VerifiedOpenSnapshot`とtyped divergenceを作る。
- status、scan、verify、commit、batch、doctorが同じsnapshot/diagnosticを消費する。
- transaction phaseごとに許容される一時的不一致と通常状態のcorruptionを分ける。
- commit active resetとFire/Resolution transitionをdurable、idempotent、replayableなpublication protocolへ移す。

## Acceptance Criteria

- branch-old/registry-newとbranch-new/registry-oldの両方向を全consumerが最初のwrite前に同じkindで拒否する。
- dry-runはapply actionを返さず、live rejectionはobject/branch/opened/active hashを変更しない。
- valid pending open/close/scan/verify/commit transactionは通常corruptionと誤認されず、exact retryで収束する。
- commit resetの全file境界とbatch Fire/Resolutionの各publication境界がcrash後のretryで一意postimageへ収束する。
- doctorはphase、authority、expected/actual、safe recovery actionをtyped reportする。

## Resolution

`VerifiedOpenSnapshot`をbranch head、opened registry、open marker、active state、repository identityの
共通authorityとして導入し、通常状態のdivergenceと回復中のtyped pending dispositionを分離した。
commit state publicationとactive resetはexact requestへ束縛したdurable reducerになり、Fire/Resolutionは
effect hashと`state_publication=pending|released`を持つactive-ledger receiptを経由する。status、scan、verify、
commit、close、discard、Doctorは同じsnapshot/receipt validatorをwrite前に消費し、exact retry以外を
fail closedにする。Doctorはpending authorityをsecret非露出のtyped actionとして報告する。

CFB-135も同じCloseで修正し、Doctorのclean-state invariantは`status=open`のFireだけを数える。
extinguished historyとreleased receiptは正常な履歴として保持する。

## Retrospect

partial transitionを個別commandのcleanupとして扱わず、subject-bound snapshot、request-bound journal、
postimage reducer、typed inspectionという一つのcontractへ統合したことで、crash recoveryとsteady-state readの
判定差をなくせた。fresh Install後に見つかったCFB-135は同rootのClose blockerとして修正済みで、新しい
blockerは最終Dogfoodと独立反例監査から見つからなかった。凍結順序どおり次はCFR-164へ進む。
