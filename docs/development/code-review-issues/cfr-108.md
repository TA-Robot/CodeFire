# CFR-108: evidence dry-runが空のevidence_idを返して実体と紛らわしい

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Evidence dry-run |
| Source | `crates/codefire-cli/src/evidence.rs:213` |

## Problem

`run_evidence_add` のdry-run resultはevidence objectを書かないが、result struct上で空文字の `evidence_id` のようなplaceholderを持つ。JSON consumerから見ると「空IDの証跡が作られた」のか「dry-runで未作成」なのかが紛らわしい。

## Why It Matters

AI toolはdry-run後に実行へ進むか判断する。ID fieldが空文字で存在すると、null/absentよりも誤用されやすく、後続のresolution evidence refに空IDを渡す危険がある。

## Failure Mode / Review Hypothesis

dry-run JSONを使ったtoolが `evidence_id` fieldの存在だけを見て成功証跡として扱う。後続extinguishでempty evidence refを指定し、別のusage errorになる。

## Code Evidence

- Primary source: `crates/codefire-cli/src/evidence.rs:213`
- Observed implementation fact: dry-run returns an `EvidenceAddResult` without writing evidence object.
- Related source: `crates/codefire-cli/src/evidence.rs:355`
- Observed implementation fact: result JSON serializes evidence result fields.

## Recommended Fix

dry-run用result dataでは `evidence_id: null` またはfield omittedにし、`created: false`, `dry_run: true`, `plan` を明示する。apply resultとはschema上区別する。

## Implementation Notes

- Priority: medium。
- First step: evidence dry-run JSON contract testを追加する。
- Boundary: dry-runが証跡objectを作らない設計は維持する。
- Related issues: CFB-050, CFR-107.

## Acceptance Criteria

- dry-run resultに空文字IDが出ない。
- dry-runとapplyのdata shape差分がdocs化される。
- evidence refとして使えるIDはapply時だけ返る。

## Test Plan

- dry-run JSONで `created=false` と `evidence_id=null/absent` を検証する。
- apply JSONではvalid `CF-EVIDENCE-*` が返ることを確認する。

## Fix

Dry-run evidence add results now use `created: false` and `evidence_id: null`; no empty-string placeholder is emitted. The operation plan remains available under `data.plan`, and the schema difference between dry-run and apply is documented in the CLI spec.
