# CFR-122: commit certificateがverification payloadと相互検証されていない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | correctness-risk |
| Area | Commit certificate |
| Source | `crates/codefire-store/src/lib.rs:431`, `crates/codefire-cli/src/main.rs:3728` |

## Problem

sealed commit validationはcertificateの形を確認するが、certificate内のresultやsummaryが実際のverification objectと一致するかを十分に照合していない。

## Impact

見た目だけ検証済みのcommitや、古いverificationを使い回したcommitを検出しにくい。AI toolはcertificateを信頼して次工程へ進むため、誤った安全判定につながる。

## Code Evidence

- `crates/codefire-store/src/lib.rs:431`: certificate resultは固定文字列の検査中心。
- `crates/codefire-cli/src/main.rs:3728`: commit時にcertificate resultを固定値で生成している。

## Recommended Fix

certificateをverification summaryの署名済みprojectionとして定義し、`verification_root` のobject内容と `result`、diagnostic count、required trace countを照合する。

## Acceptance Criteria

- verification objectとcertificate resultが異なるcommitをvalidationが拒否する。
- certificate生成元がverification summaryから一方向に導出される。
- result用語のmappingがschema docsに明記される。

## Test Plan

- certificateだけ改ざんしたfixtureをvalidation失敗にする。
- commit成功pathでcertificateとverification summaryの一致をassertする。

## Fix

- sealed commit validationで `roots.verification` のpayloadを読み、certificateの `result` とverification `result` を照合するようにした。
- certificate `consistent` はlegacy aliasとして `verification.result=passed` のみ許可する。`failed` verificationやcount mismatchは拒否する。
- certificate count fieldsはverification payloadの `open_required_fires` と各diagnostic array長から再計算して照合する。
- mismatch fixtureを追加し、見た目だけconsistentなcommitを `validate_sealed_commit` が拒否することを固定した。
