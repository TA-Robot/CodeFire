# CFR-010: `write_json_atomic` の一時ファイル名が固定で衝突し得る

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | correctness-risk |
| Area | Atomic write |
| Source | `crates/codefire-cli/src/main.rs:3987` |

## Problem

一時pathが `path.with_extension("json.tmp")` のように対象pathだけから決まり、同一pathへの同時writeで衝突し得る。

## Why It Matters

lock漏れや別processのread/writeが重なると、tmp上書き・rename競合・破損につながる。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件や並行実行でCodeFireの整合性表示・保存結果がずれる可能性がある。lock漏れや別processのread/writeが重なると、tmp上書き・rename競合・破損につながる。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:3987`
- Observed implementation fact: 一時pathが `path.with_extension("json.tmp")` のように対象pathだけから決まり、同一pathへの同時writeで衝突し得る。

## Recommended Fix

process id、monotonic counter、random suffixを含むtmp名を作り、rename失敗時に掃除する。

## Implementation Notes

- Priority: v0.6 hardeningで優先的に潰す。整合性、security、または大規模運用での破綻につながる。
- First step: 小さな再現fixtureを作って、現状の挙動を固定してから修正する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: none identified in this review batch.

## Acceptance Criteria

- 失敗時に古いtmpが残っても次回writeを阻害しない。
