# CFR-160: data result envelopeのrepo抽出規則がcommandごとに弱い

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | ux |
| Area | JSON envelope |
| Source | `crates/codefire-cli/src/main.rs:1285`, `crates/codefire-cli/src/main.rs:1296` |

## Problem

data result envelopeはpayload内のfield名に依存してrepoを推測するが、commandごとのpayload schemaが揃っていないためtop-level repoがnullになり得る。

## Impact

複数workspaceを扱うAI toolが、次commandの安全なpath引き継ぎに失敗する。pathless next_actionと組み合わさると誤操作の原因になる。

## Recommended Fix

command execution contextからrepo/open_dirをenvelopeへ直接渡す。payloadのfield名から推測する方式はlegacy fallbackにする。

## Acceptance Criteria

- repo配下で実行したJSON commandはtop-level repoを必ず返す。
- repoを持たないcommandは `repo_applicable=false` を返す。
- repo抽出の失敗がsilent nullにならない。

## Test Plan

- 主要JSON commandのtop-level repo presence snapshotを追加する。
