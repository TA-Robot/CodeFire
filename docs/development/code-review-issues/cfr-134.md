# CFR-134: storage quick modeのlargest object typeがunscanned固定になる

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | ux |
| Area | Storage report |
| Source | `crates/codefire-cli/src/storage.rs:362`, `crates/codefire-cli/src/storage.rs:385` |

## Problem

quick modeではlargest objectのtypeが `unscanned` になり、object directory名などから推定できる情報も落ちる。

## Impact

最大objectの種別が分からず、肥大化の原因調査で次に見るべき領域をAI toolが判断できない。

## Recommended Fix

quick modeでもobject path/subdirectoryやlightweight headerからtypeを推定する。推定不能な場合は `type_confidence` を返す。

## Acceptance Criteria

- quick modeのlargest objectsが可能な範囲でtypeを返す。
- `unscanned` の意味と割合がsummaryに出る。
- full modeとの差分がJSONに明示される。

## Test Plan

- known object typeを含むfixtureでquick/fullのlargest object typeを比較する。
