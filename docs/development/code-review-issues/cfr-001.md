# CFR-001: `main.rs` の command dispatch が巨大化している

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | maintainability |
| Area | CLI dispatch |
| Source | `crates/codefire-cli/src/main.rs:109` |

## Problem

`run(args)` の巨大な `match` が `scan`、`verify`、`fire`、`extinguish`、`commit`、remote、view、doctor等のdispatchと出力分岐を同じ関数で扱っている。ファイル全体も約4,691行ある。

## Why It Matters

command追加ごとに衝突しやすく、parse/plan/apply/render境界が崩れやすい。

## Failure Mode / Review Hypothesis

今後の修正で責務混在や差分衝突が増え、不変条件を守りにくくなる。command追加ごとに衝突しやすく、parse/plan/apply/render境界が崩れやすい。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:109`
- Observed implementation fact: `run(args)` の巨大な `match` が `scan`、`verify`、`fire`、`extinguish`、`commit`、remote、view、doctor等のdispatchと出力分岐を同じ関数で扱っている。ファイル全体も約4,691行ある。

## Recommended Fix

commandごとに `commands/<name>.rs` を作り、`parse -> execute -> render` の薄いinterfaceへ寄せる。

## Implementation Notes

- Priority: v0.6 hardeningで優先的に潰す。整合性、security、または大規模運用での破綻につながる。
- First step: 責務境界を先に切り、動作変更を伴わない分割commitから始める。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: none identified in this review batch.

## Acceptance Criteria

- `run` はcommand登録とdispatchだけを担当する。
- 主要commandの実行・表示分岐が個別moduleに移る。
