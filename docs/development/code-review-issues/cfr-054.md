# CFR-054: doctor issue severityがerror/warningの2段階に閉じている

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | maintainability |
| Area | Doctor |
| Source | `crates/codefire-cli/src/doctor/report.rs:1` |

## Problem

doctor outputはissue severityをerror/warning中心に扱い、repairable/blocking/security等の分類がない。

## Why It Matters

AI toolが自動修復可否や優先度を判断しにくい。

## Failure Mode / Review Hypothesis

機能追加時に同じ仕様を複数箇所へ反映する必要があり、修正漏れや不変条件破壊につながる。 AI toolが自動修復可否や優先度を判断しにくい。

## Code Evidence

- Primary source: `crates/codefire-cli/src/doctor/report.rs:1`
- Observed implementation fact: doctor outputはissue severityをerror/warning中心に扱い、repairable/blocking/security等の分類がない。

## Recommended Fix

doctor diagnosticにcategory、repairability、blockingを追加する。

## Implementation Notes

- Priority: 関連領域を触るタイミングで一緒に片付ける。単独修正でも価値はある。

- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
