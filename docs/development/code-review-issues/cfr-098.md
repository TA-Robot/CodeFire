# CFR-098: clean scanのnext_actionsがverify誘導に寄りすぎる

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Scan next_actions |
| Source | `crates/codefire-cli/src/automation.rs:121` |

## Problem

`scan_next_actions` はopen fireがない状態でもverifyを次actionとして返しやすい。changed atomが0、open fireが0、non-Atom changeもない場合、次に実行すべきことは「何もしない」またはstatus確認であり、verifyではない。

## Why It Matters

dogfooding中、clean状態でverify/commit系のnext actionが出るとautomationが無駄に走る。CodeFire改善サイクルは頻繁にscanするため、no-op stateのaction品質は速度とログ量に直結する。

## Failure Mode / Review Hypothesis

scanがclean結果を返すたびにtoolがverifyを実行し、verify結果からさらにcommit/dry-runを検討する。結果としてissue収集やalgorithm開発よりCodeFire操作のノイズが増える。

## Code Evidence

- Primary source: `crates/codefire-cli/src/automation.rs:121`
- Observed implementation fact: scan next action generationはscan summaryに対して単純なactionを返す。
- Related source: `crates/codefire-cli/src/automation.rs:384`
- Observed implementation fact: next action capはあるが、action relevanceの評価は別途必要。

## Recommended Fix

scan resultに `work_required` / `no_changes` / `requires_verification` などのderived flagsを持たせる。clean no-changeではnext_actionsを空にし、changed but no firesの場合だけverify/commitへ進める。

## Implementation Notes

- Priority: medium。
- First step: clean scan JSONのnext_actions regression testを追加する。
- Boundary: command execution orchestrationではなく、action suggestion精度の改善。

- changed_count>0/open_fire_count=0ではverify actionが出る。
- open_fire_count>0ではcontext/extinguish/batch導線が優先される。
