# CFR-131: top-level help routingが主要commandを網羅していない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | CLI help |
| Source | `crates/codefire-cli/src/main.rs:760`, `crates/codefire-cli/src/explain.rs:36` |

## Problem

`command_help_for_args` が `context`、`explain`、`migrate`、`trace-graph`、`atom-index`、`missing-links` などを網羅しておらず、`command --help` がunsupported option扱いになる経路がある。

## Impact

AI toolはhelpをcapability discoveryとして使う。helpがdispatchとずれると、存在する機能を発見できず、誤ったoption試行が増える。

## Recommended Fix

command registryを作り、dispatch、help、JSON capability、metrics対応を同じmetadataから生成する。

## Acceptance Criteria

- すべてのpublic commandで `command --help` が成功する。
- help routingとdispatch対象の差分をtestで検出できる。
- subcommand helpにJSON/metrics対応が明記される。

## Test Plan

- public command一覧に対するhelp smoke testを追加する。

## Fix

Implemented in v1.0 Phase 1a by adding help routing for `context`, `explain`, `migrate`, `atom-index`, `trace-graph`, and `missing-links`. This is the direct fix for the uncovered command set found during cycle 2. Broader command capability registry work remains tracked separately by CFR-126/CFR-150.
