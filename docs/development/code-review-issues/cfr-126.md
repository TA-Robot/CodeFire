# CFR-126: branch listが--metricsを受け付けるが出力へ反映しない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | ux |
| Area | Metrics |
| Source | `crates/codefire-cli/src/main.rs:474`, `crates/codefire-cli/src/main.rs:484` |

## Problem

`branch list --metrics --json` はparser上受け付けられるが、metrics blockが出力されず、unsupported diagnosticも出ない。

## Impact

性能計測やCI監視で欠測が発生する。flagが黙って無視されるため、利用者は未計測と高速実行を区別できない。

## Code Evidence

- `crates/codefire-cli/src/main.rs:474`: branch listは共通parserで `--metrics` を読める。
- `crates/codefire-cli/src/main.rs:484`: rendering pathで `options.metrics` が使われない。

## Recommended Fix

Fixed by making `branch list` a metrics-capable command.対応commandは必ずmetrics blockを出す方針を維持し、今回の黙殺ケースを解消した。

## Fix

- `branch_list_metrics` を追加し、elapsed time、branch count、open branch countを返す。
- `branch list --json --metrics` では `data.metrics` を返す。
- `branch list --metrics` text modeではmetrics sectionを表示する。
- `branch list --help` は `--metrics` を明示する。

## Acceptance Criteria

- `branch list --metrics --json` がmetricsを返すか明確に失敗する。
- helpにmetrics対応有無が反映される。
- metrics flagを黙って無視するcommandがtestで検出される。

## Test Plan

- `branch list --metrics --json` のcontract testを追加する。

## Verification

- `metrics_attach_to_status_scan_and_verify_data` でbranch-list metrics contractを検証する。
- `command_help_routes_before_mutating_parsers` でhelpの `--metrics` 表示を検証する。
