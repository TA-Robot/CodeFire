# CFR-079: HTTP request method/pathの正規化が弱い

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | security |
| Area | HTTP parser |
| Source | `crates/codefire-cli/src/http.rs:361` |

## Problem

request lineをsplit whitespaceしてmethod/pathをそのままdispatchする。

## Why It Matters

path正規化、percent decode後の禁止文字、method大小などの扱いが曖昧。

## Failure Mode / Review Hypothesis

悪意ある入力、誤設定、共有環境での実行により、可用性・機密性・認証境界が弱くなる可能性がある。 path正規化、percent decode後の禁止文字、method大小などの扱いが曖昧。

## Code Evidence

- Primary source: `crates/codefire-cli/src/http.rs:361`
- Observed implementation fact: request lineをsplit whitespaceしてmethod/pathをそのままdispatchする。

## Recommended Fix

HTTP parser層でmethod enum、normalized path、invalid percent/path rejectionを行う。

## Implementation Notes

- Priority: 公開remoteや共有環境で使う前にリスク評価し、可能なら早めに潰す。
- First step: 拒否すべき入力・許可すべき入力を先にテストで固定する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: [CFR-078](cfr-078.md)

## Acceptance Criteria

- invalid percent/pathを400で拒否する。
- methodは許可listだけ受け入れる。

## Test Plan

- HTTP invalid path/method tests。

## v0.7 Resolution

- HTTP request lineを `GET` / `POST` / `HTTP/1.1` のallow listで検証する。
- request pathはabsolute pathのみ許可し、backslash、scheme-like path、control character、invalid percent escape、decode後の `/`、`\`、`.`、`..` を拒否する。
- Regression: `http_request_rejects_unsupported_method_and_invalid_path`。
