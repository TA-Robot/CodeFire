# CFR-109: evidence commandの非ゼロ終了が成功証跡のように見える

## Problem

command captureはcommand exit codeをmetadataに保存するが、非ゼロ終了をどの程度success/failureとして扱うかのpolicyが弱い。証跡objectの作成自体は成功するため、失敗したtest commandが「成功証跡」と誤読され得る。

## Why It Matters

fire解消のevidenceとして失敗commandを添付できると、整合性保証が弱くなる。もちろん失敗ログ自体も証跡になり得るが、その場合は明示的に `allow_failed_command` のようなintentが必要である。

## Failure Mode / Review Hypothesis

`python -m unittest` が失敗してもevidence objectは作られ、resolution evidence refとして使えてしまう。verifyがevidence command exit codeの意味を再評価しない場合、失敗テストでfireを消せる。

- Observed implementation fact: finish step records command metadata but policy gateが必要。

## Recommended Fix

デフォルトでは非ゼロexitをevidence add failureまたはblocking diagnosticにする。失敗ログを証跡化したい場合は `--allow-failed-command` を要求し、evidence payloadに `proof_status=failed-command-captured` を明示する。

## Fix

Non-zero and timed-out evidence commands are blocking by default and no longer create successful-looking evidence objects. The JSON failure envelope reports diagnostic kind `evidence_command_failed`, resolved cwd, exit code or timeout status, and a next action that points to `--allow-failed-command` only for intentional failed-log capture.

When `--allow-failed-command` is supplied, the evidence is stored with warning diagnostics and `proof_status: failed-command-captured`.
