# CFR-004: `verify` 成功後の状態更新責務が分散している

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | correctness-risk |
| Area | State model |
| Source | `crates/codefire-cli/src/main.rs:202`, `crates/codefire-cli/src/verification.rs:58` |

## Problem

verify commandは `run_verify`、表示、exit codeを扱うが、成功時の状態語の意味や更新責務が表示処理から読み取りづらい。

## Why It Matters

verify実行後に状態が意図せず変化する/しない問題の原因追跡が難しい。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件や並行実行でCodeFireの整合性表示・保存結果がずれる可能性がある。verify実行後に状態が意図せず変化する/しない問題の原因追跡が難しい。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:202`, `crates/codefire-cli/src/verification.rs:58`
- Observed implementation fact: verify commandは `run_verify`、表示、exit codeを扱うが、成功時の状態語の意味や更新責務が表示処理から読み取りづらい。

## Recommended Fix

verifyを「read-only診断」と「state transitionを伴う確認」に分けるか、状態更新を明示関数化する。

## Implementation Notes

- Fixed in v0.7: verification persistence is now isolated in `persist_verification_result_state`.
- `verification_open_state` is the single explicit mapping from verification result to open branch state.
- `verify` persists `scan.json`, `fires.json`, `verification.json`, and `state.json`; clean successful verify moves the open branch to `open-consistent` without introducing open fires.
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: [CFR-003](cfr-003.md), [CFR-005](cfr-005.md), [CFR-006](cfr-006.md)
