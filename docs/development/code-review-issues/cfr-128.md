# CFR-128: HTTP client response bodyに読み取り上限がない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | security |
| Area | HTTP client |
| Source | `crates/codefire-cli/src/http.rs:198`, `crates/codefire-cli/src/http.rs:229` |

## Problem

HTTP clientはresponse headerに64KB上限を持つが、`Content-Length` で宣言されたbody長に対する最大値がなかった。

## Impact

壊れたremoteや悪意あるremoteが巨大な `Content-Length` を返すと、clientが大量メモリを消費し、AI toolの自動サイクルやCIが停止する。

## Code Evidence

- `crates/codefire-cli/src/http.rs:198`: responseを `Vec<u8>` bufferへ蓄積する。
- `crates/codefire-cli/src/http.rs:229`: `body_start + content_length` まで読み続ける。

## Recommended Fix

client response body size limitを導入する。limit超過時はstructured errorを返す。

## Fix

HTTP client response parsing now rejects `Content-Length` larger than `MAX_HTTP_BODY_BYTES` before attempting to read the response body. It uses the same `HttpPayloadTooLarge` error path as oversized server request bodies.

## Acceptance Criteria

- [x] body limit超過responseをclientが即時拒否する。
- [x] limitは安全なdefaultを持つ。
- [x] server request body limitとclient response body limitがdocsに並んで記載される。
