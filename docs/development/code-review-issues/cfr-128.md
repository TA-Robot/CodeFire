# CFR-128: HTTP client response bodyに読み取り上限がない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | security |
| Area | HTTP client |
| Source | `crates/codefire-cli/src/http.rs:198`, `crates/codefire-cli/src/http.rs:229` |

## Problem

HTTP clientはresponse headerに64KB上限を持つが、`Content-Length` で宣言されたbody長に対する最大値がない。

## Impact

壊れたremoteや悪意あるremoteが巨大な `Content-Length` を返すと、clientが大量メモリを消費し、AI toolの自動サイクルやCIが停止する。

## Code Evidence

- `crates/codefire-cli/src/http.rs:198`: responseを `Vec<u8>` bufferへ蓄積する。
- `crates/codefire-cli/src/http.rs:229`: `body_start + content_length` まで読み続ける。

## Recommended Fix

client response body size limitを導入し、endpoint種別ごとの期待最大サイズを設定する。limit超過時はstructured errorを返す。

## Acceptance Criteria

- body limit超過responseをclientが即時拒否する。
- limitは設定可能だが安全なdefaultを持つ。
- server request body limitとclient response body limitがdocsに並んで記載される。

## Test Plan

- mock streamで巨大Content-Length responseを返し、読み取り前に失敗する単体テストを追加する。
