# CFR-033: HTTP serverが単一thread逐次処理

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | security |
| Area | HTTP server |
| Source | `crates/codefire-cli/src/http.rs:286` |

## Problem

`listener.incoming()` を単一loopで処理し、1接続の処理中は次接続を扱わない。

## Why It Matters

遅いclientや大きいuploadが他の操作をブロックする。

## Failure Mode / Review Hypothesis

悪意ある入力または遅い接続によって、remote/serverの可用性や署名境界が弱くなる可能性がある。遅いclientや大きいuploadが他の操作をブロックする。

## Code Evidence

- Primary source: `crates/codefire-cli/src/http.rs:286`
- Observed implementation fact: `listener.incoming()` を単一loopで処理し、1接続の処理中は次接続を扱わない。

## Recommended Fix

thread poolまたはasync runtimeを導入する。依存を避けるならbounded thread spawnとtimeoutを入れる。

## Implementation Notes

- Priority: 機能追加の前後で一緒に片付ける。単独修正でも価値はあるが、関連領域の改修時にまとめると効率がよい。
- First step: 入力上限、timeout、認証/署名境界を先にテストで固定する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: [CFR-031](cfr-031.md), [CFR-032](cfr-032.md)

- slow clientが他requestを完全には止めない。
