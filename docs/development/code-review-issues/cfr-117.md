# CFR-117: ScanResultがchanged atom詳細とnon-Atom変更を同じ粒度で表現しない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | maintainability |
| Area | Core scan model |
| Source | `crates/codefire-core/src/lib.rs:170` |

## Problem

`ScanResult` はchanged Atom IDとopen firesを中心に持つが、non-Atom file changesやchanged Atom detailをcore modelとして同じ粒度で保持していない。CLI側で補足するとscan/status/contextのshapeが分散する。

## Why It Matters

要求定義では非Atomファイル変更もscanで見落とさないことが求められている。core modelが弱いとautomation JSON、text output、commit certificate、contextがそれぞれ別の補完実装を持ちやすい。

## Failure Mode / Review Hypothesis

non-Atom変更の報告がscan textには出るがJSONには弱い、またはcommit dry-runには出ない。toolはdocs/code以外の生成物、設定、artifact変更を見落とす。

## Code Evidence

- Primary source: `crates/codefire-core/src/lib.rs:170`
- Observed implementation fact: `ScanResult` includes `changed_atoms: Vec<String>` and fires, but richer change model is not first-class.
- Related source: `crates/codefire-cli/src/automation.rs:96`
- Observed implementation fact: automation JSON mirrors the simpler core shape.

## Recommended Fix

`ScanChange` modelを導入し、Atom change、non-Atom file change、metadata-only changeを区別する。JSONはsummaryとbounded detailを返し、commit certificateにも必要なcountsを入れる。

## Implementation Notes

- Priority: medium。
- First step: non-Atom file change fixtureでscan JSON/current outputを固定する。
- Boundary: file content snapshotは保存しない。active stateにはmetadataだけ。
- Related issues: CFR-097.

## Acceptance Criteria

- scan resultがnon-Atom changesをfirst-classに持つ。
- JSON/text/context/commit dry-runが同じchange modelを使う。
- outputはboundedでlarge repoに耐える。

## Test Plan

- non-Atom file addition/modification/deletionのscan testsを追加する。
- automation JSONとcontext changedの整合testを追加する。
