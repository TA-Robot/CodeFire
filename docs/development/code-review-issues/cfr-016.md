# CFR-016: 12桁digest IDは大規模化時の衝突余裕が小さい

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | compatibility |
| Area | Object ID |
| Source | `crates/codefire-store/src/lib.rs:88` |

## Problem

object IDはSHA-256 digestの先頭12 hexだけを使っている。

## Why It Matters

object数が増えると衝突確率が上がり、SOTA実験の大量artifact管理では余裕が小さい。

## Failure Mode / Review Hypothesis

インストール名、保存形式、旧実装との互換性が揺れたときに運用が壊れる可能性がある。object数が増えると衝突確率が上がり、SOTA実験の大量artifact管理では余裕が小さい。

## Code Evidence

- Primary source: `crates/codefire-store/src/lib.rs:88`
- Observed implementation fact: object IDはSHA-256 digestの先頭12 hexだけを使っている。

## Recommended Fix

v0.6互換境界でID長を16から24 hex以上へ拡張する計画を作る。

## Implementation Notes

- Priority: 機能追加の前後で一緒に片付ける。単独修正でも価値はあるが、関連領域の改修時にまとめると効率がよい。
- First step: 既存object/CLI/保存形式の読み取り互換性を壊さない移行計画を作る。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: none identified in this review batch.
