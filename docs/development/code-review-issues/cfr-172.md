# CFR-172: read-only adoptionとopen-workspace mental modelを反証するbounded experimentがない

## Summary

| Field | Value |
|---|---|
| Status | investigating |
| Severity | medium |
| Type | product-experiment |
| Area | Read-only adoption / Workspace UX |
| Source | RVC-002/009 |

## Problem

CodeFireは独自sealed/open modelとread-only commandsを持つが、既存repositoryへmutation authorityなしで導入し、
利用者がrepository、branch、open directory、base、head、pending workを正しく理解できる最小profileと実測がない。
identity safetyを直さずUX sugarを足すことも、adoptionを仮定だけでrejectすることも正しくない。

## Root Cause and Deduplication

CFB-048/101/105/108/110/111/114/126、ADR-001/009を再利用する。CFR-163のVerifiedOpenSnapshotを前提に、
Git互換writerやagent orchestrationを追加せず、read-only adapter/mental-model experimentだけをownerにする。

## Required Fix

- mutation不可、claim type明示、snapshot/base/head provenance付きのread-only assessment profile。
- existing repositoryとCodeFire repositoryの両方でsetup/first-result/interpretation taskを実行できるthin adapter。
- open workspace stateを一画面/JSONで説明するcanonical modelとrepair-safe guidance。
- falsifier、measurement、stop ruleを先に固定したdogfood/independent-consumer experiment。

## Acceptance Criteria

- adapter/profileはbranch/object/open stateを変更せず、before/after hashesで証明する。
- 参加者またはclean-room consumerがsource code/private clarificationなしでbase/head/worktree/claim kindを判定する。
- setup time、first useful result、誤解、wrong action、maintenance costを記録し、adopt/iterate/stopを明示する。
- valueがsetup/maintenance costを超えない場合はsurfaceをcoreへ昇格せずterminal stop decisionにする。

## Test Plan

- canonical/configured/plain-repo read-only hash matrix。
- minimal consumer task packetとscored comprehension fixture。
- experiment result/decision recordのproject-doc check。
