# CFR-031: HTTP request body size上限がない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | security |
| Area | HTTP server |
| Source | `crates/codefire-cli/src/http.rs:336` |

## Problem

headerは64KiB上限があるが、`content-length` に対する最大値チェックがない。

## Why It Matters

大きすぎるupload requestでメモリを消費し、簡単にDoSになる。

## Failure Mode / Review Hypothesis

悪意ある入力または遅い接続によって、remote/serverの可用性や署名境界が弱くなる可能性がある。大きすぎるupload requestでメモリを消費し、簡単にDoSになる。

## Code Evidence

- Primary source: `crates/codefire-cli/src/http.rs:336`
- Observed implementation fact: headerは64KiB上限があるが、`content-length` に対する最大値チェックがない。

## Recommended Fix

body size上限を設定し、remote storage policyで変更可能にする。

## Implementation Notes

- Priority: v0.6 hardeningで優先的に潰す。整合性、security、または大規模運用での破綻につながる。
- First step: 入力上限、timeout、認証/署名境界を先にテストで固定する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: [CFR-032](cfr-032.md), [CFR-033](cfr-033.md)

## Acceptance Criteria

- 上限超過時に413相当の応答を返す。
- upload bundleの正当なサイズ上限をドキュメント化する。

## v0.7 Resolution

HTTP request bodyに `MAX_HTTP_BODY_BYTES` を導入し、超過時は `HttpPayloadTooLarge` として413応答に分類するようにした。確認テストは `http_request_rejects_oversized_body_before_reading_body`。
