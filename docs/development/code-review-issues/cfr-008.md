# CFR-008: 引数parserが手書きで重複している

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | maintainability |
| Area | CLI parser |
| Source | `crates/codefire-cli/src/main.rs:1273`, `crates/codefire-cli/src/main.rs:1354` |

## Problem

`parse_open_args`、`parse_path_json_args`、`parse_extinguish_args` などが手書きwhile/forで似た処理を重複実装している。

## Why It Matters

新option追加時に `--flag=value` 対応漏れやusage不整合が起きやすい。

## Failure Mode / Review Hypothesis

今後の修正で責務混在や差分衝突が増え、不変条件を守りにくくなる。新option追加時に `--flag=value` 対応漏れやusage不整合が起きやすい。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:1273`, `crates/codefire-cli/src/main.rs:1354`
- Observed implementation fact: `parse_open_args`、`parse_path_json_args`、`parse_extinguish_args` などが手書きwhile/forで似た処理を重複実装している。

## Recommended Fix

依存追加を許容するなら `clap`、避けるなら内部の軽量parser helperを作る。

## Implementation Notes

- Fixed in v0.7: shared parser helpers now cover common mutating options (`--dry-run`, `--json`, `--idempotency-key`, `--wait-lock`, `--lock-timeout`), path/json/metrics flags, and required option value extraction.
- `open`, `clone`, `commit`, `extinguish`, `patch import`, `merge`, `upload`, `request-merge`, `request-review`, and `request-apply` now use the common mutating option helper for shared options.
- Table-style parser tests for mutating dry-run/json/lock/idempotency forms continue to cover `--flag value` and `--flag=value` behavior.
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: none identified in this review batch.

## Acceptance Criteria

- lock/idempotency/path/json/metrics等の共通option parserが共有される。
- usage文字列と実parserの差分をテストする。
