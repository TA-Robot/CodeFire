# CFR-116: VerificationCommandがenv/max_output/timeoutの契約をcore型で十分表現しない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | correctness-risk |
| Area | Verification policy |
| Source | `crates/codefire-core/src/lib.rs:126` |

## Problem

`VerificationCommand` core型はcommand/cwdを中心に表現しているが、timeout、env allowlist、max stdout/stderr、failure policyなど、外部検証を安全に実行するための契約が型として十分ではない。

## Why It Matters

外部検証commandはcommit gateに直結する。CLI側やremote server側で個別にtimeout/env制限を実装すると、local verifyとserver-side verificationの意味がずれる。

## Failure Mode / Review Hypothesis

policy fileで表現できない制約をCLI runner側defaultに頼る。server-side verificationでは別のdefaultになり、localで通った検証がremoteで落ちる、またはその逆が起きる。

## Code Evidence

- Primary source: `crates/codefire-core/src/lib.rs:126`
- Observed implementation fact: `VerificationCommand` is the core policy model for external checks.
- Related source: `crates/codefire-cli/src/main.rs:3900`
- Observed implementation fact: CLI runner executes verification commands using policy data.

## Recommended Fix

`VerificationCommand` にtimeout_ms、env policy、max_output_bytes、allow_failure semanticsを明示する。default policyはcoreで定義し、CLI/remoteは同じ型を使う。

## Implementation Notes

- Priority: medium。
- First step: policy parserのroundtrip/golden testを追加する。
- Boundary: process sandbox自体は別設計。まずpolicy contractを型に出す。
- Related issues: evidence command timeout系、remote server verification。

## Acceptance Criteria

- verification policyでtimeout/env/output capを表現できる。
- local/remote verification runnerが同じdefaultを使う。
- docsにpolicy fieldとdefaultが記載される。
