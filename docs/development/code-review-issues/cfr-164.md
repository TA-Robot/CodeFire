# CFR-164: trust-sensitive request/evidenceが完全subjectとresource profileへ束縛されない

## Summary

|---|---|

## Problem

remote request HMACはoperation/actor/target等のsignature metadataだけを認証し、mutation bodyやobject集合を
束縛しない。request keyのvalidity windowを評価せず、nonce cacheは容量超過時にTTL内nonceをevictする。
verification/evidence commandはsubject provenance、environment/secret policy、streaming resource boundを一つの
execution profileとして固定していない。

## Code Evidence

- `signatures.rs::{sign_remote_request_with_key,request_signature_digest,hmac_policy_secret,record_request_nonce}`。
- `evidence.rs::{capture_shell_command,capture_argv_command,run_child_command_capture}`。
- `explain.rs`のFire viewはrepo/branch/base/snapshot provenanceを持たない。

## Root Cause and Deduplication

CFR-036/037/041-045/109/116、CFB-127、ADR-013は個別timeout、nonce、evidence、outcomeを改善したが、
「誰がどの完全subjectをどのexecution profileで評価したか」の上位contractがない。既存issueを再openせず、
versioned subject/trust profileへ統合する。

## Required Fix

- canonical payload hash、operation、target、actor、key、idempotency key、time、nonceを持つversioned remote subject。
- request key validity/rotationと、TTL中nonceを決してforgetしないbounded replay policy。
- verification/evidence commandのexplicit environment、secret redaction、cwd/input digest、streaming output cap、result subject。
- context/explain/review/certificateへ同じsubject digestとtrust kindを投影する。
- live assessment subjectへcanonical worktree manifest digestを束縛し、verify開始前からbranch publish直前まで再照合する。

## Acceptance Criteria

- signed requestの任意payload/object field改変は全transportでpre-write signature failureになる。
- not-yet-valid/expired keyを拒否し、nonce capacity到達時はlive nonce evictionではなく新規requestをfail closedする。
- command outputはprocess終了前からboundedに読み、raw secret/envをdefault captureしない。
- 同じsemantic request/executionのcanonical subject bytesがclient/server、file/HTTP、Rust/Python fixtureで一致する。
- diagnostics/evidence/certificateはsubject digest、profile、phaseを漏えいなしで説明する。
- verification後のworktree差替えはcommit object/branch publication前にfail closedし、certificateとmanifestを同一subjectへ固定する。

## Resolution

remote mutationはversion 2 request signatureとversion 1 canonical subjectへ移行し、actor、operation、target、
key、UTC timestamp、nonce、idempotency key、完全payload digestをHMACへ束縛した。Rust/Python、file/HTTPは
同じgolden vectorを使用し、legacy version 1 signature、payload差替え、key window外、型不正をpre-writeで
fail closedにする。nonce cacheはTTL内entryをevictせず、capacity到達時は新規requestを拒否し、malformed
evidenceを上書きしない。Python fallbackのdefault skew未適用とlocal-time `Z` 解釈は独立監査で検出し、
UTC `calendar.timegm`と常時default 300秒検証へ修正した。

local executionはassessment/execution subjectをversion化した。live subjectはrepository、branch、open instance、
base、scan content、canonical worktree manifestを束縛し、context、explain、verify、certificateが同じidentityを
投影する。commitはverification後、decision/transaction前、manifest plan後、branch publish直前にworktree
digestを再照合し、recoveryもcandidate/open一致を再計算する。review packはimmutable `sealed_commit_pair`を
使う。verification/evidenceはminimal environment、contained cwd、streaming cap、timeout/process-group scope、
input/environment digest、secret/URI/path redactionを記録し、raw environment valueを永続化しない。

## Retrospect

署名、verification、evidence、context、review、certificateを個別の「信頼できそうな出力」として扱わず、
canonical subject、execution profile、pre-write/republication checkへ統合したことで、同じidentityをtransportと
lifecycle全体で検証できるようになった。独立監査がRust/Pythonの時刻差を実際に検出し、source testだけでなく
installed non-UTC timezone反例までClose gateへ追加した。OS-level sandboxやdistributed replay storeはclaimせず、
`local_unisolated`とfile-local nonce cacheの制約を維持する。新しいblockerは最終installed/real/canonical
Dogfoodで見つからず、凍結順序どおり次はCFR-165 remote publication rootへ進む。
