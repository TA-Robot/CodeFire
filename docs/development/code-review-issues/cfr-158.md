# CFR-158: manual fire UIDがbase_commitを含み同じ意味のfireがcommit後に再発行される

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | correctness-risk |
| Area | Fire identity |
| Source | `crates/codefire-cli/src/fire.rs:390`, `crates/codefire-cli/src/fire.rs:405` |

## Problem

manual fire identityがbase commitを含むため、同じ対象・同じ理由のmanual fireでもcommitが変わると別UIDとして生成され得る。

## Impact

同じ課題がcommitごとに別IDとなり、重複排除や履歴追跡が難しくなる。

## Recommended Fix

semantic identityとoccurrence identityを分ける。semantic keyはtarget/type/severity/message正規化値、occurrenceにはbase commitを入れる。

## Acceptance Criteria

- 同じ意味のmanual fireはcommit後も重複検出される。
- occurrence履歴としてbase commitを追える。
- UID生成規則がdocsに記載される。

## Test Plan

- 同じmanual fireをcommit前後で追加し、重複扱いになるtestを追加する。

## Resolution

- Manual fire semantic key no longer includes `base_commit`; it is based on source atom, target atom, reason, severity, and trace path hash.
- The current base commit remains visible in the operation plan as occurrence context, while UID/display identity stays semantic.
- Regression: `manual_fire_and_batch_validate_before_writing_fires`; dogfood manual fire dry-run returned `fire_sha256_*` UID independent of sequence numbering.
