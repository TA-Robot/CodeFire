# CFR-136: contextのtruncated flagが省略件数を返さない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Context |
| Source | `crates/codefire-cli/src/context.rs:306`, `crates/codefire-cli/src/context.rs:396` |

## Problem

context JSONは `truncated` の真偽値を返すが、何件省略されたか、どの種類のnode/linkが省略されたかを返さない。

## Impact

AI toolが追加取得すべきか判断できない。省略された情報量が不明なまま設計判断を行う危険がある。

## Recommended Fix

`omitted_counts` と `limit_reached_reason` を追加し、atoms/links/fires/evidenceごとの省略数を返す。

## Acceptance Criteria

- limit到達時に省略件数がmachine-readableに返る。
- text outputでも「省略あり」と次の取得commandが出る。
- 省略なしの場合の契約が明確。

## Test Plan

- 小さいlimitでcontextを実行し、省略件数が返ることを確認する。

## Fix

- Fixed in the global burn-down pass.
- `context` now includes machine-readable omitted counts under `data.summary`.
- `context` text output prints omitted counts and a suggested follow-up command when bounded output omits data.
- JSON output includes a `context_expand` next action when omitted data or omitted endpoints are present.
