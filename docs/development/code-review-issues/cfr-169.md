| Field | Value |

## Problem

責務module抽出は進んだが、`main.rs`はopen/clone/merge/commit/ancestry/lock/recordsを、CLIはobject reference
traversalとcommit JSON constructionを、巨大test filesは多数のfixture/helperを引き続き所有する。invariant changeの
reading/proof surfaceが広く、StoreとCLIでobject semanticsがdriftし得る。

## Root Cause and Deduplication

CFR-001/002/039/040の過去分割を再openせず、line countそのものではなく、今回のroot fixesに必要な
parse/validate/plan/apply/render、domain/store/workspace/transaction、fixture ownershipをacceptanceにする。

## Required Fix

- local lifecycleとopen snapshot/recoveryを責務moduleへ移し、`main.rs`をdispatch/composition中心にする。
- object reference traversal、commit/root builders、version validationをStore/domain ownerへ集約する。
- test helpers/fixturesをfeature-local moduleとcross-boundary integrationへ分け、同じinvariantの重複setupを除く。
- source architecture/command trace/data catalogを実ownerへ同期する。

## Acceptance Criteria

- public command pathがparse→validate→plan→apply→renderのownerを一意に追跡できる。
- CLIはobject kind/reference/root schemaを独自再定義せずStore APIを使う。
- feature regressionsはfeature-local test module、transport/formatはintegration corpusから実行される。
- behavior/JSON/object bytesは分割前後goldenで同一で、large refactorに無関係な機能変更を混ぜない。

## Test Plan

- ownership/source-doc checker、golden object/envelope comparison。
- focused module testsとfull workspace gate。
- removed duplicate helper/reference registry search。

## Current Source Audit

- `cli_model`、`open_snapshot`、`open_transaction`、`close_transaction`、`close_worktree`、
  `active_state`、`commit_active_reset`、`merge_resolution`、`secure_worktree`、`branch_refs`、
  `remote/{project,locks,operations,publication,doctor}` は既に責務ownerとして分離済みである。
  cohesiveなsession/proof/reducerを行数だけで再分割しない。
- 真の最初の残差は`remote.rs`のobject reference traversalとobject-directory registryである。commit roots、
  manifest blob、resolution/evidence/extension referenceをCLIとStoreが二重解釈しているため、Storeのtyped
  registry/callbackへ一利用者ずつ移し、順序・closure・first error・work counter golden後にCLI定義を削除する。
- production init/commitは`main.rs`でcommit/root JSONを直接構築し、Storeの現builderはfixture用途に偏る。
  typed root set/payload inputをStoreへ置き、canonical bytes、object ID、signed subject digestを不変にしたまま
  init、commitの順で移行する。
- `main.rs`にはstate transaction、commit transaction/recovery、repository IO/lock/context、merge/clone/
  branch-list/scan/verify等のworkflow ownerが残る。repository foundation→open/close依存解消→state transaction→
  commit transaction/workflow→残存vertical sliceの順で抽出し、最後にmainをparse/dispatch/renderへ限定する。
- `command-source-trace.md`のopen/close owner表記と、Store registry抽出後の`check_source_docs.py`参照先も
  実装と同時に同期する。CFR-168のHTTP publication仕様が固定する前にHTTPの物理分割は行わない。
