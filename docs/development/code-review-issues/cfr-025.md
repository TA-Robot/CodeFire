# CFR-025: rename detectionが削除×追加の全組み合わせLCSになっている

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | performance |
| Area | Diff |
| Source | `crates/codefire-cli/src/view/file_diff.rs:128` |

## Problem

削除fileと追加fileの二重loopで `similarity_score` を呼び、その中でLCSを計算する。

## Why It Matters

大量rename候補や大きいfileでdiff/review packが急激に遅くなる。

## Failure Mode / Review Hypothesis

入力規模が増えたときに処理時間またはメモリ使用量が急増する可能性がある。大量rename候補や大きいfileでdiff/review packが急激に遅くなる。

## Code Evidence

- Primary source: `crates/codefire-cli/src/view/file_diff.rs:128`
- Observed implementation fact: 削除fileと追加fileの二重loopで `similarity_score` を呼び、その中でLCSを計算する。

## Recommended Fix

size/hash/line fingerprintで候補を絞り、上限を超える場合はrename detectionを自動抑制する。

## Implementation Notes

- Priority: v0.6 hardeningで優先的に潰す。整合性、security、または大規模運用での破綻につながる。
- First step: 最悪ケースの入力サイズを決め、修正前後の計算量と実測を比較する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: [CFR-026](cfr-026.md), [CFR-027](cfr-027.md)

## Acceptance Criteria

- 削除N×追加Mが閾値超過時に警告付きでskipできる。
- 完全一致renameはhashで高速検出する。
