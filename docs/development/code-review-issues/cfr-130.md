# CFR-130: commit書き込みがmulti-object transactionとして扱われていない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | correctness-risk |
| Area | Commit durability |
| Source | `crates/codefire-cli/src/main.rs:3678`, `crates/codefire-cli/src/main.rs:3740` |

## Problem

commit処理は複数objectを書いた後にbranch headを更新するが、途中失敗時のtransaction manifestやcleanup方針がない。

## Impact

未参照objectが残り、storage reportやdoctorのノイズになる。将来GCやremote uploadを入れると、未完了commit由来objectの扱いが曖昧になる。

## Code Evidence

- `crates/codefire-cli/src/main.rs:3678`: commit rootを順にobject storeへ書く。
- `crates/codefire-cli/src/main.rs:3740`: branch head更新までに複数段階の失敗点がある。

## Recommended Fix

commit operationにtransaction idを導入し、pending manifestをactive metadataへ記録する。成功時にcomplete、失敗時にdoctorがoperation単位で診断できるようにする。

## Acceptance Criteria

- commit途中失敗の残骸をdoctorがoperation単位で説明できる。
- branch head更新前のobjectは未committedとして区別される。
- transaction metadataは正常commit後にcleanになる。

## Test Plan

- fault injectionで各object write後に失敗させ、doctor診断を確認する。
