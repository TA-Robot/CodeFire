# CFR-167: policy rule provenanceとnon-Atom coverageがtyped decision inputでない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | correctness-risk / explainability |
| Area | Verification policy / Change coverage |
| Source | RVC-008/016 |

## Problem

ADR-013はauthoritative outcomeとsafety floorを固定したが、各policy ruleのstable identity、default/override source、
effective value、適用対象、理由をdecision factとして保持しない。non-Atom/out-of-Atom/deleted-Atom changeもreportには出るが、
何がsemantic coverage内外かをtyped factとしてpolicy、certificate、explainへ一貫投影できない。

## Root Cause and Deduplication

CFB-003/017/025/115、CFR-022/116/117、CFR-161/ADR-013の成果を消費する拡張であり、committable predicateを
再びsurface別booleanへ分裂させない。outcomeではなくinput provenance/coverage contractをownerにする。

## Required Fix

- stable rule ID、source、effective value、applicability、safety classを持つeffective policy model。
- file/span/Atom relationを表すtyped `ChangeCoverage` factと、non-Atom/deleted/out-of-spanの明示分類。
- decision、diagnostic、explain、certificateへrule/coverage subjectをlossless投影する。
- policy/hash/schema migrationで既存resolution/verificationを正しくstale化する。

## Acceptance Criteria

- 同じinputは順序に依存せず同じeffective policy/rule digestを作る。
- default、repo config、CLI override、unsupported relaxationの出所と採否をJSON/textで説明できる。
- pure non-Atom、mixed Atom/out-of-span、deleted Atom、tool migrationのdecision tableが全surfaceで一致する。
- sealed validationはrule/coverage/result driftを拒否し、legacy profileを過剰claimしない。

## Implementation Evidence

- Coreに`effective-verification-policy-v1`を追加し、stable rule ID、default/repository/CLI source、
  effective value、applicability、safety class、order-independent digestを一つのcontractへ集約した。
  現行CLIに汎用override flagは追加せず、precedenceと`cli_override` provenanceはcore contractで固定した。
- Coreに`file-relation-v1` `ChangeCoverage`を追加し、`non_atom_file`、`deleted_atom`、
  `out_of_atom_change`、`atom_change_with_unclassified_spans`、source不変tool migrationを分類する。
  `span_precision=file_only_no_span_claim`により、未保持の行/byte範囲をcoveredと過剰claimしない。
- scan/status/verify/diagnostic/explain/commit planのtext/JSONへ同じpolicy/coverage factまたはdigestを投影した。
  通常JSONのcoverage detailは50件でboundし、summary/digestを保持したまま`--full`で全件を返す。
- policy rootとverification rootへ同じeffective policy、verification rootへcoverage、certificateへ両digestを
  sealした。Storeはrule/value/digest、classification/summary/digest、root間およびcertificate間driftを拒否し、
  historicalな両contract欠落はclaimなしとして読む。
- ADR-019がadditive disclosure claim、将来のblocking coverage policyに必要なschema/profile evolution、
  resolutionのsemantic policy hashと新しいprovenance digestの役割分離を記録する。

## Retrospect

当初の`non_atom_changed_files`は「Atomが変わった同一fileの未分類byte」を隠していたため、単なるfield追加では
なく全manifest差分からtyped relationを構築した。復旧testはcommit candidate再構築が古いpolicy root shapeを
生成する反例を発見し、recoveryも通常writerと同じcontractへ統一した。diagnosticへ独立infoを増やす案は既存件数契約を
壊したため、実diagnosticのbounded decision contractへdigestをbindした。新規blockerはなく、次のfrozen rootはCFR-168である。
