# CFR-035: remote generation更新が独立lockされていない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | correctness-risk |
| Area | Remote generation |
| Source | `crates/codefire-cli/src/remote.rs:1354` |

## Problem

`next_remote_generation` は `gc_state.json` を読み、+1してwriteするが、この関数自体にはlockがない。

## Why It Matters

複数branchや複数操作が同時にgenerationを進めるとlost updateが起き得る。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件や並行実行でCodeFireの整合性表示・保存結果がずれる可能性がある。複数branchや複数操作が同時にgenerationを進めるとlost updateが起き得る。

## Code Evidence

- Primary source: `crates/codefire-cli/src/remote.rs:1354`
- Observed implementation fact: `next_remote_generation` は `gc_state.json` を読み、+1してwriteするが、この関数自体にはlockがない。

## Recommended Fix

generation専用lockを取るか、remote全体のtransaction lock内でのみ呼べるAPIにする。

## Implementation Notes

- Priority: v0.6 hardeningで優先的に潰す。整合性、security、または大規模運用での破綻につながる。
- First step: 小さな再現fixtureを作って、現状の挙動を固定してから修正する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: none identified in this review batch.

- lockなし呼び出しを型/APIで防ぐ。
