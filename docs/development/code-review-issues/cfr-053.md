# CFR-053: opened registryのopen path整合性をdoctorが検証していない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | correctness-risk |
| Area | Doctor |

## Problem

opened registryはbase commitとactive_state_pathの存在を見るが、`.codefire-open` markerやopen pathとの相互整合性は見ない。

## Why It Matters

移動・コピー・手動編集されたopen directoryの不整合をdoctorで検出しづらい。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件・並行実行・破損状態でCodeFireの整合性判断がずれる可能性がある。 移動・コピー・手動編集されたopen directoryの不整合をdoctorで検出しづらい。

## Code Evidence

- Primary source: `crates/codefire-cli/src/doctor/checks.rs:166`
- Observed implementation fact: opened registryはbase commitとactive_state_pathの存在を見るが、`.codefire-open` markerやopen pathとの相互整合性は見ない。

## Recommended Fix

registry open.path、marker、active_state_path、branch名を相互検証する。

## Acceptance Criteria

- 存在しないopen pathをwarning/errorに分類する。

## Test Plan

- opened registry marker consistency test。

## Resolution

- Fixed in v0.7: doctor now validates `opened` registry `branch.name`, `open.open_instance_id`, `open.path`, `open.current_base_commit`, `open.active_state_path`, and `state.last_known`.
- If `open.path` exists, doctor reads `.codefire-open` and cross-checks repository path, branch name, open instance ID, and opened path against the registry.
- Missing open paths and marker mismatches are reported as structured issues and included in the `reopen_branch_workspace` next action.
