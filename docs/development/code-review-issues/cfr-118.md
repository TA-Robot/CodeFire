# CFR-118: unknown object ID lookupがsubdir全走査へ落ちる

## Problem

`object_record_path` はobject ID prefixからsubdirを推定できない場合、known subdirを走査して一致fileを探していた。互換性には有用だが、不正/未知ID入力が多い場合に不要なfilesystem scanが発生する。

## Why It Matters

remoteやpatch importなど外部入力からobject IDを受ける経路では、malformed IDを大量に渡される可能性がある。未知prefixで全subdir scanすると、DoS的なI/O増加を招く。

## Failure Mode / Review Hypothesis

invalid object IDを多数含むmanifest/remote requestを検証すると、各IDごとにobjects subdirを走査する。object storeが大きいほど拒否処理が遅くなる。

## Code Evidence

- Primary source: `crates/codefire-store/src/lib.rs:237`
- Observed implementation fact: object record path resolution has fallback scan for unknown prefix.
- Related source: `crates/codefire-store/src/lib.rs:354`
- Observed implementation fact: sealed commit validation repeatedly resolves object references.

## Recommended Fix

object ID format validationを先に行い、未知prefixは原則即errorにする。legacy互換が必要な場合はbounded fallbackに限定する。

## Fix

`object_record_path` now routes known prefixes directly and rejects unknown `CF-*` prefixes without scanning object subdirectories. The compatibility fallback remains available for legacy non-`CF-` object IDs and generic `CF-OBJECT-*` records.
