# CFR-118: unknown object ID lookupがsubdir全走査へ落ちる

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |

| Area | Object lookup |
| Source | `crates/codefire-store/src/lib.rs:237` |

## Problem

`object_record_path` はobject ID prefixからsubdirを推定できない場合、known subdirを走査して一致fileを探す。互換性には有用だが、不正/未知ID入力が多い場合に不要なfilesystem scanが発生する。

## Why It Matters

remoteやpatch importなど外部入力からobject IDを受ける経路では、malformed IDを大量に渡される可能性がある。未知prefixで全subdir scanすると、DoS的なI/O増加を招く。

## Failure Mode / Review Hypothesis

invalid object IDを多数含むmanifest/remote requestを検証すると、各IDごとにobjects subdirを走査する。object storeが大きいほど拒否処理が遅くなる。

## Code Evidence

- Primary source: `crates/codefire-store/src/lib.rs:237`
- Observed implementation fact: object record path resolution has fallback scan for unknown prefix.
- Related source: `crates/codefire-store/src/lib.rs:354`
- Observed implementation fact: sealed commit validation repeatedly resolves object references.

## Recommended Fix

object ID format validationを先に行い、未知prefixは原則即errorにする。legacy互換が必要な場合は明示legacy modeまたはbounded fallbackに限定する。

## Implementation Notes

- Priority: medium。
- First step: malformed object ID validation testとlookup count testを追加する。
- Boundary: documented legacy object IDsは壊さない。

## Acceptance Criteria

- malformed/unknown prefix object IDが全subdir scanしない。
- legacy valid IDは引き続き読める。
- remote validationでinvalid referencesの拒否がboundedになる。
