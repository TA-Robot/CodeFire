# CFR-019: 明示 `cf-atom` のcontent hashがマーカー行だけを見ている

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | correctness-risk |
| Area | Atom extraction |
| Source | `crates/codefire-core/src/lib.rs:1122` |

## Problem

`extract_explicit_cf_atoms` は `cf-atom:` を含む行だけを `content_hash` にしている。

## Why It Matters

関数本体やテスト本体が変わってもマーカー行が同じならAtom変更として検出されない可能性が高い。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件や並行実行でCodeFireの整合性表示・保存結果がずれる可能性がある。関数本体やテスト本体が変わってもマーカー行が同じならAtom変更として検出されない可能性が高い。

## Code Evidence

- Primary source: `crates/codefire-core/src/lib.rs:1122`
- Observed implementation fact: `extract_explicit_cf_atoms` は `cf-atom:` を含む行だけを `content_hash` にしている。

## Recommended Fix

language-aware extractorで関数/ブロック範囲をhash対象にする。最低限、次のatom markerまでの範囲をhashする。

## Implementation Notes

- Priority: v0.6 hardeningで優先的に潰す。整合性、security、または大規模運用での破綻につながる。
- First step: 小さな再現fixtureを作って、現状の挙動を固定してから修正する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: [CFR-020](cfr-020.md), [CFR-021](cfr-021.md)
