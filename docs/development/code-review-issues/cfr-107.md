# CFR-107: evidence JSONが解決後のcommand cwdを返さない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Evidence capture |
| Source | `crates/codefire-cli/src/evidence.rs:355` |

## Problem

evidence command captureではcommand cwdのdefault解決やvalidationを行うが、JSON resultには解決後のcwdが十分に出ない。operation planには指定値があるが、実際にどこで実行されたかを後からmachine-readableに確認しにくい。

## Why It Matters

証跡は再現性が重要である。AI toolがテスト実行証跡を保存する場合、実行cwdがrepo rootなのかopen dirなのかsubdirなのかを明確に記録できないと、後で証跡の意味を判断しづらい。

## Failure Mode / Review Hypothesis

commandは成功しevidence objectも作られるが、JSON consumerがresolved cwdを知らない。別環境で再実行しようとすると、相対pathの解釈がずれる。

## Code Evidence

- Primary source: `crates/codefire-cli/src/evidence.rs:355`
- Observed implementation fact: `evidence_add_data_json` builds result data.
- Related source: `crates/codefire-cli/src/evidence.rs:399`
- Observed implementation fact: operation plan includes cwd-related input, but result summary needs resolved execution cwd.

## Recommended Fix

`EvidenceAddResult` に `resolved_command_cwd`、`cwd_source`、`repo_relative_cwd` を追加し、evidence object payloadとJSON resultの両方へ保存する。

## Implementation Notes

- Priority: medium。
- First step: default cwdとexplicit cwdのevidence JSON testを追加する。
- Boundary: command execution sandboxではなくmetadata clarity。
- Related issues: CFB-049, CFR-108.

## Acceptance Criteria

- evidence JSON resultにresolved cwdが出る。
- evidence objectにも再現可能なcwd metadataが残る。
- repo外cwdの場合はredaction/absolute path policyに従う。

## Test Plan

- `--from-command` default cwd、`--command-cwd` explicit cwd、repo外cwd validation testsを追加する。

## Fix

`EvidenceAddResult` and the stored evidence payload now include resolved command cwd metadata:

- `command_cwd`
- `command_cwd_source`
- `repo_relative_command_cwd`

The command cwd source is stable (`explicit_cwd` or `caller_cwd`), and repo-relative cwd is emitted when the resolved cwd is under the CodeFire repository root.
