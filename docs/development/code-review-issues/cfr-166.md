# CFR-166: version/capability/conformanceがruntime全境界を閉じていない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | compatibility-risk |
| Area | Persisted schemas / Capabilities / Cross-runtime conformance |
| Source | RVC-006/007/013/017/020/022/032/033/049/053/055/057/059, CFB-134 |

## Problem

current Storeはcommit/root future versionをfail closedにする一方、branch、MR、remote idempotency等のpersisted
recordはversion/commandを十分検証せず、unknown root/extensionのcriticalityとreference traversal semanticsもない。
public command schema family、cursor snapshot contract、実行可能support profile、runtime-independent corpus/minimal consumerが
揃っておらず、Rust defaultとPython fallbackのcapability driftがremote doctorで実害化した。

## Root Cause and Deduplication

CFB-128/131/132、CFR-071/080/121-123、ADR-012がlegacy semantic/profileとsealed rootsを強化した。
残差は「全persisted/public boundaryを同じsupport decisionとconformance corpusで判定するowner」がないことであり、
個別parserの緩いfield追加で解消しない。

## Required Fix

- repository/object/branch/MR/idempotency/remote/public-command schemaのversion support matrixとcritical extension rule。
- unknown/missing/versioned fieldのALLOW/DENY/MIGRATEを一つのcapability registryへ登録する。
- command result/inputのchecked-in JSON Schema family、cursor/page/snapshot semantics、capability negotiation。
- Rust/Python golden corpus、manifest/checksum、writer/reader expectations、independent minimal consumer。
- default Rustのfile/HTTP remote doctorをadvertised capabilityと同じsemantic validatorへ接続する。

## Acceptance Criteria

- 全persisted record loaderがmissing legacy、supported current、unknown futureを決定表どおり処理する。
- unknown critical extension/referenceをsilent dropせず、noncritical extensionだけをround-tripする。
- advertised command/options/schema/profileと実装がgenerated/checked manifestで一致する。
- Rust/Python両writerのselected fixtureを両readerとminimal consumerが期待どおりaccept/rejectする。
- remote doctorはhealthy/corrupt/missing file/HTTP projectをtyped/boundedに診断し、URLをlocal path扱いしない。
