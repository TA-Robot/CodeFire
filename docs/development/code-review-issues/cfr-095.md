# CFR-095: CliErrorにstructured diagnosticへの変換責務がない

## Problem

`CliError` はDisplayとexit code分類を持つが、automation diagnosticへ変換する責務を持たない。結果として各commandが失敗をJSONにするには個別実装が必要で、global failure pathはtext-onlyになっている。

## Why It Matters

stable exit codeだけではAI toolに十分ではない。kind、severity、blocking、target、repairable、suggested commandが必要である。診断変換がないとCFR-081系のJSON失敗問題を全commandで直しにくい。

## Failure Mode / Review Hypothesis

usage/config/repo corruption/remote rejection/lock contentionがすべてmessage string中心で扱われる。textが変わるとtoolが壊れ、severityやrepairabilityがdocsと実装で乖離する。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:831`
- Observed implementation fact: `CliError` enum is central, but diagnostic serializationは別概念として存在しない。
- Related source: `crates/codefire-cli/src/exit_code.rs`
- Observed implementation fact: exit code taxonomy exists, diagnostic taxonomyとの接続が不足している。

## Recommended Fix

`CliDiagnostic` structを導入し、`impl CliError { fn diagnostic(&self) -> CliDiagnostic }` を提供する。automation envelopeはこのdiagnosticを使い、human text rendererとは分ける。

## Fix

`CliError` now owns `diagnostic()` and maps every variant to a diagnostic kind, severity, blocking flag, repairability flag, exit code, and message. JSON error envelopes call this method instead of ad hoc default serialization. Representative unit tests cover usage, repository, remote/auth, and JSON parse classes.

## Implementation Notes
