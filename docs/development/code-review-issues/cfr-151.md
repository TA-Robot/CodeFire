# CFR-151: migration next_actionsがautomation共通schemaを使っていない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | maintainability |
| Area | Migration |
| Source | `crates/codefire-cli/src/migration.rs:161`, `crates/codefire-cli/src/automation.rs:402` |

## Problem

migration reportのnext_actionsがmigration module内の独自JSONとして生成され、automation共通schemaと揃っていない。

## Impact

migrationはrepo修復の入口だが、AI toolが自動実行計画へ変換するにはmigration専用adapterが必要になる。

## Recommended Fix

migrationも共通 `NextAction` 型を返し、migration固有情報は `context` に入れる。

## Fix

Implemented in the global burn-down pass:

- Migration next actions now use `automation::next_action`.
- Migration-specific counts are emitted under canonical `target`, with legacy `context` alias preserved.
- Regression coverage asserts the common next action schema for migration blockers.

## Acceptance Criteria

- migration next_actionsが共通required fieldsを持つ。
- `migrate apply` actionがpathとdry-run/apply distinctionを持つ。
- text outputも共通rendererを使う。

## Test Plan

- migration check JSON schema snapshotを追加する。
