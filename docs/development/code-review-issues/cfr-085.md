# CFR-085: `show --json` がhelp上の契約と実装で一致していない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | bug |
| Area | View CLI |
| Source | `crates/codefire-cli/src/main.rs:338`, `crates/codefire-cli/src/view.rs:92` |

## Problem

`subcommand_help` は `show <branch-or-url> [--json]` を案内しているが、実装側の `show` pathは `--json` をparseせず、`view.rs::show_commitish` のtext outputをそのまま出す。

## Why It Matters

helpに出たcontractをAI toolが信じると、JSON parseに失敗する。`show` はsealed commitのroots、certificate、verificationを確認する重要commandなので、structured outputがないこと自体も問題である。

## Failure Mode / Review Hypothesis

`codefire show main --json` がhuman textを返す、または `--json` をcommitishとして扱う可能性がある。外部toolはcommit metadataを安定して抽出できず、review-packやdiffへfallbackする。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:338`
- Observed implementation fact: show dispatch prints returned string directly.
- Related source: `crates/codefire-cli/src/view.rs:92`
- Observed implementation fact: `show_commitish` returns `String`, not a typed view model.

## Recommended Fix

`ShowOptions` と `ShowResult` を導入し、commit ID、parents、roots、certificate、verification summary、manifest summaryをstructured dataとして返す。text rendererは `ShowResult` から生成し、`--json` はenvelopeに包む。

## Implementation Notes

- Priority: high。helpと実装の不一致は即修正対象。
- First step: `show --help` と `show --json` のcontract regression test。
- Boundary: full review-packとは別に、sealed commit summaryの範囲に絞る。
- Related issues: CFB-057, CFR-081.

## Acceptance Criteria

- helpに出る `--json` が実際に有効になる。
- `show --json` は `ok=true` envelopeとtyped `data.show` を返す。
- unknown targetの失敗もJSON envelopeになる。

## Test Plan

- local branch、remote branch、unknown branchで `show --json` testsを追加する。
- docs/CLI specを更新する。
