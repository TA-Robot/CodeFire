# CFR-144: explain text rendererがnext_actionのid fieldを前提にしている

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Explain |
| Source | `crates/codefire-cli/src/explain.rs:116`, `crates/codefire-cli/src/explain.rs:129` |

## Problem

explainのtext rendererはnext_actionに `id` fieldがある前提で表示するが、automation系next_actionは `kind` を使う。

## Impact

JSONではactionが存在していてもtextでは空や不自然な表示になり、問題解決の導線が途切れる。

## Recommended Fix

共通 `NextAction` rendererを導入し、id/kindの揺れをなくす。text rendererはschema化されたfieldだけを見る。

## Fix

Implemented in the global burn-down pass:

- Explain now creates next actions with the shared serializer.
- Explain text rendering reads `kind` first and falls back to `id` for legacy payloads.
- JSON/text action labels remain meaningful after schema normalization.

## Acceptance Criteria

- explain text outputで全next_actionが意味のあるラベルを持つ。
- JSON/textでaction数が一致する。
- unknown schema actionを出せない型設計になる。
