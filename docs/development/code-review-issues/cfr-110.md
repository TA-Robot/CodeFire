# CFR-110: HTTP error responseがCliError文字列へ潰される

## Problem

HTTP clientはremote serverからのerror responseを読み取るが、最終的には `HTTP remote error: ...` のようなusage stringへ潰す経路がある。server側がstructured JSON diagnosticを返してもclient側で保持できない。

## Why It Matters

remoteは信頼境界であり、auth failure、permission denial、invalid sealed graph、nonce replayなどを正確に区別する必要がある。clientが文字列化すると、automationは原因別のretry/修正/報告ができない。

## Failure Mode / Review Hypothesis

HTTP remote uploadがsignature failureで拒否されても、client側はusage-like errorとして扱う。exit codeやdiagnostic kindがremote rejection/auth/signatureと一致しない可能性がある。

## Code Evidence

- Primary source: `crates/codefire-cli/src/http.rs:143`
- Observed implementation fact: request/response handling converts HTTP error detail to CLI error.
- Related source: `crates/codefire-cli/src/main.rs:831`
- Observed implementation fact: `CliError` lacks structured remote diagnostic fields.

## Recommended Fix

HTTP response parserでserver JSON error envelopeを保持し、`CliError::RemoteDiagnostic` のようなvariantへ変換する。HTTP status、remote diagnostic kind、request idをclient JSONへ伝播する。

## Fix

HTTP client error responses now convert into `CliError::RemoteDiagnostic` instead of a plain usage string. The variant preserves HTTP status, remote exit code, remote diagnostic kind, and message. If the server returns `diagnostics[0].kind`, the client JSON envelope exposes that kind; otherwise it derives a remote rejection/auth/idempotency kind from the remote exit code.
