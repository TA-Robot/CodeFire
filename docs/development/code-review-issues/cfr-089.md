# CFR-089: manifest diffが全file blobをメモリへ展開する

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | performance |
| Area | View/Diff |
| Source | `crates/codefire-cli/src/view.rs:466` |

## Problem

`manifest_contents` はmanifest配下のblob contentを `BTreeMap<String, Vec<u8>>` として読み込む。diff、review-pack、patch exportの前段で全file contentを同時に保持するため、大きなcommitやbinary-heavy repoでメモリ使用量が膨らむ。

## Why It Matters

CodeFireはAI toolが大規模repoを扱う前提がある。diff対象の一部だけを見たい場合でも全manifest contentを展開すると、不要なI/Oとメモリを消費し、review automationの速度が落ちる。

## Failure Mode / Review Hypothesis

左右commitのmanifestが多数の大きなblobを含む場合、差分の少ない比較でも両側全contentを読み込み、メモリがrepoサイズに比例する。diff output capがあっても、読み込み時点のメモリ消費は抑えられない。

## Code Evidence

- Primary source: `crates/codefire-cli/src/view.rs:466`
- Observed implementation fact: function returns a map from path to full byte vector.
- Related source: `crates/codefire-cli/src/view.rs:144`
- Observed implementation fact: diff path consumes commitish content through view layer.

## Recommended Fix

manifest entry metadataとblob content readerを分ける。まずpath/hash/sizeで差分候補を決め、必要なfileだけstream/readする。binaryやlarge fileはsummary diffへ早期分岐する。

## Implementation Notes

- Priority: high。asymptotic memory issue。
- First step: `ManifestView` / `BlobReader` abstractionを作る前にlarge manifest regression testを追加する。
- Boundary: object store identityは変更しない。
- Related issues: CFR-088, CFR-086.

## Acceptance Criteria

- diff/review/patchは全blobを同時に保持しない。
- unchanged fileのcontentは読み込まない。
- large file diffでmemory-sensitive pathを検証するtestがある。

## Test Plan

- large unchanged filesを含むcommit diffで、content reader呼び出し数を制御できるunit testを追加する。
- file_diff既存testとgolden fixtureを維持する。

## Fix

- Added manifest metadata comparison before blob reads for the normal non-rename diff path.
- `patch export` now compares manifest path/blob IDs first and only reads source blob content for changed write entries.
- Kept rename/copy detection on the existing full-content path because similarity detection intentionally needs candidate content.
- Added a view module regression test where an unchanged blob ID is intentionally missing; metadata diff succeeds because unchanged content is not read.
