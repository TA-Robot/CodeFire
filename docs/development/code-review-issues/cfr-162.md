# CFR-162: unresolved merge stateをverify/commitがseal可能と判定する

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | correctness-risk |
| Area | Merge state / committable decision |
| Source | RVC-039 safety boundary, ADR-013, `main.rs::{apply_merge_result,compute_verify_with_cache,commit_parents_for_open}` |

## Problem

local merge applyはtext conflict、binary sidecar、semantic conflict candidateをactive
`state.json`へ保存する。しかしRust verificationはFire、Trace、resolution、evidence、duplicate Atom、
external checkだけから`CommittableDecision`を作り、merge metadataを読まない。

そのため非Atom fileの競合markerが残っていてもverifyはpassedになり、commit previewは二親commitを
`blocked=false`で計画できる。binary conflict sidecarや未確認semantic candidateも同じ経路で正式履歴へ
sealできる。

## Runtime / Regression Counterexample

`crates/codefire-cli/src/tests/merge_resolution.rs` に、base/target/sourceで`README.md`を別々に変更し、
targetへtext conflict markerを書いたfixtureを追加した。修正前のfocused runでは
`committable_decision`がpassedとなり、最初の安全assertionで失敗した。

```text
unresolved merge conflict was incorrectly considered committable
test result: FAILED. 0 passed; 1 failed
```

これは`docs/11_internal_architecture.md`のverification input一覧、
`docs/development/known-limitations.md`の「conflict markerはverify/commit blocker」、および予約済み
exit code 15と矛盾する。

## Root Cause and Deduplication

merge applyが記録したactive factを、ADR-013のtyped committable decisionへ渡すdomain inputがない。
RVC-039のshared semantic assessment実験すべてを昇格するのではなく、seal safetyだけを本issueへ分離する。
CFB-104はmerge直後のFire persist時期、CFB-118はdry-run next actionの問題であり、このseal bypassを
閉じていない。

## Required Fix

- text、binary、semanticのunresolved merge factsをversion-compatibleなVerification fieldへ載せる。
- `CommittableReason::UnresolvedMergeConflicts`を非緩和blockerとし、verify、commit、JSON、diagnostic、
  next action、human output、explain、sealed validationを同じdecisionへ接続する。
- exit code 15をmerge blockerのauthoritative exitにする。
- `codefire merge --continue`を明示的なresolution transitionとする。text markerが消え、binary sidecarが
  除去され、semantic candidateが明示承認された場合だけ、repository lockとpinned worktree subjectの下で
  conflict metadataを解消済みに遷移させる。
- dry-run、blocked、successful applyをJSON/textで区別し、blocked pathではactive/branch/object authorityを
  変更しない。
- conflict-free mergeとlegacy verification readは維持し、Python fallbackへ新しいwriter surfaceを
  暗黙追加しない。

## Acceptance Criteria

- unresolved text、binary、semantic conflictの各fixtureでverifyとcommit dry/liveがexit 15になり、
  immutable object、branch head、opened baseをpublishしない。live verify/commitが失敗verificationをactive
  stateへ正規persistすることは許容する。
- text markerを除去しただけではmetadataが勝手に消えず、`merge --continue`が検査してから解消する。
- binary sidecarが一つでも残る場合はcontinueがblocked、除去後は通る。
- semantic candidateは`--accept-semantic-conflicts`なしではcontinueできない。
- continue後のverifyがpassedになり、live commitは元headとsource headをparentsに持つsealed merge commitを作る。
- malformed merge metadata、path traversal、symlink/identity replacementはfail closedする。
- legacy verificationで新fieldが欠ける場合はemptyとして読み、non-empty fieldを持つsealed snapshotは拒否する。

## Resolution

- `Verification.unresolved_merge_conflicts` と `CommittableReason::UnresolvedMergeConflicts` を追加し、
  text、binary、semanticのactive merge factを非緩和の最優先blockerへ統合した。verify、commit、JSON、
  diagnostics、next actions、human output、explain、sealed validationは同じtyped decisionを消費する。
- `codefire merge --continue` を独立したparse/validate/apply境界として実装した。repository lockと
  pinned worktreeの下で、generated text boundary、binary sidecar、semantic acknowledgementを再検査し、
  成功時だけversion 1のresolution recordを保存してconflict metadataを消す。blocked/dry-runは
  active、object、branch、opened authorityを変更しない。
- legacy verificationで新fieldが欠ける場合はemptyとして読み、non-empty unresolved factを含むsealed
  snapshotはsemantic validatorが拒否する。Python fallbackにはwriter surfaceを追加していない。
- Markdownの正当なsetext separator `=======` 単独はgenerated conflict boundaryではないため許可し、
  `<<<<<<< target` / `>>>>>>> source` の残存だけをtext blockerとして扱う。
