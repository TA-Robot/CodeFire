# CFR-161: committable safety floorとCLI projectionがpolicy falseで分裂する

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | correctness-risk |
| Area | Verification policy / committable decision |
| Source | RVC-011, `crates/codefire-core/src/lib.rs::verification_result_from_signals`, `crates/codefire-cli/src/{automation.rs,exit_code.rs,main.rs,verification.rs}` |

## Problem

`VerificationPolicy` は `require_no_required_fires`、`require_no_stale_resolutions`、
`require_verification_success`、`reject_duplicate_atom_ids` を `false` にできる。coreの
`verification_result_from_signals` はその値でraw factをcommit blockerから外す一方、CLIの
diagnostic、human summary、next action、exit priorityは同じcollectionを独立に再判定する。

そのため一つのverificationが `result=passed` / process exit 0 / envelope `ok=true` / next action
`commit` と、`blocking=true` diagnosticを同時に返せる。commit gateは`result`だけを見るため、
required Fireを残したsealed commitも計画できる。

## Runtime Counterexample

`/tmp/codefire-rvc011-repro.LtKS5J` を現行final installed binaryでimportし、
`require_no_required_fires: false` のpolicy下でrequired Fireを1件作成した。

- `verify`: process exit 0、`result=passed`、`open_required_fires=1`、envelope `ok=true`、
  `blocking=true` diagnostic 1件、next action `commit`。
- `commit --dry-run`: process exit 0、`blocked=false`、verification `passed`、6 mutation operations。
- Evidence: `/tmp/codefire-rvc011-{import,fire,verify,commit-dry}.json`。

これは `docs/05_consistency_model.md` の、open required Fire、failed check、stale resolution、missing
evidence、duplicate Atom IDを常に0とするcommittable predicateに反する。policyでwarningへ落とせる
現行例外はmissing required linkの`require_trace_completeness=false`だけである。

## Root Cause and Deduplication

raw facts、policy applicability、outcome、primary reasonを持つdomain decisionがなく、consumerが
`Verification` fieldsと`result`を再解釈している。RVC-008、RVC-016、RVC-034は別issueにせず、
RVC-011のauthoritative-decision rootへ統合する。既存CFB-003/006、CFR-073/122/127/140/159は
個別projectionまたはcertificate mismatchの修正であり、このbypass rootを閉じていない。

## Required Fix

- raw verification factsから一度だけ `CommittableDecision` を構築し、typed blocker/warning reason、
  stable primary priority、outcomeを持たせる。
- open required Fire、stale resolution、missing evidence、duplicate Atom ID、required external check
  failureを非緩和のsafety floorとする。旧boolean fieldsの明示`false`はworking configで拒否し、strict
  sealed snapshotではfalseによるblocker downgradeをfail closedする。safety floorを満たすhistorical
  clean snapshotのreadabilityは維持する。
- missing required linkだけは`require_trace_completeness=false`でfactを保持したnon-blocking warningに
  できる。
- verify process/envelope、diagnostics、next actions、human summary、open state、commit gate、certificate、
  sealed validationを同じtyped decisionからprojectionする。
- persisted verification/object schemaは必要なしに変更せず、legacy-unversioned historyのreadabilityを
  維持する。

## Acceptance Criteria

- 全blocker class × policy applicability × multiple blockersのdecision tableがcoreで通る。
- safety-floor fieldを`false`にしたconfigはfield名付きconfiguration errorになり、immutable objectを
  書かない。
- programmatic/deserialized unsafe policyでも`build_verification`とstrict sealed validationは
  committableへdowngradeしない。
- 全table rowでprocess exit、JSON `ok/exit_code`、diagnostic `blocking`、next action、human summary、
  state、commit gate、certificate resultが同じoutcome/primary reasonを表す。
- 新reason追加時はexhaustive mappingがcompile/test failureになり、successへfallbackしない。

## Test Plan

- Core: safety-floor policy table、trace-warning row、multiple-blocker priority、unsafe blocker sealとclean historical read。
- CLI unit: reason-to-exit/diagnostic/text/actionのexhaustive table。
- Integration:上記runtime counterexampleがverify exit 2でconfig errorになり、commit dry/liveともobject/head/
  active stateを変えない。
- Full: fmt、warning-denying Clippy、workspace tests、source/project docs、fresh installed Dogfood。

## Resolution

- Added core `CommittableOutcome`, `CommittableReason`, and `CommittableDecision` plus one ordered
  decision table over all six reason classes.
- Rust working config rejects `false` for the four safety-floor compatibility fields before verify
  scan-state or commit publication writes. `require_trace_completeness=false` remains supported.
- `build_verification` and schema-2 sealed validation ignore unsafe false values as relaxations;
  blocker-bearing inconsistent seals fail, while clean historical false-policy seals remain readable.
- Verify exit/envelope `ok`/`data.result`/`data.decision`, diagnostics, next actions, human output,
  explain, open state, commit plan/gate/certificate, and Store validation now consume the core
  decision. Reason-to-exit/diagnostic/action/text mappings are exhaustive enum matches.
- ADR-013 and product/source/runbook/policy/fallback-boundary documentation record the contract.
