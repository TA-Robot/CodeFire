# CFR-105: storage full scanがobject JSONを毎回全件parseする

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | performance |
| Area | Storage report |
| Source | `crates/codefire-cli/src/storage.rs:362` |

## Problem

storage report full modeはobject filesを走査し、record wrapperやpayload typeを確認するため全件JSON parseする。doctorにも類似の全件parseがあり、大規模object storeではI/OとCPUが支配的になる。

## Why It Matters

storage reportはdogfooding cycleで頻繁に実行するcheckpointである。大規模repoではquick/defaultとfull/deep validationの差を明確にし、incremental cacheやsamplingを検討しないと使い勝手が落ちる。

## Failure Mode / Review Hypothesis

objectsが数十万件あるrepoで `storage --full --json` が長時間走り、AI toolのtimeoutやコンテキスト待ちを引き起こす。quick modeでもlargest objectsなどのために再帰走査が重い可能性がある。

## Code Evidence

- Primary source: `crates/codefire-cli/src/storage.rs:362`
- Observed implementation fact: `scan_objects` owns object file scan and full mode parsing.
- Related source: `crates/codefire-cli/src/doctor/checks.rs:87`
- Observed implementation fact: doctor also validates object records by parsing files.

## Recommended Fix

quick/full/deepの責務を明確化し、full scanにはphase metrics、file count cap warning、optional cacheを設計する。doctorとstorageでobject record scan serviceを共有する。

## Implementation Notes

- Priority: medium。
- First step: storage full scan metricsとlarge object store fixtureを追加する。
- Boundary: correctness validationを省略するのではなく、modeに応じて明示する。
- Related issues: CFR-051の再発防止、CFR-104.

## Acceptance Criteria

- quick modeはobject JSON full parseを避ける。
- full modeは件数/時間/bytes metricsを返す。
- doctor/storageでobject scan logicが重複しない方向へ整理される。

## Test Plan

- many object fixtureでquick/fullのparse behaviorを検証する。
- metrics JSONにobject scan phaseが出ることを確認する。

## Fix

- Added `objects.scan` to storage report JSON with mode, elapsed_ms, files_seen, bytes_seen, json_records_parsed, and invalid_records.
- Quick mode remains metadata-only and now exposes `json_records_parsed=0` so automation can assert that full object JSON parsing was skipped.
- Full mode exposes parsed record counts and invalid record counts, making large-store cost visible without adding a separate metrics flag.
- Existing storage report tests now assert the quick/full parse behavior and scan metrics shape.
