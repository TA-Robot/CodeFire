# CFR-093: status JSONがrepo root取得失敗を握りつぶす

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | correctness-risk |
| Area | Status JSON |
| Source | `crates/codefire-cli/src/main.rs:525` |

## Problem

`status` JSONでrepo情報を作る際、`open_context(&options.path).ok()` のように失敗をOptionへ落としている経路がある。status本体が成功しても、open context検証の失敗理由がdiagnosticにならず、repo fieldが欠落または弱い値になる可能性がある。

## Why It Matters

statusはautomationの起点であり、repo/open identityは次action生成に必要である。open markerやregistryの不整合を握りつぶすと、doctorへ誘導すべき状態でも単なる情報欠落に見える。

## Failure Mode / Review Hypothesis

破損した `.codefire-open` やopened registryでstatusが部分成功し、JSON consumerはrepo pathを信頼できない。後続commandがcwd依存になり、dogfoodingで観測されたcwd/path不整合を増幅する。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:525`
- Observed implementation fact: status JSON path retrieves open context with `.ok()`.
- Related source: `crates/codefire-cli/src/main.rs:4096`
- Observed implementation fact: `read_status` itself has richer state loading path.

## Recommended Fix

status resultに `repo_context` または `context_diagnostics` を持たせ、open context取得に失敗した場合はwarning diagnosticとして明示する。JSON repo fieldの算出はstatus load resultから一貫して行う。

## Implementation Notes

- Priority: medium。
- First step: malformed open marker fixtureでstatus JSONがdiagnosticを返すtestを追加する。
- Boundary: statusをdoctor代替にしない。詳細修復はdoctor next_actionへ渡す。
- Related issues: CFR-081, CFB path issues.

## Acceptance Criteria

- status JSONがrepo/open context不整合を握りつぶさない。
- diagnosticにdoctor実行next_actionが出る。
- clean repoでは従来のstatus JSON shapeが維持される。
