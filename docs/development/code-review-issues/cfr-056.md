# CFR-056: storage reportのobject type判定がrecord wrapperを考慮していない可能性がある

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | correctness-risk |
| Area | Storage report |
| Source | `crates/codefire-cli/src/storage.rs:330` |

## Problem

object fileは `ObjectRecord { object_id, type, hash, payload }` だが、reportはtop-level `type` を読んでいる。

## Why It Matters

payload typeとrecord typeのどちらを集計しているか曖昧になり、unknown扱いや誤集計につながる可能性がある。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件・並行実行・破損状態でCodeFireの整合性判断がずれる可能性がある。 payload typeとrecord typeのどちらを集計しているか曖昧になり、unknown扱いや誤集計につながる可能性がある。

## Code Evidence

- Primary source: `crates/codefire-cli/src/storage.rs:330`
- Observed implementation fact: object fileは `ObjectRecord { object_id, type, hash, payload }` だが、reportはtop-level `type` を読んでいる。

## Recommended Fix

ObjectRecordとしてparseし、record.type_tagとpayload.typeの整合性も診断する。
