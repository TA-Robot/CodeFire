# CFR-028: conflict markerがbinary/text混在を十分に区別しない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | correctness-risk |
| Area | Merge |
| Source | `crates/codefire-cli/src/main.rs:4113` |

## Problem

conflict contentは `String::from_utf8_lossy` でbytesを文字列化してmarkerに埋め込む。

## Why It Matters

binaryや非UTF-8ファイルのconflictで内容が変質した作業treeを書き出す可能性がある。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件や並行実行でCodeFireの整合性表示・保存結果がずれる可能性がある。binaryや非UTF-8ファイルのconflictで内容が変質した作業treeを書き出す可能性がある。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:4113`
- Observed implementation fact: conflict contentは `String::from_utf8_lossy` でbytesを文字列化してmarkerに埋め込む。

## Recommended Fix

binary conflictはmarkerを書かず、両側artifactを別名保存するかconflict metadataのみ出す。

## Implementation Notes

- Fixed in v0.7: text conflicts still get conflict markers, but binary or non-UTF-8 conflicts no longer pass through lossy UTF-8 conversion. Merge writes sidecar bytes under `.codefire-conflicts/<path>/target` and `.codefire-conflicts/<path>/source`, records `binary_conflicts` metadata in merge result/state, and keeps the target file unchanged.
- Priority: 機能追加の前後で一緒に片付ける。単独修正でも価値はあるが、関連領域の改修時にまとめると効率がよい。
- First step: 小さな再現fixtureを作って、現状の挙動を固定してから修正する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: none identified in this review batch.
