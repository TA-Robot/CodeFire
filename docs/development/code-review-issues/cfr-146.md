# CFR-146: fire operation planのnext_actionがpath情報を持たない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Fire dry-run |
| Source | `crates/codefire-cli/src/fire.rs:434`, `crates/codefire-cli/src/fire.rs:437` |

## Problem

fire operation planのnext_action commandがrepo/open pathを含まず、現在directoryに依存して実行される。

## Impact

AI toolが複数repoをまたいで操作すると、pathless commandが別repoへ作用する危険がある。

## Recommended Fix

next_actionには `repo_root`, `open_dir`, `cwd_requirement`, `command_args` を持たせ、表示用commandにも `--path` を含める。

## Acceptance Criteria

- fire dry-run next_actionを別cwdから実行しても同じrepoに作用する。
- next_action JSONにpath contextがある。
- pathが長い場合のtext表示も崩れない。

## Test Plan

- 別cwdからnext_action commandを実行するintegration testを追加する。

## Resolution

- Fire operation plan next actions now include `--path <open_dir>` in display commands.
- Next action targets include `branch`, `open_dir`, and `repo_root` so automation does not depend on caller cwd.
- Regression: `manual_fire_and_batch_validate_before_writing_fires`; dogfood manual fire dry-run showed path-qualified verify/extinguish commands.
