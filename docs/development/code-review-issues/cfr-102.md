# CFR-102: batch extinguish成功JSONが適用結果の直接summaryを持たない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | ux |
| Area | Batch result JSON |
| Source | `crates/codefire-cli/src/batch.rs:223` |

## Problem

batch extinguishのresult dataはoperation plan寄りで、適用後に何件解消したか、どのfire IDが更新されたか、active open fire countがどう変わったかを直接読み取りにくい。

## Why It Matters

AI toolはbatch後に次のverify/scanへ進むかを判断する。成功結果にapplied summaryがないと、追加でstatus/scan/contextを呼ぶ必要があり、操作回数とログが増える。

## Failure Mode / Review Hypothesis

batch commandが成功しても、toolは「全件適用された」「部分適用なし」「open firesが残っている」をresultだけで判断できない。結果として次action生成が保守的になり、無駄なscanを繰り返す。

## Code Evidence

- Primary source: `crates/codefire-cli/src/batch.rs:223`
- Observed implementation fact: operation plan builder is central, success result summaryとは別の構造が弱い。
- Related source: `crates/codefire-cli/src/main.rs:3325`
- Observed implementation fact: single extinguish result has richer per-fire result context.

## Recommended Fix

`ExtinguishBatchResult` を導入し、`applied_count`、`fire_ids`、`resolution_ids`、`remaining_open_fire_count`、`active_state` を返す。dry-run planとは別schemaにする。
