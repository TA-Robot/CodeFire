# CFR-096: status next_actionsがchanged countやfreshnessを見ずにverifyを勧める

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Automation next_actions |

## Problem

`status_next_actions` はstate中心でnext actionを作り、changed atom count、non-Atom changes、active scan freshnessなどを十分に見ない。clean stateでもverifyやcommitへ誘導する挙動が残り得る。

## Why It Matters

AI toolはnext_actionsを実行計画に使う。状態の根拠が薄いnext actionは無駄なverify/commit dry-runループを生み、dogfooding速度とログ量を悪化させる。

## Failure Mode / Review Hypothesis

open-cleanかつ変更なしの状態でverify next_actionが出る。toolはverifyを実行し、さらに別のnext_actionを見て同じ状態を巡回する。freshnessが古い場合にもscanではなくverifyを勧める可能性がある。

## Code Evidence

- Primary source: `crates/codefire-cli/src/automation.rs:49`
- Observed implementation fact: status next actions are generated from `Status` state fields with limited freshness context.
- Related source: `crates/codefire-cli/src/automation.rs:121`
- Observed implementation fact: scan next actions also clean状態の扱いが単純。

## Recommended Fix

state reducerにchanged_count、open_fire_count、verification freshness、active scan sourceを含め、next_actionsはreducer resultから生成する。clean/no-change状態ではno-op summaryを返し、verifyを勧めない。

## Implementation Notes

- Priority: medium。
- First step: clean repo status JSONでnext_actionsが空またはno-opになるtestを追加する。
- Boundary: next_actionsは実行管理機能ではなくCLI contract。
- Related issues: CFB-052, CFR-098, CFR-114.

## Acceptance Criteria

- clean unchanged statusで不要なverify/commit actionが出ない。
- stale scanならscanを優先する。
- open firesがある場合はfire/context/extinguish導線を優先する。

## Test Plan

- clean、changed、open fire、stale verificationのstatus next_actions testsを追加する。

## Fix

- Fixed in the global burn-down pass.
- `status_next_actions` no longer emits a verify action for `open-clean`.
- This avoids no-op verify loops when status already reports a clean branch with zero open fires.
- Open-fire status still emits context guidance through the open fire count guard.
