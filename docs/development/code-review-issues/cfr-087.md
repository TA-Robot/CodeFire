# CFR-087: review-packとpatch exportにautomation向けJSON envelopeがない

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | ux |
| Area | Review/Patch CLI |
| Source | `crates/codefire-cli/src/main.rs:367`, `crates/codefire-cli/src/main.rs:381` |

## Problem

`review-pack` と `patch export` はreviewや外部tool連携で使うcommandだが、標準の `--json` envelopeとして結果を返すcontractが弱い。file出力またはraw printに寄っており、成功/失敗/出力先/サイズ/omissionを共通schemaで扱えない。

## Why It Matters

AI toolがreview packやpatchを作るとき、出力先、対象commit、含まれるdiff、サイズ超過、omitted filesをstructuredに知る必要がある。現状ではcommand実行後にファイルの存在確認やtext parseが必要になる。

## Failure Mode / Review Hypothesis

`--output` 指定時にstdoutが少なく、automationが何を生成したか分からない。失敗時はtext errorになり、patch exportの対象や制限値をdiagnosticとして記録できない。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:367`
- Observed implementation fact: review-pack result string is written or printed without command envelope.
- Related source: `crates/codefire-cli/src/main.rs:381`
- Observed implementation fact: patch export also write/print pathに寄っている。

## Recommended Fix

`ReviewPackResult` と `PatchExportResult` を導入し、`--json` ではoutput path、bytes written、included sections、omissions、resolved commit IDsをenvelopeで返す。payloadそのものとmetadataを分ける。

## Implementation Notes

- Priority: medium。
- First step: `--output` 指定時にmetadata JSONを返すtestを追加する。
- Boundary: patch import/applyの意味論は別issueで扱う。
- Related issues: CFB-063, CFR-088.

## Acceptance Criteria

- review-pack/patch exportがJSON metadata resultを返す。
- generated payloadが大きい場合はmetadataにsize/omissionが出る。
- failure pathがCFR-081のJSON error contractに従う。

## Test Plan

- output fileあり/なし両方を確認する。
