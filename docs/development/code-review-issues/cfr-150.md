# CFR-150: metrics対応がcommand capabilityとして管理されていない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | maintainability |
| Area | Metrics |
| Source | `crates/codefire-cli/src/metrics.rs:1`, `crates/codefire-cli/src/main.rs:474` |

## Problem

metricsの型とrendererはあるが、どのcommandがmetrics対応かを宣言するcapability registryがない。

## Impact

command追加のたびにparser、help、rendererが別々に更新され、`--metrics` を受けるが出さない、helpにないが動く、といったズレが起きる。

## Recommended Fix

command metadataに `supports_metrics` を持たせ、parser/help/result envelopeが同じ値を使う。

## Fix

`command_registry.rs` now defines command capabilities with `supports_metrics`. Completion/help use the same command list, `codefire capabilities --json` exposes capability metadata, and metrics parser checks consult the registry so unsupported `--metrics` flags return structured errors.

## Acceptance Criteria

- [x] metrics対応表がdocs/help/JSON capabilityから取得できる。
- [x] 非対応commandのmetrics flagはstructured errorになる。
- [x] 対応commandは必ずmetrics blockを出す。

## Test Plan

- command registryのmetrics coverage testを追加する。
