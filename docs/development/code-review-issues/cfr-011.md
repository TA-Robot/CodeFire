# CFR-011: atomic write後にfsyncがない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | correctness-risk |
| Area | Atomic write |
| Source | `crates/codefire-cli/src/main.rs:4000` |

## Problem

temp fileへwriteしrenameするが、file syncやparent directory syncがない。

## Why It Matters

OSクラッシュ時にbranch headやregistryのdurabilityが保証しきれない。

## Failure Mode / Review Hypothesis

通常ケースでは動いても、境界条件や並行実行でCodeFireの整合性表示・保存結果がずれる可能性がある。OSクラッシュ時にbranch headやregistryのdurabilityが保証しきれない。

## Code Evidence

- Primary source: `crates/codefire-cli/src/main.rs:4000`
- Observed implementation fact: temp fileへwriteしrenameするが、file syncやparent directory syncがない。

## Recommended Fix

重要メタデータ書き込みではfile syncとdirectory syncを行う保存APIへ統一する。

## Implementation Notes

- Priority: 機能追加の前後で一緒に片付ける。単独修正でも価値はあるが、関連領域の改修時にまとめると効率がよい。
- First step: 小さな再現fixtureを作って、現状の挙動を固定してから修正する。
- Boundary: AI agent運用機能やmarketplaceをCodeFire本体へ入れず、整合性管理・履歴封印・自動化tool向けI/Oの改善として扱う。
- Related issues: none identified in this review batch.

## Acceptance Criteria

- branch head、registry、remote generation更新がdurable write APIを使う。
- 非対応platformでは明示的にbest-effort扱いする。

## Test Plan

- save API unit testとplatform別feature gate。

## v0.7 Resolution

- CLI metadata用 `write_json_atomic` はtemp fileへ書き込み後 `sync_all` し、rename後にparent directory syncをbest-effortで行う。
- branch head、opened registry、active state、remote generationなど既存の重要JSON更新は同APIを通る。
- 非対応platformやpermission制限ではdirectory syncをbest-effortとして扱う。
