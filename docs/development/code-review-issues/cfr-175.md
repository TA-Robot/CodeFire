# CFR-175: file remote authority componentsがcanonical containmentを持たない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | critical |
| Type | security-risk / correctness-risk |
| Area | File remote URL / merge-request authority paths |
| Source | `crates/codefire-cli/src/remote.rs`, `codefire` |

## Problem

file transportはpercent decode後のorg/app/branchとcaller supplied MR IDをtyped componentへ正規化せず、ambient
`PathBuf::join`へ渡す。HTTP transportにはdot component、separator、backslash、control文字の拒否がある一方、file
transportとPython fallbackは同じ境界を共有していない。remote project、lock、transaction、MR authorityが意図した
directoryの外を参照し得るため、ADR-017のcanonical project/resource identityを成立させられない。

## Why It Matters

lockとtransactionが保護するpathと実際にread/replaceされるauthority pathが一致しない。入力componentが別projectや
別authority fileへ解決されると、排他・idempotency・signature target・GC rootの全不変条件を迂回する。

## Failure Mode / Review Hypothesis

- decode後にnormal componentでないorg/appをproject root構築へ渡すと、configured projects root外へ解決できる。
- file review/applyはMR IDをlock nameではencodeするが、MR JSON pathではそのままjoinするため、lock対象とauthority対象が
  分裂できる。
- Python file transportも同型で、Rustだけのsanitizerではcross-runtime layoutを証明できない。

## Code Evidence

- `remote.rs::parse_cf_url` / `parse_cf_project_url`はdecoded componentを検証せずproject pathへjoinする。
- `remote.rs::review_merge_request` / `apply_merge_request`は`format!("{}.json", options.mr_id)`をMR directoryへjoinする。
- Python `parse_cf_url`、`cmd_request_review`、`cmd_request_apply`もambient path constructionを行う。
- HTTP `decode_http_path_component`にはより強いcomponent拒否があり、transport間contractが分裂している。

## Recommended Fix

Rust/Python/file/HTTPで一つのstrict remote component contractを共有し、org/app/branch/MR IDをversioned validated typesへ
変換してからだけauthority enumへ渡す。remote I/Oはpinned `RemoteProject` capabilityと
`RemoteAuthority::{Branch,MergeRequest,...}`からpathを導出し、任意Pathをpublication reducerへ渡さない。

## Implementation Notes

- Priority: ADR-017 implementation前のsame-batch blocker。
- First step: invalid component matrixがlayout/lock/nonce/transactionを一切作らない回帰を追加する。
- Boundary: filesystem general sandboxではなくremote authority namespaceのcontainmentを所有する。
- Related issues: CFR-165、CFR-174、ADR-017、RVC-041/045/050。

## Acceptance Criteria

- decode後のempty/current/parent、separator、backslash、absolute/prefix、control componentを全runtime/transportでpre-write拒否する。
- MR authority pathはvalidated MR IDからのみ導出され、lock/transaction/read/writeが同じtyped authorityを共有する。
- project rootと全authority parentはpinned no-follow capabilityへ束縛され、swap/symlink/non-regular inputをfail closedする。
- invalid inputでproject layout、nonce cache、lock owner、transaction、branch/MR/objectが変化しない。

## Test Plan

- org/app/branch/MR IDの共通invalid-component golden matrixをRust/Pythonで実行する。
- project/authority parent replacement、symlink、non-directory、file identity changeをwrite前後で検証する。
- file/HTTPのcanonical valid component/result identityを同じfixtureで確認する。

## Implemented Source Evidence

- Rust/Python file/HTTP components use one strict post-decode contract before project layout,
  nonce, lock, transaction, or authority publication. Maximum portable names use bounded,
  domain-separated filenames without aliasing direct names.
- `remote::project` owns the stable descriptor, bootstrap serialization, no-follow bounded reads,
  and typed authority path derivation; publication accepts typed generation/branch/MR authorities.
- Project gate acquisition rechecks descriptor/root/lock-directory identity. Symlink, hard-link,
  intermediate replacement, descriptor replacement, and authority collision fixtures fail closed.
- Invalid-component golden matrices match across runtimes, and MR list/review require that the
  recorded target belongs to the routed project before dereferencing authority.
- The local threat model coordinates CodeFire writers through the project gate; it does not claim
  isolation from an actively racing non-cooperating process with the same filesystem credentials.
  Independent final source review found no blocker within that boundary.

## Close Evidence

- Shared Rust/Python invalid-component fixtures, maximum-name/hash-alias tests, symlink/hard-link/
  descriptor/parent replacement tests, and file/HTTP pre-write nonmutation tests pass.
- Fresh installed remote upload/request/review/replay uses descriptor-backed contained paths; the
  installed counterexample reversal, full gates, real probes, and independent High review pass.

## Retrospect

Authority containment has to precede locking and journaling: otherwise the protected resource and
the written path can differ. The accepted local boundary coordinates CodeFire writers; active
non-cooperating same-credential filesystem attackers remain explicitly outside the claim.
