# CFR-111: `CODEFIRE_HTTP_TIMEOUT_MS` の不正値が診断されない

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | low |
| Type | ux |
| Area | HTTP client config |
| Source | `crates/codefire-cli/src/http.rs:333` |

## Problem

HTTP timeout環境変数のparseで、不正値や非正値を明確なdiagnosticにせずdefaultへ戻す経路があった。ユーザーはtimeoutを設定したつもりでも、実際には無視される可能性があった。

## Why It Matters

dogfoodingやCIでremoteが遅い場合、timeout調整は重要である。不正設定が沈黙すると、通信timeout問題の切り分けが難しくなる。

## Failure Mode / Review Hypothesis

`CODEFIRE_HTTP_TIMEOUT_MS=abc` でHTTP commandを実行してもwarningが出ず、default timeoutで動く。ユーザーは設定が効いていると誤認する。

## Code Evidence

- Primary source: `crates/codefire-cli/src/http.rs:333`
- Observed implementation fact: timeout value is read from environment and parsed with fallback behavior.
- Related source: `crates/codefire-cli/src/http.rs:120`
- Observed implementation fact: HTTP client uses timeout configuration for network operations.

## Recommended Fix

不正なtimeout envはusage/config diagnosticとして扱う。config sourceとeffective timeoutのdebug/metrics露出は別改善として扱う。

## Fix

`CODEFIRE_HTTP_TIMEOUT_MS` parsing now rejects invalid or nonpositive values with a usage error naming the environment variable and expected positive integer millisecond format. Valid positive overrides and the unset default path are unchanged.

## Implementation Notes

- Priority: low。
- First step: invalid env var testを追加する。
- Boundary: retry/backoff設計は別issue。
- Related issues: CFR-110.
