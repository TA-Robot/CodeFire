# CFR-101: batch extinguish dry-run planがitem詳細を無制限に含む

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | performance |
| Area | Batch operation plan |
| Source | `crates/codefire-cli/src/batch.rs:223` |

## Problem

batch extinguishのoperation planは各itemのvalidation planを詳細に含む。大量fireのbatchで `--dry-run --json` を実行すると、stdout JSONが非常に大きくなり、dogfoodingで初回import/大量変更時のJSON肥大化と同種の問題を起こす。

## Why It Matters

AI toolはまずdry-runで安全性を確認する。dry-runが巨大JSONを返すと、メモリ、ログ、コンテキスト消費が増え、実用的なbatch automationが難しくなる。

## Failure Mode / Review Hypothesis

数百から数千fireのbatch planで、全itemのrationale/evidence/planがstdoutへ展開される。toolは必要なsummaryだけでなく全詳細を読み込むことになり、次action判断が遅くなる。

## Code Evidence

- Primary source: `crates/codefire-cli/src/batch.rs:223`
- Observed implementation fact: `batch_extinguish_operation_plan` builds plan with item-level details.
- Related source: `crates/codefire-cli/src/automation.rs:384`
- Observed implementation fact: next_actions capはあるがplan payload capは別途必要。

## Recommended Fix

batch planにsummary defaultと `--details` / `--limit` を導入する。default JSONはcounts、first N diagnostics、plan digest、input pathを返し、全item detailは明示flagまたはoutput fileへ逃がす。

## Implementation Notes

- Priority: medium。
- First step: 100件batch fixtureでdry-run JSON sizeを固定するtestを追加する。
- Boundary: validation自体は全件行う。出力だけをboundedにする。
- Related issues: CFB-050, CFR-100.

## Acceptance Criteria

- default batch dry-run JSONに最大detail件数がある。
- omitted countとdetail取得方法がdataに出る。
- full detailが必要な場合は明示flagで取得できる。

## Test Plan

- large batch dry-runでJSON size/detail count capを検証する。
- invalid itemsがcap内外にある場合のsummary correctnessを確認する。
