## ビルドの基準点（旧環境、`rust:1.85` の Docker イメージで実測）

mainには `rust-toolchain.toml` がなく、devcontainerにもRustが入っていない。

| Gate | 結果 |
|---|---|
| `cargo fmt --check` | pass |
| `cargo build --workspace --locked` | pass |
| `cargo clippy --workspace --all-targets --locked -- -D warnings` | 26 errors（主に `unfulfilled lint expectation`。toolchainの版の違いによるものと推定） |
| `cargo test --workspace --locked` | CLI 772件成功 / 6件失敗（CFB-138）。最初のテストバイナリで止まるため、store・coreは未実行 |

recoveryブランチの記録では、1.98.1でfmt/clippy/buildはpass、CLIの6件失敗とStoreの1件（CFB-139）が残っていた。

## 新環境で最初にやること

1. Rust toolchainを固定する（recoveryブランチの `rust-toolchain.toml` を採用するか決める）。
2. `cargo test --workspace --locked --no-fail-fast` で全crateの基準点を取り直す。
3. CFB-138 / CFB-139 を直して、mainを成功状態にする。
4. 「初回10分」の利用の流れを自動テストにする（`demo.sh` はRust CLIでは動かない。CFB-140参照）。

方針の議論は [recovery-2026-09-05](recovery-2026-09-05.md) と、2026-11-05の診断（CFB-140、本書）を参照。
