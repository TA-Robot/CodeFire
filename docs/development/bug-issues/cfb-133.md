# CFB-133: migrate apply成功後も消化済みplanのreview actionを返す

## Summary

| Field | Value |
|---|---|
| Status | investigating |
| Severity | medium |
| Area | Migration / Automation next actions |
| Observed while | CFR-162 Retrospect後のnext-discovery replay |

## Problem

`migrate apply` はlocked planを全件適用し、`remaining_actions=[]`、`did_write=true`で成功しても、
適用前の`planned_actions`が非空という理由で`review_migration_plan`を返す。automationは完了済みplanを
未完了と解釈し、不要なdry-run loopへ入る。

## Reproduction Evidence

`/tmp/codefire-migrate-action-audit.oSUz5T`で`.codefire/cache`を欠損させ、fresh installed Rust CLIの
dry-run/applyを実行した。`apply.json`は`planned_count=1`、`applied_count=1`、`remaining_count=0`、
`did_write=true`なのに、唯一のnext actionが`review_migration_plan`である。

## Root Cause and Deduplication

`migration_report_next_actions`がcommand modeとpost-apply stateを区別せず、全modeで
`planned_actions`を未完了判定に使う。RVC-034/035のautomation outcome/action rootへ統合し、
migration engineやCFB-130のlocked applyを再実装しない。

## Acceptance Criteria

- successful applyで`remaining_actions`とblockerが空ならreview/apply actionを返さない。
- partial/failed applyは`remaining_actions`から安全なrecovery actionを作り、消化済みplan件数を使わない。
- dry-runは引き続きapply actionを返し、checkは状態に対応したread-only actionだけを返す。
- JSON/textのplanned/applied/remaining audit fieldsは保持する。

## Test Plan

- apply success、exact replay、partial failure、dry-run、blockerのnext-action decision table。
- JSON envelopeとhuman outputのfocused regression。
