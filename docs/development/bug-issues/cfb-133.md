# CFB-133: migrate apply成功後も消化済みplanのreview actionを返す

## Summary

| Field | Value |
|---|---|
| Status | investigating |
| Milestone | M2 (parked) |
| Severity | medium |
| Area | Migration / Automation next actions |
| Observed while | CFR-162 Retrospect後のnext-discovery replay |

## Problem

`migrate apply` はlocked planを全件適用し、`remaining_actions=[]`、`did_write=true`で成功しても、
適用前の`planned_actions`が非空という理由で`review_migration_plan`を返す。automationは完了済みplanを
未完了と解釈し、不要なdry-run loopへ入る。

## Reproduction Evidence

`/tmp/codefire-migrate-action-audit.oSUz5T`で`.codefire/cache`を欠損させ、fresh installed Rust CLIの
dry-run/applyを実行した。`apply.json`は`planned_count=1`、`applied_count=1`、`remaining_count=0`、
`did_write=true`なのに、唯一のnext actionが`review_migration_plan`である。

## Root Cause and Deduplication

`migration_report_next_actions`がcommand modeとpost-apply stateを区別せず、全modeで
`planned_actions`を未完了判定に使う。RVC-034/035のautomation outcome/action rootへ統合し、
migration engineやCFB-130のlocked applyを再実装しない。

## Acceptance Criteria

- successful applyで`remaining_actions`とblockerが空ならreview/apply actionを返さない。
- partial/failed applyは`remaining_actions`から安全なrecovery actionを作り、消化済みplan件数を使わない。
- dry-runは引き続きapply actionを返し、checkは状態に対応したread-only actionだけを返す。
- JSON/textのplanned/applied/remaining audit fieldsは保持する。

## Test Plan

- apply success、exact replay、partial failure、dry-run、blockerのnext-action decision table。
- JSON envelopeとhuman outputのfocused regression。

## Implementation Progress

- `migration_report_next_actions` now branches on the command mode and the current postcondition.
  Successful apply and exact replay return no action when `remaining_actions` is empty, even while
  historical `planned_actions` and `applied_actions` remain in the report.
- Check and dry-run retain their review/apply projections. Failed apply derives a bounded,
  idempotent revalidation retry from `remaining_actions`, with applied/remaining/blocker counts in
  the action target; it never uses the consumed planned count as pending work.
- Focused migration apply tests (16), the existing migration automation regression, workspace check,
  warning-denying Clippy, source-doc check, formatting, and diff checks pass in the isolated worktree.
- The immutable current-state snapshot was release-built and freshly installed under
  `/tmp/codefire-current-state-install.qBPoNe`. An isolated repository whose `.codefire/cache`
  directory was removed then passed the installed `check -> dry-run -> apply -> exact replay`
  decision table: check returned only `review_migration_plan`, dry-run returned only
  `apply_migration_plan`, successful apply returned zero next actions with
  `applied_count=1`, `remaining_count=0`, and `did_write=true`, and replay returned zero next
  actions with no write. The captured apply JSON has SHA-256
  `320edb4bd1e0c3999ac5137381a46a3cddfdfd8f4be70028e5171a9329dc798c`.
- Independent review, the final integration checkpoint, Retrospect, and the issue status transition
  remain.
