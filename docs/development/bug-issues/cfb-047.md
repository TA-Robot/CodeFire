# CFB-047: Open help is not routed through subcommand help

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | CLI help / open |
| Observed while | checking how to reattach `algorithm-evolution-agent-lab` to CodeFire |

## Observation

`codefire open --help` returns `unsupported open option: --help` instead of command usage.

## Reproduction

```bash
codefire open --help
```

## Why It Matters

`open` is the command users need when recovering or importing working directories. If help fails, users must inspect source or docs to understand path and dry-run behavior.

## Workaround

Read top-level help and source docs, or inspect `docs/04_cli_spec.md`.

## Candidate Fix

Extend the central subcommand help handling to `init`, `open`, `clone`, `merge`, `upload`, remote request commands, `context`, `migrate`, and other non-local workflow commands.

## Acceptance Criteria

- `codefire open --help` prints open usage.
- Help handling is side-effect free for every command.
- Completion/help docs tests cover all advertised top-level commands.

## Evidence

- Observed `error: unsupported open option: --help` during algorithm dogfood setup.
- `codefire link --help` returned `error: unsupported link option: --help`.
- `codefire migrate --help` returned `error: unsupported migrate command: --help`.
- `codefire clone --help` returned `error: unsupported clone option: --help`.
- `codefire request-merge --help` returned `error: unsupported option: --help`.
- Fixed in v0.9 Phase A for `open`, `clone`, `upload`, `request-merge`, `request-list`, `request-review`, `request-apply`, `review-pack`, `patch export`, `branch list`, and `evidence add` by routing help before command-specific parsing.
- Regression test: `cargo test -p codefire-cli --bin codefire-rs command_help_routes_before_mutating_parsers -- --nocapture`.
