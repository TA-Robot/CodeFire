# CFB-061: Storage report silently ignores an unreadable remote target

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | diagnostics |
| Area | storage / remote |
| Observed while | checking missing remote storage diagnostics |

## Observation

`codefire storage . --remote cf:///tmp/no/such/remote --json` returned `ok:true`, `remote:null`, no diagnostics, and no warnings.

## Reproduction

```bash
codefire storage . --remote cf:///tmp/no/such/remote --json
```

## Why It Matters

Remote storage checks are audit commands. A missing or unreadable remote target must not look like a successful report with no remote data.

## Workaround

Validate the remote URL with a separate remote command before trusting storage output.

## Candidate Fix

When a remote is requested and cannot be read, return a warning or failure diagnostic with the target URL and reason.

## Acceptance Criteria

- Requested remote targets appear in output whether successful or failed.
- Missing remote path creates a diagnostic.
- Automation can distinguish "no remote requested" from "remote requested but unreadable".

## Evidence

- Output had `ok:true`, `diagnostics: []`, `data.remote: null`, and `warnings: []`.
