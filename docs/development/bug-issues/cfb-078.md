# CFB-078: manual fire resolution can leave no-source-change branch in commit-ready state

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | ux |
| Area | Manual Fire / State Recovery |
| Observed while | cleaning up a manual fire probe |

## Observation

After creating a manual fire in an otherwise clean open directory and extinguishing it as obsolete, `status --json` reported `state: open-consistent` and suggested `codefire commit -m <message>`, even though there were no source changes.

Running `scan --path . --json` returned the branch to `open-clean`.

## Reproduction

```bash
cd subprojects/algorithm-evolution-agent-lab
codefire fire REQ-AUTO-033 --to DES-AUTO-015 --reason "manual fire apply probe" --path . --json
codefire extinguish FIRE-001 --path . --resolution obsolete --rationale "probe cleanup" --json
codefire status --path . --json
codefire scan --path . --json
codefire status --path . --json
```

## Why It Matters

Manual fire probes and accidental manual fires should have a clear recovery path. Suggesting a commit for a no-source-change cleanup can create unnecessary sealed commits or confuse automation.

## Workaround

Run `scan --path . --json` after extinguishing a manual fire with no source changes.

## Candidate Fix

When all open fires are resolved and current source matches base, update state to `open-clean` or provide an explicit discard/reset active manual fire workflow.

## Acceptance Criteria

- no-source-change manual fire cleanup returns to `open-clean`.
- status next_actions do not suggest commit when changed atom count is zero and no open fires remain.
- tests cover manual fire apply -> extinguish -> status.

## Evidence

- Observed during cycle 2 dogfooding; scan reset the state without source changes.
