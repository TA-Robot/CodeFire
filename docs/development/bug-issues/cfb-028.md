# CFB-028: Blocking-only verify JSON still includes non-blocking missing links

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | automation-json |
| Area | `verify --blocking-only --json` |
| Observed while | trace completeness relaxed in `algorithm-evolution-agent-lab` |

## Observation

`verify --details --blocking-only --json` filters `diagnostics`, but `data.missing_required_links` still contains non-blocking warnings.

## Reproduction

```bash
codefire verify . --details --blocking-only --json
```

## Why It Matters

`diagnostics` and `data` disagree about filtering, so automation may treat warnings as blockers.

## Workaround

Trust `diagnostics[].blocking` and ignore `data.missing_required_links` for blocker decisions.

## Candidate Fix

Split fields into `blocking_missing_required_links` and `all_missing_required_links`, or apply the filter to `data` too.

## Acceptance Criteria

- `blocking_only` JSON has an unambiguous blocker-only list.
- Full warning data remains available under an explicitly named field.

## Evidence

- Blocking-only verify returned `diagnostics_count=1` and `missing_required_links` count 24.
