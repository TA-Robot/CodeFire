# CFB-036: Storage command is advertised but not usable

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | `storage` |
| Observed while | checking `.codefire` size in algorithm repo |

## Observation

Top-level help lists `storage`, but `storage --json`, `storage . --json`, and `storage --help` are unsupported.

## Reproduction

```bash
codefire storage --json
codefire storage . --json
codefire storage --help
```

## Why It Matters

Dogfooding large experiment repositories needs storage reporting, but the advertised command cannot be discovered or automated.

## Workaround

Use `du -sh .codefire` and `find .codefire/objects`.

## Candidate Fix

Implement `codefire storage [path] [--json]` or remove it from help until ready.

## Fix

v0.8 routes `codefire storage`, `codefire storage [path]`, `codefire storage --json`, and `codefire storage report ...` through the same storage report runner. Subcommand help now documents both aliases.

## Acceptance Criteria

- `storage --help` prints usage.
- `storage --json` returns object counts and size summary in a command_result envelope.

## Evidence

- CLI returned `unsupported storage command: --json`.
- Regression coverage: storage report tests and command-source trace update.
- Verification: `cargo test -p codefire-cli --bin codefire-rs -- --nocapture`.
