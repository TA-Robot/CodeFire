# CFB-089: atom-index and missing-links reject --path/--json as filesystem paths

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | ux |
| Area | Debug Commands / JSON Contract |
| Observed while | clean-state probe before FrontierFeedbackIntegrator work |

## Observation

`atom-index` and `missing-links` do not parse `--path` or `--json`. They treat `--path` as a positional filesystem path and fail with a plain OS error.

Observed:

```text
codefire atom-index --path . --json
error: No such file or directory (os error 2)

codefire missing-links --path . --json
error: No such file or directory (os error 2)
```

## Reproduction

```bash
cd subprojects/algorithm-evolution-agent-lab
codefire atom-index --path . --json
codefire missing-links --path . --json
```

## Why It Matters

These commands expose core trace/debug data that AI tools naturally use after `scan` or `context`. Treating flags as paths creates confusing OS errors and bypasses the normal command result envelope.

## Workaround

Use positional path form where possible and do not pass `--json`, or prefer `context --changed --json`.

## Candidate Fix

Formalize `atom-index` and `missing-links` as normal read-only commands with shared path parsing, `--json` support, help coverage, and `codefire.command_result.v1` envelopes.

## Acceptance Criteria

- `atom-index --path <open-dir> --json` returns command result JSON.
- `missing-links --path <open-dir> --json` returns command result JSON.
- Unsupported flags never become filesystem paths.
- Tests cover debug command path/json parsing.
