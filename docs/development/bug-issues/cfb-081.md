# CFB-081: explain verify-failure treats non-blocking warnings as blockers on passed verification

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | automation-json |
| Area | Explain / Verification |
| Observed while | probing clean algorithm project state during CodeFire improvement cycle 2 |

## Observation

`codefire explain verify-failure --json` returned `ok:true` for a verification whose `result` was `passed`, but the summary said `verification result is passed with 8 blocker(s)`. The listed diagnostics were all `blocking:false` missing required link warnings because trace completeness is not required in this repository.

## Reproduction

```bash
codefire explain verify-failure --path /workspace/project/subprojects/algorithm-evolution-agent-lab --json
```

Observed shape:

```json
{
  "data": {
    "summary": "verification result is passed with 8 blocker(s)",
    "verification": {
      "result": "passed",
      "trace_completeness_required": false,
      "missing_required_links": []
    }
  },
  "diagnostics": [
    {"kind": "missing_required_link", "blocking": false, "severity": "warning"}
  ],
  "ok": true
}
```

## Why It Matters

An AI tool runner can treat the word `blocker(s)` as a commit-stopping condition even though the command result and diagnostics say the repository is passed. This undermines `--blocking-only` workflows and makes `explain verify-failure` unsafe as a machine-readable recovery hint.

## Workaround

Ignore the natural-language summary and use `data.verification.result` plus `diagnostics[].blocking`.

## Candidate Fix

Make `explain verify-failure` distinguish actual blocking diagnostics from non-blocking warnings. If verification passed, return a passed-state summary such as `verification passed with 8 warning(s)` and avoid the `verify-failure` framing unless a failure exists.

## Acceptance Criteria

- passed verification never reports non-blocking warnings as blockers.
- summary, diagnostics, and `data.verification.result` agree.
- tests cover `trace_completeness_required=false` with missing required links.

## Evidence

- Observed on 2026-06-07 in `/workspace/project/subprojects/algorithm-evolution-agent-lab`.
- Command: `codefire explain verify-failure --path /workspace/project/subprojects/algorithm-evolution-agent-lab --json`.

## Fix

- Fixed in the global burn-down pass.
- `explain verify-failure` now counts blockers from verification diagnostics with `blocking:true`.
- Passed verification with non-blocking warnings is summarized as passed with warnings and 0 blockers.
- The JSON includes `data.diagnostic_summary.blocking_count` and `warning_count`.
