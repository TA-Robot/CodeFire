# CFB-057: `show --json` returns human text with exit 0

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | automation-json |
| Area | show |
| Observed while | checking sealed commit state during `ExperimentRiskRegister` dogfooding |

## Observation

`codefire show main --json` exits 0 but prints human text instead of JSON.

## Reproduction

```bash
codefire show main --json
```

## Why It Matters

An automation tool treats exit 0 plus `--json` as parseable JSON. This command violates that contract and fails at the parser rather than at CodeFire's diagnostic layer.

## Workaround

Fixed. Use `codefire show <target> --json`.

## Candidate Fix

Implemented. `show --json` returns `codefire.command_result.v1` with the show payload under `data`.

## Fix

- `show --json` now emits parseable JSON with top-level `ok`, `exit_code`, `repo`, `diagnostics`, and `next_actions`.
- The payload includes `data.type: codefire_show_result` and `data.show`.
- JSON-mode show failures are wrapped as command_result error envelopes.

## Acceptance Criteria

- `show --json` always emits valid JSON.
- `ok`, `exit_code`, `repo`, `diagnostics`, and `next_actions` are present.
- A regression test parses `show main --json`.

## Evidence

- `codefire show main --json` returned `Object: main@CF-COMMIT-...` text and `python3 -m json.tool` failed.
- Fixed on 2026-06-10 in the global burn-down pass.
- Regression coverage: `show_and_diff_local_branches`, `parse_diff_args_accepts_algorithm_forms`.
