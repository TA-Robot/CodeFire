# CFB-018: Fire volume amplifies repeated evidence entry

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Fire Volume / Extinguish Batch |
| Observed while | Adding new requirements that created many trace-change fires |

## Observation

Adding a requirement often creates multiple REQ/DES/CODE/TEST fire edges that all need the same review evidence.

## Impact

The logical review was one change set, but the operational workflow required repeating the same evidence across many edge-level fires.

## Fix

The combination of `--batch-template` and `--all-matching` provides a practical change-set workflow without changing the underlying fire ledger model:

- `--batch-template` creates one batch file with shared defaults for all current open fires.
- `--all-matching` resolves all fires for the same source/target pair with one command.
- Batch execution still validates every item before writing ledgers.

## Evidence

- `cargo test -p codefire-cli --bin codefire-rs extinguish_batch_template -- --nocapture`
- Existing all-matching extinguish tests continue to pass.
