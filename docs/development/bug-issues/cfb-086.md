# CFB-086: extinguish result marks evidence-ref resolutions as has_evidence false

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | ux |
| Area | Extinguish / Evidence JSON |
| Observed while | algorithm cycle 3 ResearchFrontierMap fire resolution |

## Observation

`codefire extinguish <fire> --evidence-ref <id> --json` returns a resolution block with a non-empty `evidence_refs` array, but `has_evidence` is `false`.

Observed excerpt:

```json
{
  "resolution": {
    "evidence_refs": ["CF-EVIDENCE-3ccde813e3f05983edd0afdc"],
    "has_evidence": false,
    "has_rationale": true,
    "resolution_type": "implemented"
  }
}
```

## Reproduction

```bash
cd subprojects/algorithm-evolution-agent-lab
codefire evidence add --path . --from-command "PYTHONPATH=src python3 -m unittest discover -s tests -v" --cwd "$PWD" --json
codefire scan --path . --json
codefire extinguish FIRE-F3DFF3E8F7AF --path . --resolution implemented --rationale "implemented and tested" --evidence-ref CF-EVIDENCE-3ccde813e3f05983edd0afdc --json
```

## Why It Matters

Automation can read `has_evidence:false` and treat an evidence-backed resolution as weak or incomplete even though `evidence_refs` is populated. This weakens claim/audit workflows that depend on CodeFire evidence references.

## Workaround

Trust `resolution.evidence_refs.length > 0` instead of `has_evidence`.

## Candidate Fix

Define `has_evidence` as true when either inline evidence text or evidence references are present, or split the booleans into `has_inline_evidence` and `has_evidence_refs`.

## Acceptance Criteria

- `--evidence-ref` resolution JSON reports evidence presence consistently.
- Tests cover inline evidence, evidence refs, and no-evidence cases.
- Text output and JSON output use the same evidence presence definition.
