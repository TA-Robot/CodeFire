# CFB-111: clone next_action lacks safe open path guidance

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | UX bug |
| Area | Branch clone / Next action path guidance |
| Observed while | algorithm branch boundary dogfood |

## Observation

`codefire clone <source> <new-branch> --dry-run --json` returns an `open` next action with a literal `<path>` placeholder and no repo-root or suggested safe target path.

## Reproduction

```bash
codefire clone main feature/probe-nested-open --dry-run --json
```

The result includes:

```text
codefire open feature/probe-nested-open <path>
```

The next action target only identifies the branch.

## Why It Matters

Branch-per-feature operation expects agents to clone and then open a new worktree. Without a concrete safe path or repo context, an agent has to invent the target path and can pick a repo-root-external path or a nested path inside the current open directory.

## Workaround

After clone, manually choose a sibling directory under the CodeFire repo root instead of following the placeholder command literally.

## Candidate Fix

Have clone plans return a safe default open target, for example `<repo>/<sanitized-branch-name>` or a configurable workspace-open-dir pattern. Include repo, source head, target branch, and path boundary policy in the next action context.

## Acceptance Criteria

- Clone success and dry-run next actions include a concrete suggested open path.
- The command string is directly executable or explicitly marked as a template.
- The next action target includes repo root, branch, and source head.
- Tests cover JSON next action shape for clone.
