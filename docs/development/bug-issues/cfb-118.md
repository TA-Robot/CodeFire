# CFB-118: merge dry-run suggests apply despite semantic conflict candidates

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | bug |
| Area | Merge / Semantic conflict next actions |
| Observed while | CodeFire merge next_actions implementation review after branch-per-feature dogfood |

## Observation

`merge_next_actions` adds an `apply_merge` next action whenever the merge is a dry-run and file conflicts are empty:

```rust
if result.dry_run && result.conflicts.is_empty() {
    actions.push(json!({
        "kind": "apply_merge",
        ...
    }));
}
```

The condition does not check `result.semantic_conflicts`. Semantic conflict candidates are appended later as separate `review_semantic_conflict` actions, so a dry-run can return both:

- `apply_merge`
- `review_semantic_conflict`

This makes `apply_merge` look immediately executable even though semantic review is still required.

## Reproduction

Code path review:

```bash
nl -ba crates/codefire-cli/src/main.rs | sed -n '4788,4865p'
```

Create a merge where source and target modify the same Atom from the same base without a file-level conflict. The dry-run JSON can include an `apply_merge` action before or alongside `review_semantic_conflict`.

## Why It Matters

CodeFire next actions are intended to be automation-friendly. If an agent follows the first actionable command, it can apply a merge before reviewing concurrent semantic changes to the same Atom. That weakens the branch-per-feature workflow because semantic conflicts are the main CodeFire-specific merge signal.

## Workaround

Before applying a merge dry-run, manually inspect:

- `semantic_conflicts` in the dry-run result;
- `semantic_conflict_candidates` after any applied merge;
- `review_semantic_conflict` next actions.

Do not run `apply_merge` until the semantic conflict list is empty or explicitly accepted.

## Candidate Fix

Only emit `apply_merge` when both file conflicts and semantic conflicts are empty:

```rust
if result.dry_run && result.conflicts.is_empty() && result.semantic_conflicts.is_empty() {
    ...
}
```

When semantic conflicts are present, put `review_semantic_conflict` actions first and include a clear blocking reason.

## Acceptance Criteria

- Merge dry-run with semantic conflict candidates does not emit `apply_merge`.
- Merge dry-run with no file conflicts and no semantic conflicts still emits `apply_merge`.
- JSON output explains that semantic review is required before applying.
- Tests cover dry-run next actions for semantic-only conflicts.

## Evidence

- `crates/codefire-cli/src/main.rs::merge_next_actions` gates `apply_merge` on `result.conflicts.is_empty()` but not on `result.semantic_conflicts.is_empty()`.
- The same function appends `review_semantic_conflict` actions after the apply action block.
