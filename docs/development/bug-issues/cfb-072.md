# CFB-072: evidence dry-run plan does not resolve command cwd

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | automation-contract |
| Area | Evidence / Dry Run CWD |
| Observed while | preparing test evidence for `ClaimAuditTrailBuilder` |

## Observation

`codefire evidence add --path . --from-command "true" --dry-run --json` returns a plan with `cwd: null`. The plan confirms command capture would run, but it does not state the resolved working directory or whether cwd comes from `--cwd`, `--path`, or the caller process.

## Reproduction

```bash
cd subprojects/algorithm-evolution-agent-lab
codefire evidence add --path . --from-command "true" --label "dry-run probe" --dry-run --json
```

Observed:

```json
{
  "data": {
    "dry_run": true,
    "plan": {
      "from_command": "true",
      "cwd": null,
      "operations": [{"kind": "run_command_capture", "enabled": true}]
    }
  }
}
```

## Why It Matters

Evidence capture is often used to prove tests ran in the intended repository. A dry-run that omits resolved cwd cannot prove the eventual evidence command will execute in the open directory.

## Workaround

Pass `--cwd <open-dir>` explicitly and inspect the applied evidence result.

## Candidate Fix

Resolve cwd in dry-run mode using the same precedence as apply mode. Include `resolved_cwd` and `cwd_source` in the plan and applied result.

## Acceptance Criteria

- evidence dry-run includes resolved cwd.
- applied evidence result includes resolved cwd.
- cwd source is one of `explicit_cwd`, `path_open_dir`, `caller_cwd`, or equivalent stable values.
- Tests cover `--path` with no `--cwd`.
