# CFB-100: merge dry-run next_actions are not executable command_result actions

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | automation-json |
| Area | Merge / Operation plan JSON |
| Observed while | branch-per-feature dogfood in `algorithm-evolution-agent-lab` |

## Observation

`codefire merge feature/nameaudit-summary-line --into main --dry-run --json` returned a valid merge plan, but the command_result envelope had `repo:null` and a top-level next_action with an empty command:

```json
{
  "repo": null,
  "next_actions": [
    {
      "kind": "apply_merge",
      "command": "",
      "hint": "run codefire merge feature/nameaudit-summary-line --into main"
    }
  ]
}
```

The executable apply command only appears as prose in `hint`.

## Reproduction

```bash
cd /workspace/project/subprojects/algorithm-evolution-agent-lab
codefire merge feature/nameaudit-summary-line --into main --dry-run --json
```

## Why It Matters

Dry-run plans are the safe path for automation before mutating a target branch. If the top-level next_action command is empty and repo is null, generic command_result consumers cannot proceed without special-casing merge plan internals.

## Workaround

Fixed in branch workflow burn-down. Older binaries require reading `data.plan.next_actions[0].hint` manually and running the command it describes.

## Candidate Fix

Normalize merge operation-plan next_actions into the shared schema:

- top-level `repo` should be the CodeFire repository root.
- `next_actions[].command` should be `codefire merge <source> --into <target>` with path context when available.
- `target` / `context` should include source branch, target branch, source commit, target commit, and target open dir.

## Acceptance Criteria

- Merge dry-run JSON returns non-null `repo`.
- Top-level next_actions contain executable commands, not empty strings.
- Plan-local next_actions use the same shape or are converted before envelope rendering.

## Evidence

- Observed on 2026-06-12 while dry-running merge from `feature/nameaudit-summary-line` into `main`.
- Fixed by carrying `repo` in merge plans and rendering `apply_merge` with executable command/reason/target fields.
- Regression: `crates/codefire-cli/src/tests.rs::merge_branch_writes_source_changes_and_marks_target_burning`.
