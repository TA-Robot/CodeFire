# CFB-093: status next_actions miss commit-ready state after verified fire resolution

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Status / Next actions |
| Observed while | `algorithm-evolution-agent-lab` cycle 4 dogfooding for `ResearchCyclePlanSynthesizer` |

## Observation

After adding `REQ-AUTO-040`, `DES-AUTO-022`, `CODE-ResearchCyclePlanSynthesizer`, and `TEST-research-cycle-plan-synthesizer-builds-next-cycle-lanes`, CodeFire correctly produced six trace fires. Those fires were extinguished, and `codefire verify --details --blocking-only --json --metrics --path subprojects/algorithm-evolution-agent-lab` passed with `open_required_fires:0`.

Immediately before the CodeFire commit, `status --json` had enough `scan_prediction` information to know that the branch had pending changes and zero open fires, but the next actions still pointed at `scan` and `verify` instead of the actionable `commit`.

## Reproduction

```bash
codefire scan --path subprojects/algorithm-evolution-agent-lab --json --metrics
codefire extinguish FIRE-... --resolution addressed --rationale "..." --path subprojects/algorithm-evolution-agent-lab --json
codefire verify --details --blocking-only --json --metrics --path subprojects/algorithm-evolution-agent-lab
codefire status --path subprojects/algorithm-evolution-agent-lab --json
```

Observed pre-fix status context:

- `state:"open-burning"`
- `scan_prediction.changed_count > 0`
- `scan_prediction.open_fire_count == 0`
- `next_actions` recommended `scan` and `verify`, not `commit`

## Why It Matters

For CodeFire as an automation tool, `next_actions` should be the fastest safe path. After verification has passed and the read-only prediction says there are pending changes but no fires, the next action is to seal the branch. Recommending another scan/verify loop wastes tool calls and makes AI automation think the branch still has blocking diagnostics.

## Workaround

Read `verify` output directly and run `codefire commit -m ... --path ...` manually when `open_required_fires` is zero.

## Candidate Fix

Use the JSON `scan_prediction` already computed by `status_data_json_with_prediction` when generating status JSON next actions. If the stored state is `open-burning`, predicted changed count is positive, and predicted open fire count is zero, return a `commit` next action instead of the generic scan/verify loop.

## Acceptance Criteria

- `status --json` recommends `commit` when scan prediction reports pending changes and zero open fires.
- Existing clean status still returns no next actions.
- Existing burning status with open fires still recommends scan/verify/context.
- A unit test covers the prediction-driven commit recommendation.

## Evidence

- Regression test: `automation::tests::burning_status_with_clean_prediction_suggests_commit`.
- Dogfood context: `algorithm-evolution-agent-lab` CodeFire commit `CF-COMMIT-711547728f2ad3345d7bcc82`.

## Fix

Implemented in cycle 4 burn-down.

- Added `status_next_actions_with_prediction`.
- `status --json` now passes the prediction-enriched data into next-action generation.
- The commit recommendation includes branch, base, `pending_changes:true`, and `open_fires:0`.
