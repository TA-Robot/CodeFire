# CFB-007: CodeFire needs built-in performance observability

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | performance |
| Area | Performance / Observability |
| Observed while | Measuring `status`, `scan`, and `verify --details` manually in `algorithm-evolution-agent-lab` |

## Observation

Early dogfooding used manual timings for status, scan, and verify. There was no stable command surface for phase timing and counters.

## Impact

As repositories grew, operators would not be able to identify whether extraction, trace graph construction, verification, or rendering caused slowdowns.

## Fix

Metrics-capable commands expose structured metrics, and `codefire capabilities --json` reports which commands support metrics.

## Evidence

- Metrics support in status, scan, verify, and branch list.
- `bug-backlog.md` CFB-007 row.
