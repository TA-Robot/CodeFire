# CFB-049: Evidence command default cwd changes when `--path` is supplied

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | bug |
| Area | evidence add / command capture |
| Observed while | recording initial-import test evidence for `algorithm-evolution-agent-lab` |

## Observation

From the algorithm open directory, `codefire evidence add --path . --from-command "PYTHONPATH=src python3 -m unittest discover -s tests -v" --json` ran the command from a directory where `tests` was not importable. The same command succeeds when `--cwd /workspace/project/subprojects/algorithm-evolution-agent-lab` is supplied.

## Reproduction

```bash
cd subprojects/algorithm-evolution-agent-lab
codefire evidence add --path . --from-command "PYTHONPATH=src python3 -m unittest discover -s tests -v" --json
```

## Why It Matters

AI agents will expect a command issued from an open directory to run there unless `--cwd` says otherwise. A hidden cwd shift creates failed evidence, and because failed command evidence is currently `ok:true`, the mistake can be missed.

## Workaround

Always pass `--cwd <open-dir>` for evidence command capture.

## Candidate Fix

Define and document command capture cwd precedence. A reasonable default is: explicit `--cwd`, else the invocation cwd, else open directory. Include resolved cwd in evidence result JSON.

## Acceptance Criteria

- Evidence command capture default cwd is stable and documented.
- Result JSON includes `command_cwd`.
- Parser/runner tests cover `--path` plus default cwd behavior.

## Evidence

- Failed evidence object: `CF-EVIDENCE-e666bc3745cfdd335bdb8142`.
- Passing evidence with explicit cwd: `CF-EVIDENCE-a0c5c25f5a1be67a69d56c76`.

## Fix

Command capture cwd resolution is now explicit and machine-readable:

- explicit `--cwd` resolves to canonical cwd and reports `command_cwd_source: explicit_cwd`.
- no `--cwd` resolves to the caller process cwd and reports `command_cwd_source: caller_cwd`.
- paths under the CodeFire repo are also reported as `repo_relative_command_cwd`.

The same resolved cwd is used for dry-run planning and applied command capture.
