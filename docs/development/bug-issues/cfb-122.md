# CFB-122: open-target containment is lexical and can miss symlink or dot-dot escapes

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | bug |
| Area | Path safety / Open target |
| Observed while | 2026-07-11 source/security boundary audit before new product development |

## Original Observation

Before this fix, Rust `absolute_path` joined a relative path to the current directory without normalization, and the open-target guard relied on lexical `starts_with` relationships. A path that began under the allowed workspace but traversed `..`, or an allowed-looking existing ancestor that was a symlink to an outside directory, was not resolved and rechecked at the use boundary.

## Original Reproduction

The original disposable-workspace counterexamples used an allowed directory containing a symlink to
an outside target and an allowed-prefix path containing `..`. They are now automated together with
validation/use ancestor swaps; no mutating reproduction should be run against user work.

## Why It Matters

Open materializes a full branch tree. A lexical containment decision can write outside the configured workspace, cross another open directory, or make cleanup/authority ambiguous for humans and agents.

## Historical Workaround

Before the fix, users needed normalized sibling paths with no symlink component or `..` and had to inspect the real path of every existing ancestor before apply. Open dry-runs remain read-only.

## Chosen Fix

Introduce one canonical path-boundary resolver that canonicalizes the deepest existing ancestor, rejects symlink components according to policy, appends only validated non-existing suffixes, and rechecks the resolved target against repository/workspace and existing-open boundaries immediately before use.

## Implemented Fix

Open now resolves its target through `PinnedTargetResolution` below the canonical workspace
boundary. Resolution rejects `..`, symlink components, non-directory ancestors, repository overlap,
existing-open overlap, and component-prefix escapes. It retains no-follow directory capabilities and
stable identities for every existing ancestor rather than reducing the decision to a lexical path.

The open transaction records the resolution identity chain and the staging-parent identity.
`StagedWorktree` creates and materializes through descriptor-relative, no-follow operations, then
publishes the complete staged tree atomically. Recovery rebinds the recorded identities; ancestor,
created-parent, target-name, nested-symlink, or post-fingerprint replacement fails closed before
repository metadata is advanced. Structured `open_target_resolution_failed` diagnostics retain the
requested path, safe resolved/boundary evidence, reason, and a dry-run next action.

## Acceptance Criteria

- `..`, symlink-to-outside, symlink-into-another-open, and prefix-collision paths are rejected in dry-run and apply.
- A normal non-existing sibling target remains supported.
- Validation and use share the same resolved subject or detect a race and fail closed.
- JSON diagnostics include the requested path, resolved boundary evidence where safe, and a non-destructive next action.

## Evidence

- `crates/codefire-cli/src/main.rs::resolve_open_target` applies workspace, repository, and
  existing-open containment to a `secure_worktree::PinnedTargetResolution`.
- `crates/codefire-cli/src/secure_worktree.rs::PinnedTargetResolution` walks components no-follow,
  pins existing ancestors, and rechecks their identities; `StagedWorktree` owns staged materialization
  and atomic target publication.
- `crates/codefire-cli/src/open_transaction.rs` persists and rebinds the resolution/staging-parent
  identities across retry and retains the published target capability through content verification
  and metadata publication.
