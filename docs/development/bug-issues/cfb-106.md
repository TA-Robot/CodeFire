# CFB-106: merge allows self-merge and returns an apply next_action

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | bug |
| Area | Merge / Self merge guard |
| Observed while | algorithm branch lifecycle dry-run probe |

## Observation

`codefire merge main --into main --dry-run --json` succeeds even though the source and target branch are identical. The plan has no file actions but still returns an `apply_merge` next action.

## Reproduction

```bash
cd /workspace/project/subprojects/algorithm-evolution-agent-lab
codefire merge main --into main --dry-run --json
```

Observed result:

- `ok:true`
- `file_actions: []`
- source branch `main`
- target branch `main`
- next action: `codefire merge main --into main`

## Why It Matters

A self-merge is not meaningful branch workflow work. Returning an apply action makes automation treat a no-op as a valid merge operation, which can create confusing logs, idempotency records, or future state transitions.

## Workaround

Do not merge a branch into itself. Check source and target branch names before invoking `merge`.

## Candidate Fix

Reject local merge when source branch equals target branch. Also reject when source commit equals target commit unless an explicit no-op inspection mode is requested.

## Acceptance Criteria

- `merge main --into main --dry-run --json` returns `ok:false` with `kind:self_merge` or equivalent.
- No apply next action is returned for self-merge.
- Tests cover branch-name self merge and same-commit no-op merge behavior.

## Evidence

- 2026-06-12 algorithm branch probe showed self-merge dry-run succeeds with empty file actions and an executable apply next action.
