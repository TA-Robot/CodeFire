# CFB-083: branch list --metrics succeeds but drops metrics

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | automation-json |
| Area | Branch / Metrics |
| Observed while | checking branch state from the algorithm project during CodeFire improvement cycle 2 |

## Observation

`codefire branch list --path <open-dir> --json --metrics` exited successfully, but the result contained no `metrics` block and no diagnostic saying that metrics are unsupported for branch list. Help for `branch list` does not advertise `--metrics`, so accepting and dropping it is misleading.

## Reproduction

```bash
codefire branch list --path /workspace/project/subprojects/algorithm-evolution-agent-lab --json --metrics
```

Observed:

```json
{
  "command": "branch-list",
  "data": {
    "branches": []
  },
  "diagnostics": [],
  "exit_code": 0,
  "ok": true
}
```

## Why It Matters

Automation often applies common flags across commands. Silently ignoring `--metrics` makes it impossible to distinguish "metrics were zero/empty" from "metrics are unsupported". This weakens performance monitoring and capability probing.

## Workaround

Do not pass `--metrics` to `branch list`; rely on status/scan/verify metrics instead.

## Candidate Fix

Either implement branch-list metrics or reject `--metrics` with a structured JSON diagnostic when `--json` is present. Help should match the accepted flag set.

## Acceptance Criteria

- `branch list --json --metrics` returns a metrics block, or fails with an envelope diagnostic.
- `branch list --help` documents `--metrics` only if it is supported.
- tests cover unsupported common flags not being silently ignored.
