# CFB-048: Existing non-empty project cannot be imported as an open directory

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | ux |
| Area | init / open / import workflow |
| Observed while | turning `algorithm-evolution-agent-lab` back into a CodeFire-managed dogfood project |

## Observation

CodeFire can initialize an empty repository and open a branch into an empty target, but there is no safe first-class command to adopt an existing non-empty source tree as the initial open directory.

## Reproduction

```bash
cd existing-project
codefire init .
codefire open main .
```

The open path is rejected because the target is non-empty or contains `.codefire`.

## Why It Matters

Dogfooding and migration both start from existing projects. Without an import/adopt workflow, users must manually move directories, initialize a repo elsewhere, open an empty target, copy files back, and then extinguish a large initial fire set.

## Workaround

Create the CodeFire repository in a parent directory, move the existing project aside, `open` into the original path, copy files back, then treat the resulting changes as an initial import.

## Candidate Fix

Add an explicit `codefire import <path> [--branch main]` or `codefire init --adopt <path>` workflow that creates the repo, writes a valid open marker/registry, scans the existing tree, and generates a bounded initial-import plan.

## Acceptance Criteria

- Existing non-empty project can be adopted without manual move/copy.
- Dry-run shows exactly what metadata and initial active state will be created.
- Import plan makes the initial fire volume and required evidence explicit.

## Evidence

- Algorithm dogfood setup required manually moving `algorithm-evolution-agent-lab`, running `codefire init` in `subprojects/`, opening `main`, and copying files back.

## Fix

- Added `codefire import [path] [--branch <name>] [--dry-run] [--json] [--idempotency-key <key>]`.
- The command adopts an existing directory in place, creates `.codefire`, `.codefire-open`, opened registry, and active state, then persists a scan so branch state reflects the imported tree.
- Dry-run returns a `codefire_operation_plan` with `initial_files` and the exact metadata paths that would be created, without writing filesystem state.
- Idempotency replay returns the recorded import result before already-imported target validation.
- CLI help, completion, capabilities, and `docs/04_cli_spec.md` now include the import workflow.

## Close Evidence
