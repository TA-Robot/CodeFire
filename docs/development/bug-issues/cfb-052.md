# CFB-052: Clean verify suggests commit even when there are no changes

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | low |
| Type | ux |
| Area | verify next_actions |
| Observed while | checking clean state after initial algorithm import commit |

## Observation

After the algorithm branch was clean, `codefire verify --details --blocking-only --json --metrics` passed and returned `next_actions` with `codefire commit -m <message>`, even though `scan` reported zero changed atoms and zero open fires.

## Reproduction

```bash
codefire scan --path . --json
codefire verify --path . --details --blocking-only --json
```

## Why It Matters

In a clean open branch, a commit action is misleading. AI tools may attempt no-op commits or treat the branch as pending work.

## Workaround

Check `scan --json` for `changed_atoms.length == 0` before following verify next actions.

## Candidate Fix

Make verify next actions state-aware: suggest commit only when there are pending changes that can be sealed; otherwise suggest no-op/continue or status.

## Acceptance Criteria

- Clean verified branch does not suggest commit.
- Dirty verified branch still suggests commit.
- JSON next action includes machine-readable `pending_changes`.

## Evidence

- After `CF-COMMIT-176865705a2e2a5f63e88d2f`, `scan` reported zero changes while `verify` still suggested commit.
