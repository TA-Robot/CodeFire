# CFB-090: bounded context trace links can reference omitted atoms

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | automation-contract |
| Area | Context / Bounded Graph |
| Observed while | implementing `FrontierFeedbackIntegrator` in `algorithm-evolution-agent-lab` |

## Observation

`codefire context --changed --path . --limit 5 --json` returned five `data.atoms`, but `data.trace_links` included a link to `TEST-frontier-feedback-integrator-updates-frontier-signals`, which was omitted from the returned atom list by the limit.

The output did set `data.truncated.atoms = true`, but it did not mark the trace link endpoint as omitted, did not return omitted endpoint counts, and did not provide a recovery command specific to the missing endpoint.

## Reproduction

```bash
cd subprojects/algorithm-evolution-agent-lab
codefire context --changed --path . --limit 5 --json
```

Observed during the frontier feedback change:

```json
{
  "data": {
    "atoms": [
      {"atom_id": "CODE-FrontierExperimentPlanner"},
      {"atom_id": "CODE-FrontierFeedbackIntegrator"},
      {"atom_id": "DES-AUTO-018"},
      {"atom_id": "REQ-AUTO-036"},
      {"atom_id": "TEST-frontier-experiment-planner-builds-runnable-plans"}
    ],
    "trace_links": [
      {
        "from": "REQ-AUTO-036",
        "to": "TEST-frontier-feedback-integrator-updates-frontier-signals",
        "type": "verified_by"
      }
    ],
    "truncated": {
      "atoms": true
    }
  }
}
```

## Why It Matters

AI tools commonly build a compact local graph from `atoms` and `trace_links`. If a returned link points to an omitted atom without endpoint metadata, the graph looks internally dangling. The tool cannot distinguish corruption, stale links, or ordinary bounded omission without issuing broader follow-up commands.

## Workaround

Treat any `truncated.atoms = true` context pack as incomplete and rerun with a higher `--limit` before constructing a graph.

## Candidate Fix

Bounded context should annotate trace link endpoints with whether each endpoint is included in the returned atom set or omitted by the limit. It should also return omitted endpoint counts and a recovery command such as `codefire context --changed --path <path> --limit <larger> --json`.

## Acceptance Criteria

- Trace links in bounded context identify endpoint availability: returned, omitted, or missing.
- Context JSON reports omitted endpoint counts for bounded graph output.
- `next_actions` includes a recovery command when returned links reference omitted endpoints.
- Tests cover `--limit` where a trace link endpoint is outside the returned atom list.

## Evidence

- Observed on 2026-06-07 while adding `FrontierFeedbackIntegrator`; `context --changed --path . --limit 5 --json` returned a `verified_by` link to an omitted test Atom.

## Fix

Implemented in the active burn-down batch.

- Added `data.summary` counts for atoms, trace links, fires, scan changed atoms, and scan open fires.
- Added `data.trace_link_endpoints` with endpoint `presence` values: `returned`, `omitted`, or `missing`.
- Existing `data.trace_links` shape is preserved for compatibility.
