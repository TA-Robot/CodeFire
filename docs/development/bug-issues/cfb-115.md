# CFB-115: non-Atom edits inside atom-bearing files can be invisible

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | bug |
| Area | Scan / Non-Atom change detection |
| Observed while | CodeFire scan implementation review after algorithm documentation dogfood |

## Observation

`non_atom_changed_files_since_base` excludes every file path that appears in either the current or base Atom index. For Markdown files, Atom content starts at the Atom heading and ends before the next same-or-higher-level Atom heading. Text before the first Atom heading is not part of any Atom hash.

As a result, editing non-Atom prose inside an atom-bearing file can produce:

- no changed Atom, because the edit is outside every Atom span;
- no non-Atom changed file, because the whole file path is excluded by `atom_paths.contains(&path)`.

The same class of risk can apply to explicit `cf-atom` source files when content outside all explicit Atom spans changes.

## Reproduction

Code path review:

```bash
rg -n "fn non_atom_changed_files_since_base|extract_markdown_atoms" crates/codefire-cli/src/main.rs crates/codefire-core/src/lib.rs
```

Scenario:

```markdown
Intro text outside any Atom.

## REQ-AUTH-001: Requirement

Atom body.
```

Changing only `Intro text outside any Atom` does not change the Markdown Atom body. Because the file path is atom-bearing, it is skipped from non-Atom file reporting.

## Why It Matters

CodeFire should seal the whole worktree state, not only Atom spans. Documentation files often contain introductions, indexes, examples, and notes around Atom headings. If those edits disappear from `status`, `scan`, `verify`, and commit summaries, a contributor can believe a branch is clean while meaningful documentation changed.

## Workaround

Keep important prose inside an Atom span or put non-Atom prose in a separate non-Atom file. Manually inspect filesystem diffs for atom-bearing files before assuming a branch is clean.

## Candidate Fix

Track file-level changes independently from Atom-level changes for atom-bearing files:

- compare full-file content manifest for all files;
- report changed atom-bearing files even when no Atom hash changed;
- distinguish `atom_changed_files` from `non_atom_changed_files`, or add `untracked_span_changed_files`;
- include these files in status/scan/commit summaries and close/merge safety checks.

## Acceptance Criteria

- Editing text before the first Markdown Atom heading produces a visible pending change.
- Editing text outside all explicit `cf-atom` spans produces a visible pending change.
- Existing Atom changes still report changed Atom IDs.
- Commit summaries include changed files whose full-file content changed even if no Atom hash changed.
- Tests cover atom-bearing Markdown and explicit-source files with out-of-span edits.

## Evidence

- `crates/codefire-cli/src/main.rs::non_atom_changed_files_since_base` skips any path present in current or base Atom index.
- `crates/codefire-core/src/lib.rs::extract_markdown_atoms` hashes only heading-scoped blocks, not file prose before the first Atom heading.
