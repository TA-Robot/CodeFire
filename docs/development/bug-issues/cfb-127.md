# CFB-127: commit-signature rotation test depended on the wall clock

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | test reliability |
| Area | Commit signatures / Key rotation |
| Observed while | 2026-07-11 organization completion audit with restored Rust source gates |

## Observation

`commit_signature_verifies_key_policy_and_rotation_bounds` signed its fixture with `now_iso_utc()` but constrained the key to a fixed window ending at `2026-07-01T00:00:00Z`. The test therefore changed from passing to `key is expired` as wall-clock time advanced, even though the signature verifier's intended rotation-boundary behavior had not changed.

## Root Cause

The production signing helper owned both signature construction and the current-time choice, so the unit test could not supply a deterministic `signed_at` value inside its fixed key window.

## Fix

Extracted a private `sign_commit_payload_at` constructor. Production signing still passes `now_iso_utc()`, while the rotation test supplies `2026-06-05T00:00:00Z` explicitly. No production signature format or policy behavior changed.

The same restored gate exposed unused line-counter increments in diff hunk rendering and eight eager-null Clippy findings on Rust 1.97. Those were removed or changed to `Value::Null` without changing output.
