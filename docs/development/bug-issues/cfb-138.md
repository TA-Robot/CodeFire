# CFB-138: Bootstrap rollback exceeds its own reserved recovery byte budget

## Summary

| Field | Value |
|---|---|
| Status | investigating |
| Milestone | MS-recovery-baseline |
| Severity | high |
| Type | correctness / recovery |
| Area | Rust remote bootstrap cleanup and decision-work reservations |
| Observed while | REC-02 current-source baseline in the isolated CodeFire recovery worktree |

## Observation

Rust 1.98.1 fmt/clippy/build pass at product base `83b4522`, but six CLI tests fail in bootstrap cancellation,
cleanup and recovery. A simple cancellation returns `InvalidRepository("remote bootstrap recovery byte
limit exceeded (45732)")` instead of completing cleanup. The ledger cancellation variant fails with 47136.
Both reproduce alone, so the six cleanup failures are not explained by suite load.

## Reproduction

```bash
source docs/development/tools/rust_env.sh
cargo test -p codefire-cli --bin codefire-rs http::tests::missing_bootstrap_cleanup_follows_route_intent_owner_cancellation -- --exact
cargo test -p codefire-cli --bin codefire-rs remote::locks::tests::ledger_bootstrap_cancel_consumes_permits_and_releases_current -- --exact
```

## Why It Matters

A cancelled or failed bootstrap may fail its bounded cleanup and force avoidable recovery/quarantine.
An agent cannot treat operation rejection as successful restoration of the prior repository state.
The cause is charging directory filesystem `st_size` as payload even though the reservation covers logical entry/name frames and file payload. Directory allocator sizes vary by filesystem and are not file bytes to clean up.

## Workaround

Do not claim the source gate or bootstrap cleanup contract passes. Preserve recoverable state and logs.
No workaround that bypasses accounting or deletes unowned directories is admitted.

## Candidate Fix

Align the pre-reserved rollback capacity with bounded actual traversal/cleanup work. Preserve the safety
ceiling, ownership, cancellation and error semantics; do not merely inflate constants until tests pass.

## Acceptance Criteria

- Reproduce before fixing and explain the mismatched work dimensions.
- All six cleanup cases pass, with bounded exact/over-budget regression coverage.
- Unowned/replaced paths remain untouched, live owners/permits are released, and true capacity excess still fails.
- Focused tests, fmt, strict Clippy and the admitted integrated workspace suite pass.

## Evidence

REC-02 packet and `target/recovery-rust/test.log`, `focused-results.json`, `focused-{0,1}.log` in the recovery checkout.
The unrelated import concurrent replay test hit a 5s lock timeout in the full suite but passed alone; it is
tracked separately in REC-02 and must not be disguised by this fix.

## Intermediate Fix Review

Grok aligned scan/remove accounting with the reservation: E = fixed layout entries + admitted entries;
B = fixed payload allowance + admitted file payload + E * maximum entry frame. Rollback reserves two passes
(2E/2B), and temporary memory remains a peak allowance. Limits were not increased. Forty-seven bootstrap
cases and two differently named original-failure cases pass on the intermediate patch.

Independent review requires entry/name-frame charging before symlink_metadata, retaining deterministic
budget refusal before another metadata read. Correction and full integrated validation are pending; this
issue is not fixed based only on intermediate focused passes.
