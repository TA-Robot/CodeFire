# CFB-138: Python HTTP uploadが保守的な全record retained予約で既定上限を超える

## Summary

| Field | Value |
|---|---|
| Status | investigating |
| Severity | high |
| Type | resource correctness / availability |
| Area | Python HTTP upload / sealed validation accounting |
| Observed while | CFR-168 upload ancestry recoveryの1201-commit scale fixture |

## Observation

Python fallbackの既存project HTTP uploadへ1201 commitのdivergent historyを渡すと、ancestry判定へ入る前の
`semantic_validation`で`retained_bytes`の上限予約が`130,977,816` bytesとなり、既定
`http_v1`上限`33,554,432` bytesを超えて`ResourceBudgetExceeded`になる。

同じfixtureを上限512 MiBで最後まで走らせたとき、意図した409 non-fast-forward判定へ到達する。既定上限で
拒否された時点のledger peakは`2,274,829` bytesであり、拒否値は同時に保持する実memoryではなく、全recordの
保守的なheap upperをconcurrent retainedとして合算した値である。

## Why It Matters

構造的に有効でwire/object上限内の履歴でも、実際の同時保持量より約57倍大きい予約によって通常uploadが
拒否される。CFR-168は1x/3x/10x fixtureで時間・memory orderと既定profileの実用境界を証明する必要があり、
testだけ上限を上げるとscale gateを迂回するため、この問題はCFR-168 Close blockerである。

## Reproduction

- Target: `cb13da08e82c2502920f735d27617e61f978527a`
- Fixture: root commit + 1200 descendants + bootstrap records
- Profile: unmodified `DecisionWorkProfile.http_v1()`
- Result:
  - type: `ResourceBudgetExceeded`
  - phase: `semantic_validation`
  - dimension: `retained_bytes`
  - observed: `130977816`
  - limit: `33554432`
  - terminal reason: `budget_exceeded`
  - retained current after cleanup: `0`
  - authority snapshot: byte-identical

## Candidate Fix

- sealed validationのdocument/semantic heap upperを全record同時保持として一括取得せず、実際のowner lifetimeに
  合わせてstream/chunkし、current record・frontier・memoとして同時に生存する値だけをconcurrent retainedへ
  計上する。
- 同一request ledger、snapshot revalidation、signature/ancestry diagnostic precedence、deadline polling、
  effect前failure、zero-debt cleanupを維持する。
- 既定limitを単に引き上げる修正や、semantic validationを省略する修正は認めない。

## Acceptance Criteria

- 1201-commit fixtureが既定`http_v1` profileでancestryまで到達し、既存と同じ409 non-fast-forward結果を返す。
- 1x/3x/10x fixtureでconcurrent retained peakとrecord/graph workを記録し、document countを掛けた全量
  concurrent予約ではなく、実owner lifetimeから説明できるboundに収まる。
- retained exact / minus-one / plus-oneが意図したproduction ownerで決まり、budget/deadline/subject-change時は
  branch、object、nonce、transaction、receipt、responseを一切部分公開しない。
- shared DAG、deep iterative traversal、signature policy、diagnostic precedence、replay、zero-debt cleanupを
  維持する。
- Python全体、cross-runtime corpus、fresh Install、installed scale reversal、Dogfood、Retrospectを通すまで
  `fixed`にしない。
