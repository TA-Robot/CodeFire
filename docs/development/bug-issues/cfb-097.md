# CFB-097: extinguish batch dry-run next_actions drop explicit path context

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | automation-json |
| Area | Extinguish batch / Next actions path |
| Observed while | cycle 60 dogfood in `algorithm-evolution-agent-lab` |

## Observation

`codefire extinguish --batch <file> --path subprojects/algorithm-evolution-agent-lab --dry-run --json` validates the batch against the intended open directory, and `data.plan.open_dir` plus `next_actions[0].target.path` preserve that path. However the executable command string in `next_actions` drops the path:

```json
{
  "command": "codefire verify --details --json",
  "kind": "verify",
  "target": {
    "path": "subprojects/algorithm-evolution-agent-lab"
  }
}
```

The command was invoked from `/workspace/project`, not from the algorithm open directory.

## Reproduction

```bash
cd /workspace/project
codefire extinguish --batch /tmp/codefire-cycle60-batch.json \
  --path subprojects/algorithm-evolution-agent-lab \
  --dry-run \
  --json
```

## Why It Matters

Dry-run outputs are commonly used by AI agents as a plan to execute. If the next action command string omits the explicit path, an agent that executes it verbatim can verify the wrong CodeFire repository/open directory even though the machine-readable target has the right path.

## Workaround

Ignore the pathless command string and use the target path manually:

```bash
codefire verify --details --json --path subprojects/algorithm-evolution-agent-lab
```

## Candidate Fix

When building operation-plan next actions for batch extinguish dry-run/apply results, render the same path used by the operation into the command string and include it in `target` / `context`.

## Acceptance Criteria

- `extinguish --batch <file> --path <open-dir> --dry-run --json` returns verify next_actions whose command includes `--path <open-dir>`.
- The non-dry-run batch result follows the same path-preservation rule.
- Regression coverage asserts command text and machine target path match.

## Evidence

- Observed on 2026-06-12 during cycle 60 dogfood after adding `FinalManifestGate`.
- Dry-run returned `target.path: "subprojects/algorithm-evolution-agent-lab"` but `command: "codefire verify --details --json"`.

## Fix

Implemented in cycle 60 burn-down.

- Batch extinguish operation plans now render the same path in the verify command string that they already expose in `target.path`.
- The rule applies to both dry-run and applied batch result plans.
- Regression test: `tests::extinguish_batch_validates_all_items_before_writing_ledgers`.
- Targeted test run: `cargo test -p codefire-cli extinguish_batch_validates_all_items_before_writing_ledgers`.
