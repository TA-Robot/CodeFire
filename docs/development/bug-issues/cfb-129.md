# CFB-129: unhealthy doctor and migrate JSON emit two envelopes

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | automation-json |
| Area | doctor / migrate command result rendering |
| Observed while | diagnosing the CFB-128 Stage 1 dogfood blocker |

## Observation

`doctor --json` on an unhealthy repository and `migrate check --json` on an incompatible
repository each write a detailed command-result envelope and then return a domain error. The
top-level error handler renders that returned error as a second generic command-result envelope on
the same stdout stream.

As a result, stdout is not one JSON value. The first envelope has the useful issue/blocker details;
the second loses most repository/path context. A consumer cannot use an ordinary JSON parser and
cannot know which envelope is authoritative without command-specific stream splitting.

## Reproduction

```bash
codefire doctor /workspace/algorithm-evolution-agent-lab --full --json \
  > /tmp/doctor.json
jq . /tmp/doctor.json

codefire migrate check /workspace/algorithm-evolution-agent-lab --json \
  > /tmp/migrate.json
jq . /tmp/migrate.json
```

Both commands fail `jq` with trailing JSON after the first document. Source inspection confirms
that the doctor and migrate dispatch arms print their report and then return
`InvalidRepository`/`MigrationIncompatibility`, while top-level `main()` renders the second error.

## Why It Matters

The automation interface promises one deterministic command-result envelope. Error paths are the
paths where an AI tool or CI process most needs typed diagnostics and executable recovery actions.
Two concatenated documents turn a correctly detected repository problem into an unrelated JSON
transport failure and can cause the richer first report to be ignored.

## Workaround

Capture stdout as text and manually split two top-level documents. This is intentionally not a
supported automation contract and must not be required of consumers.

## Candidate Fix

After rendering a structured doctor/migrate report, return the existing rendered-result sentinel
(`CommandFailed(exit_code)` or an equivalent single-owner outcome) so the top-level handler only
sets the process exit code. Keep the domain details, repo/path, diagnostics, and next actions in the
one emitted envelope. Do not suppress non-JSON human-readable failure behavior.

## Resolution

Doctor and migrate now return the rendered-result sentinel after emitting a structured failure
report. The top-level handler therefore owns only the process exit status and never appends a
generic second envelope. Text mode retains its report, stderr error, and nonzero exit behavior.

## Acceptance Criteria

- Healthy and unhealthy `doctor --json` each emit exactly one parseable JSON document.
- Compatible and incompatible `migrate check|dry-run|apply --json` each emit exactly one parseable
  JSON document.
- The single failure envelope retains the detailed report, repository/path context, blockers,
  diagnostics, next actions, and documented nonzero exit code.
- Text mode still emits one human-readable report and exits nonzero on unhealthy/incompatible state.
- A CLI integration test parses the complete stdout with one `serde_json::from_slice` call and
  rejects any trailing content.

## Evidence

- Installed Stage 1 build reproduced two documents for both commands on
  `/workspace/algorithm-evolution-agent-lab`.
- `crates/codefire-cli/src/main.rs` doctor dispatch prints the report before returning
  `CliError::InvalidRepository`.
- `crates/codefire-cli/src/main.rs` migrate dispatch prints the report before returning
  `CliError::MigrationIncompatibility`.
- `crates/codefire-cli/tests/doctor_migrate_json.rs` parses complete healthy and unhealthy doctor,
  compatible and incompatible migrate check/dry-run/apply stdout with one
  `serde_json::from_slice` call. All 3 integration tests pass.
- The integrated workspace gate passes 472 Rust tests, warning-denying Clippy, formatting, and both
  documentation checkers.
