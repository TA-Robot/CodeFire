# CFB-069: verify --blocking-only next_actions include non-blocking missing-link work

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | automation-contract |
| Area | Automation JSON / Verify Filter |
| Observed while | verifying `ClaimReviewQueue` dogfood changes |

## Observation

`codefire verify --path . --details --blocking-only --json --metrics` correctly returned blocking diagnostics only for open required fires. However, `data.missing_required_links` still contained non-blocking missing links because `trace_completeness_required=false`, and `next_actions` suggested multiple `context --atom ...` commands for those non-blocking missing links.

## Reproduction

```bash
cd subprojects/algorithm-evolution-agent-lab
codefire verify --path . --details --blocking-only --json --metrics
```

Observed result:

```json
{
  "data": {
    "diagnostic_filter": "blocking_only",
    "trace_completeness_required": false,
    "open_required_fires": 6,
    "missing_required_links": [/* non-blocking warnings */]
  },
  "diagnostics": [
    {"kind": "open_required_fires", "blocking": true}
  ],
  "next_actions": [
    {"kind": "context_changed"},
    {"kind": "scan"},
    {"kind": "context_atom", "target": {"atom_id": "DES-AUTO-001"}}
  ]
}
```

## Why It Matters

`--blocking-only` is the mode an automation tool uses when it wants the minimal set of work that prevents progress. Returning next actions for non-blocking warnings makes the tool chase lower-priority trace cleanup instead of extinguishing open fires.

## Workaround

Ignore `context_atom` next actions for missing links when `data.trace_completeness_required=false` and `data.diagnostic_filter=blocking_only`. Use `diagnostics[].blocking` and `data.open_required_fires` as the source of truth.

## Candidate Fix

Make next action generation aware of the diagnostic filter. In `--blocking-only` mode, next_actions should be derived only from blocking diagnostics. Non-blocking remediation can remain available in the unfiltered verify output.

## Acceptance Criteria

- `verify --blocking-only --json` emits next_actions only for blocking diagnostics.
- Non-blocking missing links remain visible in a clearly separated all-data field or unfiltered mode.
- Tests cover `trace_completeness_required=false` with open fires and missing links.
- The first next action guides toward open fire inspection/extinguish, not missing-link cleanup.

## Evidence

- Observed during cycle 2 dogfooding after `ClaimReviewQueue` changes, with 6 open required fires and 8 non-blocking missing required links.

## Fix

- Fixed in the global burn-down pass.
- `verification_next_actions` is now aware of the diagnostic filter.
- `verify --blocking-only --json` skips non-blocking missing-link `context_atom` actions when trace completeness is not required.
- Unfiltered verify output can still suggest missing-link remediation.
