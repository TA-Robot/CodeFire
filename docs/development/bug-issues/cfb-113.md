# CFB-113: remote clone does not gate source branch state

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | bug |
| Area | Branch workflow / Remote clone source state |
| Observed while | CodeFire branch workflow source review after algorithm documentation dogfood |

## Observation

Local clone now checks source branch state through `ensure_sealed_source_state`, but remote clone paths do not apply the same gate.

In `clone_branch`:

- local branch clone loads `source["state"]` and rejects `open-burning` / `open-consistent`;
- `cf://` clone loads the remote branch record, reads `head`, validates the sealed commit, and proceeds without checking the remote branch state;
- HTTP clone fetches a branch bundle, reads `head`, validates the sealed commit, and proceeds without checking the bundled branch state.

That means a remote branch with unsealed open work can be cloned from its last sealed head, silently excluding the unsealed work.

## Reproduction

Code path review:

```bash
rg -n "fn clone_branch|ensure_sealed_source_state|cf://|HTTP remote returned an invalid branch bundle" crates/codefire-cli/src/main.rs
```

Relevant control flow:

```text
local clone:
  load_branch_record(...)
  source_state = source["state"]
  ensure_sealed_source_state(...)

cf:// clone:
  load_remote_branch(...)
  source_head = source["head"]
  validate_sealed_commit(...)
  # no source state check

HTTP clone:
  fetch branch bundle
  source_head = branch["head"]
  validate_sealed_commit(...)
  # no source state check
```

## Why It Matters

Branch-per-feature operation relies on source branches being sealed before clone or merge. If local clone rejects unsealed source branches but remote clone does not, automation can behave differently depending on transport. An agent may believe it cloned the current remote feature state while actually cloning the previous sealed head.

## Workaround

Before cloning from a remote branch, manually inspect the remote branch state and require it to be `closed` or `open-clean`. Avoid cloning remote branches that are known to have open unsealed work.

## Candidate Fix

Apply the same source state gate to remote branch records:

- read remote branch `state`;
- reject `open-burning` and `open-consistent`;
- include remote branch name, state, and repo/remote context in the structured error;
- document that remote clone uses only sealed branch heads.

## Acceptance Criteria

- Local, `cf://`, and HTTP clone all enforce the same source branch state policy.
- Remote clone rejects source branch states that can contain unsealed work.
- JSON errors include remote source, branch, state, and a recovery next action.
- Tests cover `cf://` and HTTP branch records with `open-consistent` state.

## Evidence

- `crates/codefire-cli/src/main.rs` local clone path calls `ensure_sealed_source_state`.
- The `cf://` and HTTP clone branches validate only `head` and sealed commit object availability before planning clone.
