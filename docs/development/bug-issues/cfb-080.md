# CFB-080: trace-graph path/json command returns raw empty graph

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | correctness-risk |
| Area | Trace Graph / JSON Contract |
| Observed while | following link batch next_actions in the algorithm project |

## Observation

`codefire trace-graph --path . --json` returned raw JSON, not a command result envelope. It also returned `links: []` in a repository whose scan metrics reported 235 trace links.

## Reproduction

```bash
cd subprojects/algorithm-evolution-agent-lab
codefire scan --path . --json --metrics
codefire trace-graph --path . --json
```

Observed:

```json
{
  "type": "trace_graph",
  "version": 1,
  "links": []
}
```

## Why It Matters

An empty trace graph from a populated project can make automation believe traceability is absent. The raw, non-envelope JSON also breaks the command result contract used by other automation-facing commands.

## Workaround

Use `context --changed --json`, `scan --json`, or read `codefire.links.yaml` directly for trace information.

## Candidate Fix

Formalize `trace-graph` as a normal command: parse `--path`, honor `--json`, return `codefire.command_result.v1`, and load the actual project Trace Graph.

## Acceptance Criteria

- `trace-graph --path <open-dir> --json` returns non-empty links for a project with links.
- output is wrapped in the command result envelope.
- `trace-graph --help` works.
- tests compare trace-graph link count with scan/context trace parsing.

## Evidence

- Observed during cycle 2 dogfooding; scan metrics reported 235 trace links while trace-graph returned zero.
