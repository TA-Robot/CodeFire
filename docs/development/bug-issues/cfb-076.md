# CFB-076: link batch invalid dry-run reports ok true

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | automation-contract |
| Area | Batch / Dry Run Validation |
| Observed while | probing link batch during cycle 2 dogfooding |

## Observation

`codefire link --batch <file> --path . --dry-run --json` returned `data.valid=false` and an `existing_link` diagnostic with severity `error`, but the top-level envelope still had `ok:true` and `exit_code:0`.

## Reproduction

```bash
cd subprojects/algorithm-evolution-agent-lab
tmp=$(mktemp)
cat > "$tmp" <<'EOF'
version: 1
links:
  - from: REQ-AUTO-033
    to: DES-AUTO-015
    type: refined_by
EOF
codefire link --batch "$tmp" --path . --dry-run --json
rm -f "$tmp"
```

## Why It Matters

Dry-run validation is frequently used to decide whether apply is safe. A top-level success envelope with error diagnostics requires every caller to remember command-specific `data.valid` semantics.

## Workaround

Treat `data.valid=false` or any diagnostic with `severity:error` as failure, regardless of top-level `ok`.

## Candidate Fix

Define a stable validation-failure contract for dry-run commands. Either return `ok:false` with a nonzero validation exit code, or add a clear envelope-level validation state shared by batch commands.

## Acceptance Criteria

- invalid link batch dry-run is not indistinguishable from successful validation at envelope level.
- docs define dry-run validation failure semantics.
- tests cover invalid dry-run envelope fields.

## Evidence

- Observed with an already-existing `REQ-AUTO-033 -> DES-AUTO-015` link.
