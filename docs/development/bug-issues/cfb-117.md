# CFB-117: HTTP clone dry-run writes remote objects locally

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | bug |
| Area | Remote clone / Dry-run side effects |
| Observed while | CodeFire clone implementation review after branch-per-feature dogfood |

## Observation

The HTTP clone path writes remote object records into the local `.codefire/objects` directory before checking `options.dry_run`.

In `clone_branch`, the HTTP branch bundle path does:

```text
fetch HTTP bundle
extract branch record and object records
write_object_records(local objects, records)
validate sealed commit from local objects
build plan
if dry_run return plan
```

That means `codefire clone https+cf://... --dry-run` can mutate local object storage even though the operation reports a dry-run plan.

The `cf://` clone path does not copy objects until after the dry-run return, so the behavior differs by remote transport.

## Reproduction

Code path review:

```bash
nl -ba crates/codefire-cli/src/main.rs | sed -n '4990,5030p'
```

The mutation happens at the `write_object_records(...)` call before:

```rust
if options.dry_run {
    return Ok(CloneResult { plan });
}
```

## Why It Matters

Dry-run should be safe to execute in exploratory automation. Writing remote objects during dry-run changes repository storage, can affect storage reports, and violates the expectation that dry-run only reads state and returns a plan. Transport-specific behavior also makes automation harder to reason about.

## Workaround

Avoid HTTP remote clone dry-run when object store purity matters. Use local or `cf://` dry-run for planning, or inspect storage before and after if HTTP clone dry-run is necessary.

## Candidate Fix

Do not write HTTP bundle objects during dry-run. Options:

- validate the bundle in memory;
- write to a temporary object directory and delete it before returning;
- defer `write_object_records` until after the dry-run return and validate the remote commit against the bundled records directly.

## Acceptance Criteria

- HTTP clone dry-run leaves `.codefire/objects` unchanged.
- HTTP clone apply still copies required object records before writing the branch record.
- `cf://` and HTTP clone dry-run have the same mutation contract.
- Tests compare object store contents before and after HTTP clone dry-run.

## Evidence

- `crates/codefire-cli/src/main.rs` writes object records in the HTTP clone path before the dry-run branch.
- The `cf://` clone path returns before `copy_object_graph(...)` when `options.dry_run` is true.
