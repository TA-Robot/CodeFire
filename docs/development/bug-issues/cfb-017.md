# CFB-017: Non-Atom changed files are invisible in scan output

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Scan / Context / Commit |
| Observed while | Updating `algorithm-evolution-agent-lab` documents alongside Atom-bearing files |

## Observation

`scan` focused on changed Atom IDs and open fires. README, todo, history, and other plain project files could be added or edited without appearing in the changed summary.

## Impact

Document-only changes looked clean unless the operator separately inspected file diffs. That weakened CodeFire as a self-contained development ledger because non-Atom work could be sealed without being visible in scan/context/commit summaries.

## Fix

`ScanResult` now carries `non_atom_changed_files` as first-class metadata. The CLI computes this from content manifest differences against the base commit while excluding files that contain current or base Atoms.

The following outputs now expose non-Atom file changes:

- `scan` text output
- `scan --json`
- `status --json` scan prediction
- `context --changed --json`
- `commit --dry-run --json`
- commit text summary

## Evidence

- `cargo test -p codefire-cli non_atom_file_changes_are_reported_in_scan_context_and_commit`
- `cargo test -p codefire-cli`
