# CFB-103: branch operation next_actions do not shell-quote branch names or paths

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | automation-json |
| Area | Branch workflow / Next actions |
| Observed while | branch workflow source review after branch-per-feature dogfood |

## Observation

Branch operation next_actions build command strings with raw branch names:

```text
codefire open {new_branch} <path>
run codefire merge {source_branch} --into {target_branch}
```

The same module has a `command_arg` helper, and tests show branch names can contain spaces and non-ASCII characters through `ref_file_name("feature/a b%雪")`. Without quoting, generated commands become ambiguous or non-executable for valid branch names such as `feature/a b`.

## Reproduction

```bash
cd /workspace/project
codefire clone main "feature/a b" --dry-run --json
```

The plan-local open next_action renders the branch name without shell quoting.

## Why It Matters

AI agents and generic command_result consumers often execute `next_actions[].command` literally. If CodeFire accepts branch names that require quoting but emits unquoted commands, automation can open or merge the wrong branch name tokens, fail with confusing usage errors, or require command-specific escaping logic.

## Workaround

Fixed in branch workflow burn-down. Older binaries require reading structured `target.branch` fields and building argv arrays manually.

## Candidate Fix

Use the existing `command_arg` helper, or better an argv-capable next_action representation, whenever rendering branch names and paths into command strings. Apply this consistently to `open`, `clone`, `merge`, and close/discard lifecycle commands when added.

## Acceptance Criteria

- `clone --dry-run --json` quotes branch names in generated command strings.
- Merge apply next_actions, once normalized, quote source and target branch names.
- Open success next_actions quote the opened path when CFB-098 is fixed.
- Tests cover branch names with spaces.

## Evidence

- Source review on 2026-06-12 found raw `format!` command rendering in `clone_operation_plan` and `merge_next_actions`.
- `crates/codefire-cli/src/tests.rs::ref_file_name_matches_python_quote_safe_empty` demonstrates that branch names with spaces are valid at the storage layer.
- Fixed by routing branch/path command strings through `command_arg` for open/clone/merge/close next_actions.
- Regression: `crates/codefire-cli/src/tests.rs::clone_branch_creates_closed_branch_and_rejects_unsealed_source`.
