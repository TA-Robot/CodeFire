# CFB-026: `context --changed --json` summary shape differs from `scan --json`

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | automation-json |
| Area | `context --changed` |
| Observed while | `algorithm-evolution-agent-lab` の `ExperimentRunbookGenerator` 追加 |

## Observation

`scan --json` は `data.changed_atoms` と `data.open_fires` を返すが、`context --changed --json` は `data.atoms`、`data.fires`、`data.scan.changed_atoms` に情報が分散している。

## Reproduction

```bash
codefire scan . --json
codefire context --changed --json
```

## Why It Matters

AI agentがscan結果とcontext結果を同じ処理で扱えず、changed countやopen fire countを取り違えやすい。

## Workaround

`data.scan.changed_atoms` と `data.fires` を個別に読む。

## Candidate Fix

`context_changed` dataに `changed_atoms`、`open_fires`、`changed_count`、`open_fire_count` の互換summaryを追加する。

## Acceptance Criteria

- `context --changed --json` からscan相当のsummaryを直接読める。
- 既存の詳細 `atoms` / `fires` / `trace_links` は維持される。

## Evidence

- `context --changed --json` returned `data_keys=["atoms","branch","fires","limits","scan","selector","trace_links","truncated","type","version"]`.
- Fixed by adding top-level `changed_atoms`, `open_fires`, `changed_count`, and `open_fire_count` to context data while preserving detailed `atoms` / `fires` / `trace_links`.
- Regression: `cargo test -p codefire-cli --bin codefire-rs context_pack_returns_atom_changed_and_fire_views -- --nocapture`.
