# CFB-031: Metrics expose an unimplemented cache block

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | low |
| Type | ux |
| Area | `--metrics` |
| Observed while | collecting scan/verify metrics |

## Observation

Metrics always include `cache.status=unimplemented` and `disabled_reason=not_implemented`.

## Reproduction

```bash
codefire scan . --metrics --json
```

## Why It Matters

The cache block looks actionable even though there is no user-tunable cache. It adds noise to automation metrics.

## Workaround

Ignore `metrics.cache`.

## Candidate Fix

Hide the cache block until implemented, or mark it as experimental/unavailable in diagnostics.

## Fix

v0.8 reports unimplemented cache telemetry as `cache_status=unavailable` and omits the normal detailed `cache` object until cache behavior exists.

## Acceptance Criteria

- Metrics focus on implemented measurements by default.
- Unimplemented future fields do not appear as normal telemetry.

## Evidence

- `metrics.cache` reported `implementation=none`, `status=unimplemented`.
- Regression coverage: `metrics_attach_to_status_scan_and_verify_data`.
- Verification: `cargo test -p codefire-cli --bin codefire-rs -- --nocapture`.
