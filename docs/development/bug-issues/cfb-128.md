# CFB-128: strict Trace endpoint validation strands legacy extractor history

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | compatibility |
| Area | Rust Atom extraction / versioned sealed semantic profile / migration recovery |
| Observed while | installing the Stage 1 source-close build and dogfooding `algorithm-evolution-agent-lab` |

## Observation

The installed Stage 1 build correctly applies the CFB-123 Trace endpoint predicate to sealed
commits, but both configured Algorithm repositories become unusable before `scan` can construct a
current index:

- `/workspace/algorithm-evolution-agent-lab/main` fails on head
  `CF-COMMIT-5d3f0f33e5ce16ab34d72ac1`;
- `/workspace/project/subprojects/algorithm-evolution-agent-lab` fails on head
  `CF-COMMIT-1bc27ac05b3a2f8e9d9c1de3`.

The historical transition is an authenticated Python-to-Rust extractor migration rather than an
arbitrary object edit. The first affected commit replaced a Python-produced Atom index containing
`CODE:src/evoagent/models.py::class:ExperimentPlan` with the Rust explicit-marker-only index while
retaining the same source manifest and Trace Graph. The source class and the link still exist, but
the unprofiled sealed snapshot has one endpoint absent from its Atom index. The configured
workspace head uses legacy root schema 1, while the canonical in-repo head already uses root schema
2; neither records which cross-root semantic predicates existed when it was written. Forty-six
commits in the configured workspace descend from the first affected commit.

`status` and `branch list` return `sealed_commit_invalid`; `doctor` marks the head and open base
unrepairable while recommending `branch list`/`open`; `branch list` fails on the same validation;
and `migrate check` reports the invalid head as a blocker without a graph migration action.

The first command exits 22 with:

```text
sealed commit validation failed: trace_graph.links[89].to atom
CODE:src/evoagent/models.py::class:ExperimentPlan is missing from atom_index
```

## Why It Matters

CFB-123 must continue to reject new current-format commits with dangling endpoints. At the same
time, retroactively applying a stronger cross-root invariant to schema-1 history without a bounded
compatibility/migration path prevents every normal recovery command, so a valid worktree and an
otherwise hash-valid linear history cannot be inspected, scanned, verified, or rebaselined.
Automation is sent through a circular next-action path and cannot distinguish historical extractor
semantics from arbitrary corruption.

## Workaround

There is no supported non-destructive CLI workaround. Manually editing object records would break
their content identity, and manually moving branch/open references would discard authenticated
history. The affected repositories must remain unchanged until CodeFire supplies the recovery path.

## Candidate Fix

Treat this as one extractor-version/legacy-read boundary, not as a waiver for current corruption:

1. Restore the supported Python derived-symbol Atom profile in the Rust default implementation and
   bump the Atom extractor/hash schema identity.
2. Add an explicit current sealed semantic profile/epoch. Keep full Trace endpoint enforcement for
   that profile. Read structurally valid, profile-absent schema-1 and early schema-2 snapshots under
   their historical semantic coverage so they can be parents of a current migration commit; unknown
   profiles fail closed and every Rust current writer emits the current profile.
3. Validate the current worktree Trace Graph against the newly built current Atom index before any
   state write. With unchanged source and a schema bump, classify the delta as `tool_migration`
   rather than ordinary source fires.
4. Permit the normal verified commit path to seal a schema-2 rebaseline whose current Atom/Trace
   roots pass the authoritative predicate, while retaining the legacy parent chain.
5. Make doctor/migration output distinguish a recoverable legacy semantic-profile transition from
   arbitrary malformed/current-schema graph corruption and provide an executable next action.

## Resolution

- Added the explicit `sealed-snapshot-v1` commit semantic-validation profile. Current Rust writers
  always emit it; profile-absent commits remain readable as legacy input; unknown or non-string
  profiles fail closed.
- Kept structural, hash, root, reference, parent, schema-2 semantic, and certificate validation
  unconditional. Only the newly introduced Atom/Trace endpoint-closure predicate is selected by
  the commit's semantic profile.
- Restored bounded Python derived-symbol extraction in the Rust core and advanced the Atom hash
  schema to 3. Unchanged historical source is classified as `tool_migration`, not an ordinary
  source change or Fire storm.
- Added doctor and migrate warnings for a valid legacy head/base, including executable scan and
  migration inspection actions. A current-profile bridge clears the warning while retaining its
  authenticated legacy parent.
- Added a CLI bridge integration test that constructs the historical schema-2 dangling-endpoint
  case, proves read/scan/verify recovery, and seals a strict current-profile child without rewriting
  the legacy object graph.

## Acceptance Criteria

- Current schema-2 sealed commits with missing or ambiguous Trace endpoints still fail closed.
- Structurally/hash-valid profile-absent history created before the endpoint-closure invariant,
  including both schema-1 and early schema-2 commits, can be read as explicitly legacy input and
  retained as parent history without rewriting objects.
- Rust extraction recreates the supported Python derived ID
  `CODE:src/evoagent/models.py::class:ExperimentPlan` deterministically while preserving explicit
  `cf-atom` ownership and duplicate detection.
- The extractor semantic change has a new schema identity and unchanged-source scan reports a
  bounded `tool_migration` with no ordinary Fire storm.
- `status`, `scan`, `verify`, `branch list`, and `doctor` reach a non-circular recovery path on both
  Algorithm repositories.
- A verified rebaseline creates a current schema-2 commit, preserves the legacy parent chain, and
  leaves branch/open/active state mutually consistent across retry/failure boundaries.
- Arbitrary malformed objects, bad hashes, missing roots/references, unknown profiles, and
  current-profile graph corruption remain rejected.
