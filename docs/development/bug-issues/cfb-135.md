# CFB-135: Doctorがextinguished Fireをopenとして数える

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | bug |
| Area | Doctor / Active-state invariant |
| Observed while | CFR-163 fresh Install後のlocal authority/recovery Dogfood |

## Observation

fresh installed CFR-163 binaryでmanual Fireを作成して通常の`extinguish`を完了すると、branch、opened
registry、active `state.json`はすべて`open-clean`になり、`fires.json`の唯一のFireも
`status=extinguished`になる。それにもかかわらず`doctor --quick --json`は
`active_state_invariant_violation`をblocking errorとして返し、process/envelopeともexit 20になる。

同じfixtureの`active_ledger_transaction.json`は`status=complete`、`phase=complete`、
`state_publication=released`であり、pending recoveryではない。validなclean stateを再openするnext actionまで
提示されるため、CFR-163のinstalled Dogfood/Closeを進められない。

## Reproduction

```bash
/tmp/codefire-cfr163-closed.58tvD9/bin/codefire doctor \
  --path /tmp/codefire-cfr163-dogfood.bTQl3y/repo \
  --quick --json
```

## Why It Matters

解消済みFireの履歴を保持する正常なrepositoryが破損扱いになり、人間やAI agentが不要なreopenや内部state
修復へ誘導される。CFR-163が追加したdurable active-ledger receiptとclean stateの正当な組み合わせを
Doctor自身が拒否するため、同rootのClose blockerである。

## Workaround

`status --json`と`fires.json`の各`status`、branch/opened/active stateの一致をread-only確認し、Doctorの
当該invariantだけを手動で無視する。Fire履歴、receipt、active stateを削除・編集しない。

## Candidate Fix

Doctorのactive-state invariantは`fires.json`の配列長ではなく`status == "open"`のFireだけを数える。
shared Fire shape validatorを通した値に対して判定し、manual Fireを通常extinguishした`open-clean` fixtureを
回帰テストにする。pending active-ledger authorityはshared descriptorからtyped operation/phase/request hashを
投影し、released receiptはpending issueにしない。

## Acceptance Criteria

- `open-clean` / `open-consistent`を拒否するのは`status=open`のFireが1件以上ある場合だけである。
- manual Fire作成、通常extinguish、`open-clean`の実workflowでDoctorがcleanになる。
- released active-ledger receiptはblocking issueを作らない。
- pending ledger/state-publication receiptはshared validator由来のtyped authorityとなり、payloadを出さず、
  read-only inspectionとexact owning retryだけを案内する。
- focused regression、source/project docs checker、fresh Install、fixture replayが通るまでinvestigatingを維持する。

## Resolution

pending active-ledger authorityはshared snapshot descriptorからoperation、phase、request hash、safe read-only
inspection、exact owning retryをtyped reportし、released receiptはblocking issueへ投影しない。
