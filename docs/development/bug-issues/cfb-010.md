# CFB-010: Status does not predict scan work

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Status vs Scan |
| Observed while | `status` looked commit-ready before a later scan opened many fires |

## Observation

`status` reported the last known open state and open fire count, but it did not show what a current scan would find.

## Impact

An operator could see `open-consistent` and assume the branch was ready to commit, only to discover a large extinguish workload after running `scan`.

## Fix

`status --json` now includes `data.scan_prediction`, computed with a read-only preview scan:

- `branch_state`
- `changed_count`
- `open_fire_count`
- `tool_migration`
- `base_commit`

## Evidence

- `cargo test -p codefire-cli --bin codefire-rs context_pack_returns_atom_changed_and_fire_views -- --nocapture`
