# CFB-051: Commit dry-run JSON includes every changed atom by default

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | automation-json |
| Area | commit --dry-run |
| Observed while | dry-running the initial algorithm import commit |

## Observation

`commit --dry-run --json` includes a full `changed_atoms` array. For the algorithm initial import this was 219 Atom IDs, making the plan noisy and larger than needed for the default automation decision.

## Reproduction

```bash
codefire commit --path . -m "Initial import" --dry-run --json
```

## Why It Matters

Dry-run plans should be compact enough to inspect in logs and agent context. Full changed Atom lists are useful, but they should be opt-in or bounded.

## Workaround

Filter the result through `jq` and rely on counts from scan/verify.

## Candidate Fix

Add `changed_atom_count`, include only the first N Atom IDs by default, and include `changed_atoms_omitted`. Provide full detail through `--full` or an output file option.

## Acceptance Criteria

- Commit dry-run JSON is bounded by default.
- The total changed Atom count is always present.
- Full detail can still be requested explicitly.

## Evidence

- Initial import dry-run emitted all 219 changed Atom IDs.
