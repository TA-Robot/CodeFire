# CFB-070: local operation dry-run envelopes do not lift repo and next_actions

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | automation-contract |
| Area | Automation JSON / Operation Plan |
| Observed while | dry-running extinguish during `ClaimAuditTrailBuilder` dogfooding |

## Observation

`codefire extinguish ... --dry-run --json` returns a useful operation plan, but the top-level envelope has `"repo": null` and top-level `next_actions: []`. The repository path and next actions are only available inside `data.plan`.

## Reproduction

```bash
cd subprojects/algorithm-evolution-agent-lab
codefire extinguish FIRE-9856EB644D66 --path . \
  --resolution updated \
  --rationale "dry run check" \
  --dry-run --json
```

Observed shape:

```json
{
  "command": "extinguish",
  "ok": true,
  "repo": null,
  "next_actions": [],
  "data": {
    "type": "codefire_plan_result",
    "plan": {
      "open_dir": "/workspace/project/subprojects/algorithm-evolution-agent-lab",
      "next_actions": [{"kind": "verify"}]
    }
  }
}
```

## Why It Matters

Automation expects `repo` and top-level `next_actions` to be envelope-level fields. Keeping them only inside command-specific plan data makes local dry-run commands harder to compose safely.

## Workaround

Read `data.plan.open_dir` and `data.plan.next_actions` for local operation plan commands.

## Candidate Fix

When a dry-run plan includes repo/open-dir and next actions, lift those into the command result envelope while preserving the detailed plan under `data.plan`.

## Acceptance Criteria

- `extinguish --dry-run --json` has non-null top-level `repo`.
- top-level `next_actions` includes relevant plan next actions.
- commit/open/clone/patch local plan envelopes follow the same rule.
- Tests cover local operation plan envelope consistency.

## Evidence

- Observed during cycle 2 dogfooding with `ClaimAuditTrailBuilder` open fires.
