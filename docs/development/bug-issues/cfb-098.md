# CFB-098: open success next_actions omit opened path

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | automation-json |
| Area | Open / Next actions path |
| Observed while | branch-per-feature dogfood in `algorithm-evolution-agent-lab` |

## Observation

`codefire open feature/nameaudit-summary-line /workspace/project/subprojects/algorithm-evolution-agent-lab-feature-nameaudit-summary-line --json` successfully opened the feature branch and returned `target.path`, but the executable next action command was pathless:

```json
{
  "command": "codefire status --json",
  "target": {
    "path": "/workspace/project/subprojects/algorithm-evolution-agent-lab-feature-nameaudit-summary-line"
  }
}
```

The command was invoked from the existing main open directory. Running the suggested command verbatim from that cwd checks `main`, not the newly opened feature directory.

## Reproduction

```bash
cd /workspace/project/subprojects/algorithm-evolution-agent-lab
codefire clone main feature/nameaudit-summary-line --json
codefire open feature/nameaudit-summary-line /workspace/project/subprojects/algorithm-evolution-agent-lab-feature-nameaudit-summary-line --json
```

## Why It Matters

Branch-per-feature usage depends on moving from `clone` to `open` to status/scan in the newly created open directory. AI agents commonly execute `next_actions[].command` literally; dropping the path sends the agent back to the caller cwd and can make it operate on the wrong branch.

## Workaround

Fixed in branch workflow burn-down. Older binaries require ignoring the command string and using the machine-readable target path manually:

```bash
codefire status --path /workspace/project/subprojects/algorithm-evolution-agent-lab-feature-nameaudit-summary-line --json
```

## Candidate Fix

When rendering `open` success next_actions, include `--path <opened-path>` in the command string and copy the same path into `target` and `context`.

## Acceptance Criteria

- `open <branch> <path> --json` returns an executable status next_action for the opened path.
- The command string, target path, and context path agree.
- Regression covers invoking `open` from a different existing open directory.

## Evidence

- Observed on 2026-06-12 while opening `feature/nameaudit-summary-line`.
- Opened path: `/workspace/project/subprojects/algorithm-evolution-agent-lab-feature-nameaudit-summary-line`.
- Fixed by rendering open success next_actions as `codefire status --path <opened-path> --json`.
- Regression: `crates/codefire-cli/src/tests.rs::open_materializes_manifest_and_updates_registry`.
