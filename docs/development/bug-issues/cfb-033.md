# CFB-033: Doctor repairable issues lack repair next actions

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | `doctor` next_actions |
| Observed while | doctor reported repairable missing directories |

## Observation

Doctor reports `repairable: true` but next_actions only suggest rerunning doctor.

## Reproduction

```bash
codefire doctor . --json
```

## Why It Matters

An AI agent can get stuck rerunning diagnostics without discovering migrate or repair commands.

## Workaround

Manually run `codefire migrate check --json`.

## Candidate Fix

For repairable issues, suggest `migrate dry-run`, `migrate apply`, or `doctor --repair` when available.

## Acceptance Criteria

- Repairable doctor findings include a concrete repair/review command.
- The suggested command matches the reported issue kind.

## Evidence

- Doctor next action was `inspect_doctor_report` despite `repairable=true` issues.
- Fixed by adding `review_migration_plan` next action for repairable layout findings. The action points to `migrate dry-run --json` and reports the affected count.
- Regression: `doctor_checks_layout_active_state_and_open_marker_shape`; full `cargo test --workspace`.
