# CFB-099: merge --help returns usage error

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | low |
| Type | ux |
| Area | Merge / Help |
| Observed while | branch-per-feature dogfood in `algorithm-evolution-agent-lab` |

## Observation

`codefire merge --help` exits with code 2 and prints an error-style usage line instead of returning normal help.

## Reproduction

```bash
cd /workspace/project/subprojects/algorithm-evolution-agent-lab-feature-nameaudit-summary-line
codefire merge --help
```

## Why It Matters

`merge` is central to branch-per-feature usage. If help is an error path, human operators and AI agents cannot reliably discover `merge <source> --into <target> [--dry-run] [--json]` without external docs or source inspection.

## Workaround

Fixed in branch workflow burn-down. Older binaries require reading the error usage line or consulting docs/source manually.

## Candidate Fix

Route `merge --help` through the shared help surface and return exit 0 with usage, options, and examples.

## Acceptance Criteria

- `codefire merge --help` exits 0.
- Output includes source branch, `--into`, `--dry-run`, `--json`, idempotency, and lock options.
- JSON error handling for malformed merge commands remains unchanged.

## Evidence

- Observed on 2026-06-12 before merging `feature/nameaudit-summary-line` into `main`.
- Fixed by routing `merge --help` through `command_help_for_args`.
- Regression: `crates/codefire-cli/src/tests.rs::command_help_routes_before_mutating_parsers`.
