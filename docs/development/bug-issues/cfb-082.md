# CFB-082: storage quick mode marks largest object types as unscanned even when type is inferable

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | storage |
| Area | Storage / Quick Report |
| Observed while | checking storage impact of the algorithm project during CodeFire improvement cycle 2 |

## Observation

`codefire storage <path> --quick --json` returned the largest object list, but every largest object had `"type": "unscanned"`. The same command without `--quick` resolved the same object IDs and paths to concrete types such as `resolution_ledger`, `fire_ledger`, and `atom_index`.

## Reproduction

```bash
codefire storage /workspace/project/subprojects/algorithm-evolution-agent-lab --quick --json
codefire storage /workspace/project/subprojects/algorithm-evolution-agent-lab --json
```

Observed quick-mode sample:

```json
{
  "data": {
    "mode": "quick",
    "objects": {
      "largest": [
        {
          "object_id": "CF-RESOLUTION-215048ac7090c050c43f5ab4",
          "type": "unscanned"
        }
      ]
    },
    "skipped_checks": ["object_json_validation", "object_type_breakdown", "external_artifact_refs"]
  }
}
```

## Why It Matters

Quick mode is useful for frequent AI-agent storage checks, but `unscanned` hides the most important triage information: which object family is growing. The type is inferable from the object ID prefix or object subdirectory without full JSON validation, so quick mode can be more informative without paying the full scan cost.

## Workaround

Run full `codefire storage <path> --json` when object type matters.

## Candidate Fix

In quick mode, infer `largest[].type` from known object ID prefixes or object subdirectories while keeping full JSON validation in the full scan.

## Acceptance Criteria

- quick storage reports concrete largest object types when ID prefix or subdirectory is recognized.
- quick mode still lists skipped expensive checks accurately.
- full and quick mode agree for recognized largest object type names.

## Evidence

- Observed on 2026-06-07 in `/workspace/project/subprojects/algorithm-evolution-agent-lab`.
- Full mode resolved the same largest objects to `resolution_ledger`, `fire_ledger`, and `atom_index`.
