# CFB-137: HTTP retry testがwall-clock Date headerで非決定的に失敗する

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | test reliability |
| Area | Python HTTP upload retry characterization |
| Observed while | CFR-168 pair + semantic carrierのcanonical Python gate |

## Observation

`test_python_upload_surrogate_identity_is_exactly_retryable`は、同じ不正requestを2回送って得たHTTP wire全体を
byte比較していた。production responseは標準的なwall-clock `Date` headerを毎回生成するため、2回の応答が
UTC秒境界を跨ぐと、status、安定header、JSON body、ledger、filesystem stateがすべて同一でも失敗した。

## Why It Matters

全525件のcanonical gateがproduct regressionなしに約18分後redとなり、実装差分とtest flakeの切り分けに
同じ長時間gateの再実行が必要になる。retryのsemantic同一性を検証するtest自身がvolatile transport metadataを
契約へ混入していた。

## Fix

- 各応答に`Date` headerがexactly one存在することは個別に検証する。
- retry同一性はstatus line、`Date`以外の全header、response bodyの組で完全一致を検証する。
- error kind、filesystem無変更、nonce/transaction/receipt非生成、ledger zeroの既存検証は維持する。

## Acceptance Criteria

- UTC秒境界を跨いでもretry characterizationが失敗しない。
- `Date` headerの欠落・重複は引き続き失敗する。
- `Date`以外のheaderまたはbody差分はbyte単位で失敗する。
- focused反復とcanonical Python gateで確認する。

## Evidence

- `tests/test_codefire_cli.py`: `test_python_upload_surrogate_identity_is_exactly_retryable`
- 発見時の差分は`Date: ...58:54 GMT`対`Date: ...58:55 GMT`だけだった。
- 修正後focused testを6並列反復して6/6 passした。
- 正規toolchain環境のcanonical Python suiteは525/525 passした。
