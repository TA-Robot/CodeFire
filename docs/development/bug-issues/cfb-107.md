# CFB-107: branch command errors lose repo/path recovery context

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | bug |
| Area | Branch JSON / Error context |
| Observed while | algorithm branch lifecycle dry-run probe |

## Observation

Several branch workflow errors return structured JSON, but the top-level `repo` is `null` and recovery `next_actions` are empty or pathless even when the repo root is known from cwd.

Examples:

- `codefire open main <new-path> --dry-run --json` rejects an already-open branch but returns `repo:null` and no next action.
- `codefire open feature/name-ci-note-md <existing-main-dir> --dry-run --json` rejects the existing target path but returns `repo:null` and no next action.
- `codefire close feature/name-ci-note-md --dry-run --json` rejects a closed branch but returns `repo:null` and no next action.
- `codefire clone main main --dry-run --json` rejects an existing branch name but returns `repo:null` and no next action.
- `codefire clone missing-source feature/probe-missing-source --dry-run --json` returns a branch-list next action, but the command omits an explicit path and `repo` is still null.

## Reproduction

```bash
cd /workspace/project/subprojects/algorithm-evolution-agent-lab
codefire open main /workspace/project/subprojects/algorithm-evolution-agent-lab-main-second --dry-run --json
codefire close feature/name-ci-note-md --dry-run --json
codefire clone main main --dry-run --json
codefire clone missing-source feature/probe-missing-source --dry-run --json
```

## Why It Matters

Branch lifecycle automation often reacts to errors by listing branches, checking status, or retrying from a different open directory. If the failure envelope loses the repo and path context, an agent has to infer cwd-specific state instead of following reliable recovery actions.

## Workaround

After branch command failures, manually run:

```bash
codefire branch list --json
codefire status --path <known-open-dir> --json
```

from the intended repo/open directory.

## Candidate Fix

Populate top-level `repo` for branch command domain errors after repo discovery succeeds. Add path-aware recovery next actions for common branch lifecycle failures.

## Acceptance Criteria

- Already-open, not-open, existing-branch, existing-target-path, and unknown-source errors include non-null `repo`.
- Recovery next action command strings include `--path <open-dir>` or another unambiguous repo selector when available.
- Tests cover representative branch error envelopes.
