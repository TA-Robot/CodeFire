# CFB-088: evidence dry-run returns an empty evidence_id

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | ux |
| Area | Evidence / Dry Run JSON |
| Observed while | clean-state probe after FrontierExperimentPlanner commit |

## Observation

`codefire evidence add --dry-run --json` returns `data.evidence_id` as an empty string even though no evidence object is created.

Observed excerpt:

```json
{
  "dry_run": true,
  "evidence_id": "",
  "object_path": null,
  "plan": {
    "would_apply": false
  }
}
```

## Reproduction

```bash
cd subprojects/algorithm-evolution-agent-lab
codefire evidence add \
  --path . \
  --from-command "PYTHONPATH=src python3 -m unittest tests.test_frontier -v" \
  --cwd . \
  --dry-run \
  --json
```

## Why It Matters

An empty string looks like a malformed but present ID. Automation should not have to special-case `""` to distinguish dry-run from a real evidence object. A nullable field or explicit `created:false` contract is safer.

## Workaround

Treat `dry_run:true` as authoritative and ignore `evidence_id` when it is an empty string.

## Candidate Fix

For dry-run results, return `evidence_id:null` or omit the field, and add an explicit `created:false` field. Keep real evidence creation results as non-empty IDs.

## Acceptance Criteria

- evidence dry-run never returns an empty-string ID.
- dry-run result has an explicit creation status.
- tests cover dry-run and non-dry-run evidence result ID semantics.
