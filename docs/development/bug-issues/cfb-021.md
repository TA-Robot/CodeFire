# CFB-021: Commit output does not summarize what was sealed

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Commit Output |
| Observed while | Reviewing `algorithm-evolution-agent-lab` commit logs |

## Observation

`codefire commit` text output only reported the commit hash, branch, and final state. JSON output exposed the full plan, but did not provide a compact top-level summary that an automation loop could read without digging through nested fields.

## Impact

After repeated dogfood cycles, logs did not clearly show what each sealed commit contained. A reviewer had to correlate the commit message with previous scan, verify, and extinguish output to infer changed atom volume, fire resolution volume, and evidence usage.

## Fix

Commit results now expose a compact summary in both text and JSON output:

- message
- changed atom count
- extinguished fire count
- active resolution count
- evidence reference count

The JSON `data` object mirrors these fields at top level while preserving the full operation plan for detailed inspection.

## Evidence

- `cargo test -p codefire-cli commit_dry_run_json_reports_blockers_and_bounds_changed_atoms`
- `cargo test -p codefire-cli extinguish_evidence_ref_links_resolution_and_verify_detects_missing_ref`
