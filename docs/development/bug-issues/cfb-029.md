# CFB-029: Verify next actions lose the explicit path

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | `verify` next_actions |
| Observed while | running `verify . --json` in algorithm open directory |

## Observation

When `verify . --json` is used, next actions still suggest `codefire scan --json` and `codefire context --changed --json` without preserving the path.

## Reproduction

```bash
codefire verify . --json
```

## Why It Matters

An AI agent executing next_actions from a different cwd can target the wrong repository or fail discovery.

## Workaround

Fixed. Verify next actions now preserve the explicit path in both command text and `target.path`.

## Candidate Fix

Implemented in the global burn-down pass.

## Fix

- `verification_next_actions` now accepts the original action path.
- Verify-generated scan/context/commit/status/evidence/extinguish next actions include `--path <path>` where applicable.
- Each path-aware action also includes machine-readable `target.path`.

## Acceptance Criteria

- Path-aware commands preserve path in next_actions.
- Every next_action has enough structured target data to execute safely from another cwd.

## Evidence

- Fixed on 2026-06-10.
- Regression coverage: `verification_next_actions_preserve_explicit_path_context`.
- Verification: `cargo test --workspace`.
