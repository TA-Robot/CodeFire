# CFB-130: migrate help advertises an unimplemented apply command

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | bug |
| Area | migrate apply / layout recovery contract |
| Observed while | adding single-envelope tests for CFB-129 during Stage 1 dogfood recovery |

## Observation

The canonical CLI help advertises:

```text
codefire migrate apply [path] [--json] [--target-format v0.6]
```

but `migration::MigrateMode` only has `Check` and `DryRun`, and `parse_migrate_args` rejects
`apply` as an unsupported command. `migrate dry-run` can return `planned_actions`, including the
repairable layout directories seen in the Algorithm repositories, but no CodeFire command can apply
that plan. Product docs and help therefore expose a recovery transition that does not exist.

## Reproduction

```bash
codefire migrate --help
codefire migrate apply /workspace/algorithm-evolution-agent-lab --json
```

The first command lists `apply`; the second returns an unsupported-command usage error.

## Why It Matters

Migration is part of the fail-closed recovery path. Automation can inspect an exact dry-run plan but
cannot execute it, so it must either leave known repairable layout drift unresolved or create
internal directories manually without CodeFire's lock, containment, idempotency, or JSON contract.
The discrepancy is particularly damaging when doctor recommends migration during another recovery.

## Workaround

Manually create only the listed layout directories after independently validating the repository
root. This bypasses the intended command contract and is not acceptable as the final recovery path.

## Candidate Fix

Implement `MigrateMode::Apply` as the exact execution counterpart of the validated dry-run plan:

- acquire the repository lock and recompute the plan after acquisition;
- reject compatibility blockers before mutation;
- apply only registered, repo-contained layout actions through the shared layout definition;
- make already-applied actions idempotent and reject symlink/non-directory replacements;
- return the same typed report with applied/skipped counts and `would_write`/`did_write` semantics;
- keep check/dry-run non-mutating and align help, capability metadata, docs, exit codes, and tests.

## Resolution

Implemented `MigrateMode::Apply` as a layout-only recovery transition. It performs a full clean
preflight, bootstraps the persistent lock directory only when that exact action was planned,
acquires the shared repository lock, reloads and compares the authoritative plan, and applies only
registered `AutoCreate` directories through retained `.codefire`/`objects` capabilities. Repository
and parent identities are checked around every mutation; replacement, symlink, non-directory,
outside-root, contention, and concurrent-plan cases fail closed. Exact replay is a successful no-op.

`current` and `v0.6` are explicitly compatibility profiles. This command does not rewrite format
metadata and reports `format_write_supported=false` / `format_write_performed=false`.

## Acceptance Criteria

- `migrate apply` is accepted exactly as documented, including path, JSON, target-format, and
  quick/full option behavior where meaningful.
- Apply acquires the repository lock, reloads state, and never executes a stale dry-run plan.
- Blockers cause zero repository writes and one typed JSON result.
- Missing registered directories are created inside the repository; a second exact apply is a
  successful no-op.
- Symlink, non-directory, outside-root, parent-replacement, and concurrent-plan changes fail closed.
- Check and dry-run remain byte-for-byte non-mutating on repository domain state.
- Help, command capability metadata, source docs, and integration tests agree on the implemented
  surface.

## Evidence

- `crates/codefire-cli/src/main.rs::subcommand_help` lists `migrate apply`.
- `crates/codefire-cli/src/migration.rs::MigrateMode` has only `Check` and `DryRun`.
- `crates/codefire-cli/src/migration.rs::parse_migrate_args` rejects every other subcommand.
- CFB-128 dogfood doctor/migrate reports two repairable missing layout directories but can only
  produce a dry-run plan.
- `crates/codefire-cli/src/tests/migration_apply.rs` passes 12 focused cases covering lock
  contention, bootstrap/replay, blocker non-mutation, byte-stable check/dry-run, symlink and
  non-directory rejection, outside-root forgery, repository/objects parent replacement,
  concurrent plan drift, compatibility-profile-only behavior, and legacy-head warnings.
- Help, bash/zsh completion, CLI/automation/runbook, and canonical source documents describe the
  implemented surface. The integrated workspace, Clippy, format, JSON, and documentation gates all
  pass.
