# CFB-012: Status should not say burning when open fires are zero

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | UX / State Label |
| Observed while | Extinguishing all fires and then running `verify --details --blocking-only` |

## Observation

After all fires were extinguished and verification passed, `status` could still report `open-burning` with `Open fires: 0`.

## Impact

The state label implied unresolved fire work even though the branch was ready for commit.

## Fix

The state reducer now reports a consistent post-verify state: pending source changes with zero fires become commit-ready rather than burning.

## Evidence

- Global burn-down state reducer fixes.
- `current-cycle-burn-down-plan.md` CFB-012 entry.
