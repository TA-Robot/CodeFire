# CFB-102: clone and merge allow open-consistent source branches with unsealed changes

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | bug |
| Area | Branch workflow / Source branch state |
| Observed while | branch workflow source review after branch-per-feature dogfood |

## Observation

`clone_branch` and `build_merge_result` reject a source branch only when its branch record state is `open-burning`.

That means an `open-consistent` source branch is accepted. In normal workflow, `open-consistent` can still contain verified but uncommitted worktree changes. The branch record `head` remains the last sealed commit, so `clone` or `merge` proceeds from a stale sealed head and silently ignores the unsealed source changes.

Relevant code:

```text
crates/codefire-cli/src/main.rs::clone_branch
crates/codefire-cli/src/main.rs::build_merge_result
```

## Reproduction

```bash
cd /workspace/project
codefire open feature/demo /tmp/codefire-feature-demo
# edit and verify the feature open directory until status is open-consistent
codefire merge feature/demo --into main --dry-run --json
```

The merge plan is computed from `feature/demo`'s sealed `head`, not from the verified-but-uncommitted open directory contents.

## Why It Matters

The intended branch-per-feature workflow relies on developers sealing feature work before merging. If CodeFire accepts `open-consistent` sources, an agent can verify work, forget to commit it, merge the branch, and get a successful no-op or partial merge plan. That is a data-loss-shaped workflow bug because the command succeeds while leaving the intended changes behind in the feature open directory.

## Workaround

Fixed in branch workflow burn-down. Older binaries require checking the source branch state manually and committing the source branch before merging.

## Candidate Fix

Make local `clone` and `merge` reject source branches whose branch record state is not `closed` unless the command explicitly supports and documents an open-clean source case. At minimum, reject `open-consistent` with a message telling the user to commit or close the source branch first.

## Acceptance Criteria

- `clone` rejects `open-consistent` source branches with an actionable diagnostic.
- `merge` rejects `open-consistent` source branches before building a plan.
- Tests cover `open-burning` and `open-consistent` separately.
- The CLI spec documents which source branch states are accepted.

## Evidence

- Source review on 2026-06-12 found both `clone_branch` and `build_merge_result` check only `source_state == "open-burning"`.
- Fixed by sharing a source-state guard between `clone`, merge planning, and merge idempotency payload construction.
- Regressions: `crates/codefire-cli/src/tests.rs::clone_branch_creates_closed_branch_and_rejects_unsealed_source`; `crates/codefire-cli/src/tests.rs::merge_branch_rejects_open_consistent_source`.
