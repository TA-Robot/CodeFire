# CFB-079: trace-graph --help emits data instead of usage

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | ux |
| Area | CLI Help / Trace Graph |
| Observed while | checking link batch next_actions |

## Observation

`codefire trace-graph --help` printed a raw trace graph JSON object instead of command usage.

## Reproduction

```bash
cd subprojects/algorithm-evolution-agent-lab
codefire trace-graph --help
```

Observed:

```json
{
  "type": "trace_graph",
  "version": 1,
  "links": []
}
```

## Why It Matters

Help must be side-effect-free and should explain path/json behavior. Emitting data on `--help` makes the command hard to discover and can mislead automation probing command capabilities.

## Workaround

Read source/docs or avoid `trace-graph` until the command surface is formalized.

## Candidate Fix

Route `trace-graph --help` through the shared command help path before command execution.

## Acceptance Criteria

- `trace-graph --help` prints usage, not data.
- help documents path and JSON behavior.
- docs/help consistency tests cover trace-graph.

## Evidence

- Observed during cycle 2 dogfooding after `link --batch --dry-run` suggested `codefire trace-graph`.
