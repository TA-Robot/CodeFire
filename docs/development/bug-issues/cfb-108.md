# CFB-108: open allows branch materialization outside the CodeFire repo root

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | bug |
| Area | Branch open / Workspace boundary |
| Observed while | algorithm branch open path boundary probe |

## Observation

`codefire open` accepts a target path outside the CodeFire repo root without warning. In the algorithm repo, the CodeFire repo root is `/workspace/project/subprojects`, but this dry-run succeeds:

```bash
codefire open feature/name-ci-note-md /workspace/project/algorithm-outside-subprojects --dry-run --json
```

The plan materializes the feature branch under `/workspace/project/algorithm-outside-subprojects` while writing registry state under `/workspace/project/subprojects/.codefire`.

## Why It Matters

Open directories outside the managed repo root make cleanup, workspace boundaries, and sub-agent instructions harder to reason about. A branch-per-feature workflow should keep feature open directories in a predictable managed area unless the user explicitly opts out.

## Workaround

Use target paths under the CodeFire repo root, such as sibling directories inside `/workspace/project/subprojects/`.

## Candidate Fix

Reject open targets outside the repo root by default, or require an explicit opt-in flag such as `--allow-outside-root` with a warning diagnostic and clear close/discard behavior.

## Acceptance Criteria

- Opening outside the repo root is rejected by default in dry-run and apply modes.
- The rejection includes the repo root, requested target path, and safe example path.
- If an opt-in flag is supported, tests cover the explicit override and the close cleanup path.

## Evidence

- 2026-06-12 dry-run probe produced a successful open plan targeting `/workspace/project/algorithm-outside-subprojects` while the repo root was `/workspace/project/subprojects`.
