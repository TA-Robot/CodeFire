# CFB-046: Init help creates a repository named `--help`

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | bug |
| Area | CLI help / init |
| Observed while | reinstalling CodeFire and preparing `algorithm-evolution-agent-lab` dogfooding |

## Observation

`codefire init --help` does not print help. It treats `--help` as a path and initializes a CodeFire repository under a directory literally named `--help`.

## Reproduction

```bash
mkdir /tmp/cf-init-help
cd /tmp/cf-init-help
codefire init --help
find --help/.codefire -maxdepth 2 -type d
```

## Why It Matters

Help flags must be safe. AI agents and humans routinely try `--help` before mutating a command. A help probe that writes a repository is a surprising side effect and can pollute worktrees.

## Workaround

Use top-level `codefire help` and avoid `codefire init --help`.

## Candidate Fix

Handle `-h` / `--help` before `parse_init_args`, and ensure every mutating command treats help as read-only.

## Acceptance Criteria

- `codefire init --help` prints init usage and writes nothing.
- `codefire init -h` prints init usage and writes nothing.
- A regression test asserts no `--help/.codefire` directory is created.

## Evidence

- Observed command created `/workspace/project/subprojects/algorithm-evolution-agent-lab/--help/.codefire`; the accidental directory was removed immediately.
- Fixed in v0.9 Phase A by routing command help through `command_help_for_args` before `parse_init_args` or repository mutation.
- Regression test: `cargo test -p codefire-cli --bin codefire-rs command_help_routes_before_mutating_parsers -- --nocapture`.
