# CFB-013: Clean scan output should state empty results explicitly

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | UX / Scan Output |
| Observed while | Running clean `status`, `verify`, and `scan` after a sealed algorithm commit |

## Observation

Clean `scan` output showed empty headings for changed atoms and open fires instead of saying none.

## Impact

Logs were ambiguous: users had to infer whether the repository was clean or whether rendering omitted data.

## Fix

Clean scan text now prints explicit empty states such as `Changed atoms: none` and `Open fires: none`.

## Evidence

- Global burn-down scan text summary fixes.
- `current-cycle-burn-down-plan.md` CFB-013 entry.
