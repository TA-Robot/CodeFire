# CFB-136: command cacheが同一inode object書換えをvalidated hitとして再利用する

## Summary

| Field | Value |
|---|---|
| Status | investigating |
| Milestone | backlog parked (not reproduced by completed remote M1) |
| Severity | high |
| Type | correctness / integrity |
| Area | Store validation cache / Branch and Doctor snapshots |
| Observed while | CFR-168 command-scoped cache設計の独立反証 |

## Observation

`SealedCommitValidationCache`のhit subjectはobjects root/subdirectoryのdirectory identityとcommit IDである。
一度validatedになったcommit recordまたはreachable recordを、同じdirectory内の同一inodeへ協調lock外から
書き換えてもdirectory identityは変わらない。cacheを保持した次のhead/queryはrecordを再読せずvalidated hitを
返し得る。

現行branch listはheadごとにfresh cacheを作るためcross-head reuseを十分活用していないが、CFR-168がそのcacheを
command-wideへ拡大するだけでは、先にvalidatedなshared ancestorの破損を後続headが見逃す。local branch list自体も
repository snapshot lockを保持しないため、単なるcache-key field追加だけではTOCTOUを閉じない。

## Why It Matters

性能改善がvalidation省略になり、同じcommand内で先のbranchはvalid、後のbranchは同じ破損subjectをcache hitとして
成功表示できる。Doctor、storage、branch、ancestryが異なる診断を返し、CodeFireの「壊れた履歴を通常操作へ
広げない」不変条件を破るため、CFR-168 Close blockerである。

## Reproduction Plan

1. shared ancestorを持つ2 headを作り、同じ`SealedCommitValidationCache`で最初のheadをvalidateする。
2. validation後、shared recordの同一inode/同一pathへinvalid bytesまたはhash-mismatch payloadを書き戻す。
3. directory identitiesを維持したまま2番目のheadを同じcacheでvalidateする。
4. current behaviorがcache hitで破損を再読しない反例をfocused Store/CLI fixtureとして固定する。

## Candidate Fix

- 一つのcommand/request-wide `DecisionWorkSession`を、pinned object-root、support profile、repository/shared lock
  または検証可能なsnapshot tokenへbindする。
- lock/snapshotで同一inode内容不変を証明できないreaderは、cache hit前にrecord identity/digest/sizeをbounded
  no-follow再検証し、same-inode mutationをmiss/corruptionにする。
- cache stateを`parsed`、`validated node`、`fully validated reachable head`へ分け、cold early-stopや別subjectへの
  complete claimに流用しない。
- Rust/Python、branch/Doctor/storage/ancestryで同じmutation fixtureとdiagnosticを使う。

## Acceptance Criteria

- same-path/same-inode/same-sizeを含むrecord mutationがcache hitで隠れない。
- immutable snapshot内のshared DAGは一度だけvalidateされ、result/order/diagnosticはcold pathと一致する。
- snapshot/lockを取得できないruntimeはcacheをbypassまたはfail closedし、path/mtimeだけをauthorityにしない。
- cache countersはhit/miss/revalidated/invalidatedをaggregateで示し、metrics無効化でsemantic behaviorが変わらない。
- full CFR-168 scale、compatibility、Install、Dogfood、Retrospect gateが通るまでfixedにしない。
