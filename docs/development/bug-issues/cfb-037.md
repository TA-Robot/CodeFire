# CFB-037: Evidence command failure still returns ok true

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | bug |
| Area | `evidence add --from-command` |
| Observed while | saving runbook test evidence |

## Observation

`evidence add --from-command ... --json` returned `ok: true` and created an evidence ID even when `command_exit_code` was 1.

## Reproduction

```bash
codefire evidence add --from-command '<failing command>' --label runbook-test --json
```

## Why It Matters

Failed commands can be mistaken for successful verification evidence and used to extinguish fires.

## Workaround

Always inspect `data.command_exit_code` before trusting the evidence.

## Candidate Fix

Return `ok:false` for non-zero command exit unless `--allow-failed-command` is explicitly set.

## Acceptance Criteria

- Non-zero command evidence has error or warning diagnostics.
- Successful evidence and failed evidence are clearly distinguishable in JSON.

## Evidence

- Evidence result included `command_exit_code: 1`, `ok: true`, and `CF-EVIDENCE-*`.
