# CFB-120: scan reads the current base without sealed-commit validation

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | bug |
| Area | Scan / Sealed base integrity |
| Observed while | 2026-07-11 canonical source-document audit before new product development |

## Original Observation

Before this fix, Rust `compute_scan` obtained `current_base_commit` from the opened registry and called `load_base_atom_index`. That helper read the commit object and its Atom-index root with ordinary object-record validation, but did not call `codefire_store::validate_sealed_commit` for the base. `status` and several lifecycle paths did perform the stronger validation, so the invariant differed by command.

## Original Reproduction

Source-level counterexample:

1. Create and open a repository.
2. Construct a content-addressed commit whose certificate/root contract is invalid while its Atom-index root remains readable.
3. Point `opened/<branch>.json.open.current_base_commit` at that object.
4. Compare `status` with `scan`/`verify` behavior.

This counterexample is now maintained as the executable malformed-certificate, root-type,
missing-root, and invalid-parent matrix named under Regression Evidence.

## Why It Matters

Scan is upstream of Fire derivation, verification, and commit planning. Accepting a base that fails the sealed-commit contract can make later results appear to compare against an authoritative subject when only one readable root was checked.

## Historical Workaround

Before the fix, users could run `status` or `doctor` and resolve every sealed-base diagnostic before trusting scan/verify output. That operational check was not a replacement for the shared invariant now enforced in scan.

## Chosen Fix

Validate `current_base_commit` once at the scan consuming boundary before loading any root, and reuse the validated commit/root values so the fix does not multiply object reads. Keep success and corruption diagnostics equivalent across status, scan, verify, and commit.

## Implemented Fix

`compute_scan_with_cache` now validates `current_base_commit` with
`validate_sealed_commit_pinned_with_cache` before reading the base Atom index or deriving scan
state. The resulting `ValidatedSealedCommit` owns the validated object-store subject and is used by
`load_validated_base_atom_index`, `source_manifest_unchanged_validated`, and
`non_atom_changed_files_since_base`; those reads therefore cannot silently switch back to an
ambient object-store path after validation.

`ScanExecution` carries the same token into verification. Live scan/verify publication rechecks the
validated store identity before starting a state transaction and again at the publication boundary,
so an equal-content root replacement is rejected before active state is written. One
`SealedCommitValidationCache` is shared through each scan/verify execution, avoiding a second sealed
graph traversal for the same subject.

## Acceptance Criteria

- Scan and verify reject an invalid current base before deriving Atoms, Fires, or verification results.
- The failure uses the normal structured error envelope and preserves the explicit path/repository context.
- A focused fixture proves status, scan, and verify agree for malformed certificate, root type, missing root, and invalid parent cases.
- The valid path does not introduce repeated sealed-graph traversal within one command context.

## Evidence

- `crates/codefire-cli/src/main.rs::compute_scan_with_cache` obtains and retains the pinned token
  before `load_validated_base_atom_index` and all scan derivation.
- `crates/codefire-cli/src/main.rs::compute_verify_with_cache` carries that token through verify,
  while `persist_verification_result_state` rechecks it before mutable state publication.
- `crates/codefire-store/src/lib.rs::ValidatedSealedCommit` performs descriptor-relative
  commit/root/object reads with identity checks before and after each consuming operation.

## Regression Evidence

- `crates/codefire-cli/src/tests.rs::scan_status_and_verify_reject_an_unsealed_current_base_before_writing_state`
  covers malformed certificate, wrong root type, missing root, and invalid parent. Status, scan,
  verify, context, and Fire consumption all reject the base, and scan/verification/Fire/state files
  remain unpublished.
- `crates/codefire-cli/src/tests/sealed_token_boundary.rs::verify_carries_validated_store_token_and_rejects_equal_root_replacement_before_persist`
  replaces the validated object root with an equal-content directory and proves verification and
  state transactions remain unwritten while branch and opened-registry records remain unchanged.
- `crates/codefire-store/src/lib.rs::validated_sealed_commit_rejects_same_content_root_swap_after_validation`
  and `validated_sealed_commit_rejects_same_content_root_subdir_swap` cover root and root-subdirectory
  subject replacement after successful validation.
