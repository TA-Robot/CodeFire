# CFB-059: Batch file read failures are plain text even with `--json`

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | automation-json |
| Area | batch commands |
| Observed while | checking evidence/link/fire/extinguish batch failure paths |

## Observation

Batch commands return plain text OS errors when the batch file is missing, even when `--json` is supplied.

## Reproduction

```bash
codefire evidence add --batch /tmp/does-not-exist.json --path . --json
codefire link --batch /tmp/does-not-exist.json --path . --json
codefire fire --batch /tmp/does-not-exist.json --path . --json
codefire extinguish --batch /tmp/does-not-exist.json --path . --json
```

## Why It Matters

Batch workflows are a core automation surface. Missing file, parse failure, schema failure, and validation failure should be distinguishable in structured diagnostics.

## Workaround

Check file existence before calling CodeFire.

## Candidate Fix

Wrap batch file read errors in `codefire.command_result.v1` when `--json` is requested, with diagnostic kind such as `batch_file_missing`.

## Acceptance Criteria

- Missing batch file errors emit JSON for all batch commands.
- Diagnostics include command, path, error kind, and next action.
- Exit code remains non-zero and matches envelope `exit_code`.

## Fix

- Added a contextual `BatchFileRead` CLI error and shared `read_batch_file` helper for batch readers.
- `evidence add --batch`, `link --batch`, `fire --batch`, and `extinguish --batch` now return `codefire.command_result.v1` failure envelopes when `--json` is requested.
- Missing files are reported as `batch_file_missing` with `check_batch_path` and `show_batch_schema` next actions.
- JSON parse/schema failures now remain command-result diagnostics instead of leaking plain text after JSON output.
