# CFB-053: Scan JSON is impractically large for initial imports

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | automation-json |
| Area | scan --json |
| Observed while | scanning the initial import of `algorithm-evolution-agent-lab` |

## Observation

`scan --json` returns full `changed_atoms` and full `open_fires` arrays. For an initial import with 219 changed atoms and 427 fires, the output was too large for normal agent context and command logs.

## Reproduction

```bash
codefire scan --path . --json --metrics
```

## Why It Matters

Automation usually needs counts, severity summaries, and a small number of representative fires before deciding what to do next. Full data should be retrievable, but default JSON should remain bounded.

## Workaround

Pipe scan output through `jq` and use `context --fire` for specific details.

## Candidate Fix

Add bounded default scan JSON with counts, representative samples, and omitted metadata. Provide `--full` or `--output` for complete fire lists.

## Acceptance Criteria

- Large scan JSON remains bounded by default.
- `changed_count`, `open_fire_count`, and representative samples are present.
- Full data remains available explicitly.

## Evidence

- Initial algorithm import scan produced 219 changed atoms and 427 open fires, causing very large JSON output.
