# CFB-060: Context and explain unknown Atom errors ignore `--json`

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | automation-json |
| Area | context / explain |
| Observed while | probing Atom detail retrieval before `ExperimentRiskRegister` implementation |

## Observation

Unknown Atom selectors return plain text errors even when `--json` is requested.

## Reproduction

```bash
codefire context --atom DOES-NOT-EXIST --json
codefire explain atom DOES-NOT-EXIST --path . --json
```

## Why It Matters

Agents need to distinguish an unknown Atom from command failure or malformed JSON. The current behavior forces text parsing.

## Workaround

Only call context/explain with Atom IDs taken from `scan --json` or known trace links.

## Candidate Fix

Return a JSON envelope with diagnostic kind `unknown_atom` and a next action to run `scan --json` or inspect known Atom IDs.

## Acceptance Criteria

- Unknown selector errors produce JSON when `--json` is present.
- `diagnostics[0].kind` identifies the selector failure.
- Text mode behavior remains human-readable.

## Evidence

- Both commands returned `error: unknown atom: DOES-NOT-EXIST`.
