# CFB-003: Verify should separate policy warnings from blockers

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Diagnostics |
| Observed while | Running `verify` with `commit_policy.require_trace_completeness: false` |

## Observation

`verify` displayed missing required link counts even when trace completeness was not a blocking policy.

## Impact

Operators could mistake non-blocking trace warnings for the actual commit blocker, especially when stale resolutions or duplicate Atom IDs were the real problem.

## Fix

`verify` output now separates blocking checks from non-blocking warnings.

- Existing verify failure tests cover `Blocking checks:`.
