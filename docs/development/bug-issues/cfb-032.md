# CFB-032: Doctor reports a usable repository as invalid

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | compatibility |
| Area | `doctor` |
| Observed while | `algorithm-evolution-agent-lab` could scan, verify, and commit |

## Observation

`doctor . --quick --json` reports blocking layout errors for missing directories even though normal operations continue to work.

## Reproduction

```bash
codefire doctor . --quick --json
```

## Why It Matters

AI agents and CI may treat a usable repository as invalid and attempt unnecessary repairs.

## Workaround

Use `verify` and `commit` as final gates; check `migrate check` before repair.

## Candidate Fix

Downgrade auto-creatable optional directories to warnings, or align doctor validity with actual operation requirements.

## Acceptance Criteria

- Doctor does not mark a commit-capable repository invalid solely for optional missing directories.
- Blocking doctor issues correspond to real operation blockers.

## Evidence

- Doctor reported missing `.codefire/idempotency`, `objects/artifact_refs`, and `objects/evidence` while verify/commit worked.
- Fixed by routing doctor and migrate through a shared layout registry. Auto-creatable directories now report as non-blocking `missing_repairable_directory` / `missing_repairable_object_subdirectory` warnings.
- Regression: `doctor_checks_layout_active_state_and_open_marker_shape`; full `cargo test --workspace`; algorithm dogfood `codefire doctor --path . --quick --json` returned `ok:true`.
