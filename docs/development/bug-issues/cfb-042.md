# CFB-042: Branch command has no machine-readable listing

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | automation-json |
| Area | `branch` |
| Observed while | checking algorithm branch state |

## Observation

Help lists `branch`, but `branch --json` is unsupported.

## Reproduction

```bash
codefire branch --json
```

## Why It Matters

Branch management automation has to rely on internal JSON files.

## Workaround

Use `status --json` for current branch and inspect `.codefire/branches/*.json`.

## Candidate Fix

Add `branch list --json` and `branch show --json`, or align help with implemented subcommands.

## Fix

v0.8 added `branch list --json`. The global burn-down pass completed the remaining contract:

- `branch show [branch] --json` returns `codefire_branch_detail`.
- Without an explicit branch, `branch show --path <open-dir> --json` resolves the current branch from the open marker.
- The detail includes branch name, head, state, sealed validation status, and opened registry summary.
- Unsupported branch subcommands with `--json` return a `codefire.command_result.v1` error envelope.

## Acceptance Criteria

- Branch list/show has stable JSON output.
- Unsupported branch subcommands return JSON envelope when `--json` is requested.

## Evidence

- CLI returned `unsupported branch command: --json`.
- Partial regression coverage: `branch list` now accepts `--json` through the shared path/json parser and renders branch records in a command result envelope.

- Regression coverage: `branch_list_reads_repo_from_open_marker_and_validates_heads`, `command_help_routes_before_mutating_parsers`, `parse_diff_args_accepts_algorithm_forms`.
