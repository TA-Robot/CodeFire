# CFB-023: Common path option is missing on local workflow commands

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | path parsing |
| Observed while | returning to `algorithm-evolution-agent-lab` after v0.7 install |

## Observation

`status --path . --json`, `scan --path . --json`, and `verify --path . --json` failed with unsupported option errors, even though these commands all conceptually operate on a repository or open directory path.

## Reproduction

```bash
codefire status --path . --json
codefire scan --path . --json
codefire verify --path . --json
```

## Why It Matters

AI agents commonly preserve target paths in generated next steps. Requiring some commands to use positional paths and others to use `cd` makes automated recovery brittle.

## Workaround

Before v0.8, run the command from the target directory or use positional path forms where supported.

## Fix

v0.8 extends shared path parsing so `parse_path_json_args` accepts `--path <path>` and `--path=<path>`. `parse_verify_args` now accepts the same aliases for verify.

## Acceptance Criteria

- `status --path . --json` parses.
- `scan --path . --json` parses.
- `verify --path . --json` parses.
- The existing positional path form remains supported.

## Evidence

- Regression coverage: `parse_state_diagnostic_json_args`.
- Verification: `cargo test -p codefire-cli --bin codefire-rs -- --nocapture`.
