# CFB-009: Rust CLI command responsibilities can accumulate in main.rs

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | architecture / maintainability |
| Area | Rust CLI module boundaries |
| Observed while | reviewing v0.6 Rust command growth |

## Observation

Rust CLI feature work can drift into `main.rs` because dispatch, parsing, planning, domain mutation, and rendering historically lived close together.

## Impact

When new commands add logic directly to `main.rs`, invariants become harder to review and command-specific tests cannot sit near the implementation.

## Fix

- Added the `import` workflow as `crates/codefire-cli/src/import_workflow.rs` instead of expanding `main.rs` with command-specific parse and mutation logic.
- Kept `main.rs` responsible for dispatch and rendering the final command result envelope.
- Updated command registry, help, completion, CLI spec, and tests so new command surface is connected through the existing shared registries.
- Retained `docs/development/module-boundaries.md` as the development rule for future command additions.

## Close Evidence

- `import_workflow.rs` owns `parse_import_args`, `import_existing_project`, import plan generation, result JSON, and idempotency replay marker handling.
- Tests cover help routing, capabilities registry, dry-run, apply, status visibility, and idempotency replay for the new workflow.
