# CFB-006: Non-blocking trace completeness noise hides real blockers

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | UX / Trace completeness |
| Observed while | Using `verify --details` in `algorithm-evolution-agent-lab` with relaxed trace completeness |

## Observation

When trace completeness was configured as non-blocking, missing link diagnostics still dominated detailed verification output.

## Impact

The next action was hard to identify when the branch had real blockers such as open fires or stale resolutions.

## Fix

`verify --details --blocking-only` filters diagnostics, JSON data, and next actions to blocking items.

## Evidence

- Global burn-down confirmation for verification diagnostic filtering.
- `current-cycle-burn-down-plan.md` CFB-006 entry.
