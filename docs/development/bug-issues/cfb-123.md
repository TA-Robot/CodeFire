# CFB-123: directly edited Trace Links can retain dangling Atom references

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | bug |
| Area | Trace Graph / Atom reference integrity |
| Observed while | 2026-07-11 core-domain and canonical documentation audit |

## Original Observation

Before this fix, `codefire_core::current_trace_graph` parsed `codefire.links.yaml` into typed links but received no `AtomIndex` and therefore could not reject a `from` or `to` Atom ID that did not exist in the current index. Link batch mutation validated endpoints in its own path, but a direct file edit reached scan through the weaker constructor.

## Original Reproduction

The original counterexample added a syntactically valid Trace Link whose source or target Atom ID was
absent, then ran scan and verify. It is now an executable fixture and returns a structured
`trace_graph_endpoint_integrity` blocker.

## Why It Matters

The Trace Graph is used for required-link checks, Fire derivation, stale-resolution basis, and sealed commit roots. A syntactically valid dangling endpoint can create incomplete or misleading graph evidence and makes direct-edit behavior weaker than batch tooling.

## Historical Workaround

Before the fix, users needed the validated link-batch path and manual endpoint comparison before trusting a direct `codefire.links.yaml` edit. Direct edits now pass through the shared predicate at consumption.

## Chosen Fix

Add a domain-level graph-versus-Atom-index validator and invoke it in scan before Fire/verification derivation. Decide and version any intentional external/unresolved-link representation instead of treating an unknown endpoint as an ordinary valid link.

## Implemented Fix

`codefire_core::validate_trace_graph_endpoints` is now the shared domain predicate for Trace Link
endpoint integrity. It derives Atom-ID occurrence counts from the actual Atom list, checks both
`from` and `to`, and classifies zero matches as `missing_atom` and multiple matches as
`ambiguous_atom_id`. Its deterministic diagnostics retain total/omitted counts while bounding both
the issue count and UTF-8 samples.

Scan invokes the predicate immediately after constructing the current Atom index and Trace Graph,
before Fire or verification derivation and before mutable scan state is written. The same predicate is
used by required-link evaluation, direct trace-graph reads, context/Fire paths through scan or their
consuming boundary, and link-batch validation of both the existing and candidate graph. Sealed-commit
validation also cross-checks the Atom-index and Trace-Graph roots, so an ordinary dangling endpoint
cannot be accepted as a valid current sealed snapshot.

## Acceptance Criteria

- Scan/verify reject or explicitly classify dangling `from` and `to` endpoints.
- Direct edits and link-batch mutations share one endpoint-validity predicate and diagnostic taxonomy.
- A focused test covers missing source, missing target, duplicate Atom ID ambiguity, and valid links.
- Sealed Trace Graph roots cannot silently contain ordinary dangling endpoints under the supported profile.

## Evidence

- `crates/codefire-core/src/lib.rs::validate_trace_graph_endpoints` owns the common missing/ambiguous
  endpoint predicate and bounded diagnostic taxonomy.
- `crates/codefire-cli/src/main.rs::compute_scan_with_cache` validates the directly edited graph
  before reading Fire/state inputs or deriving scan output.
- `crates/codefire-cli/src/link_batch.rs::validate_links` applies the same predicate to the existing
  graph and each proposed candidate graph.
- `crates/codefire-store/src/lib.rs` cross-validates sealed `atom_index` and `trace_graph` roots as
  part of the sealed-commit contract.

## Regression Evidence

- `crates/codefire-core/src/lib.rs::trace_graph_endpoint_validator_reports_missing_source`,
  `trace_graph_endpoint_validator_reports_missing_target`,
  `trace_graph_endpoint_validator_reports_duplicate_atom_id_ambiguity`, and
  `trace_graph_endpoint_validator_accepts_uniquely_resolved_graph` cover the four primary domain
  outcomes.
- `crates/codefire-core/src/lib.rs::trace_graph_endpoint_validator_bounds_and_orders_large_diagnostics`
  and `trace_graph_endpoint_validator_byte_bounds_utf8_diagnostic_samples` cover deterministic,
  bounded failure output.
- `crates/codefire-cli/src/tests.rs::scan_rejects_a_directly_edited_trace_graph_with_a_dangling_endpoint`
  proves scan returns `trace_graph_endpoint_integrity` with repository/path context; context,
  required-link, and Fire consumers reject the same graph.
- `crates/codefire-cli/src/tests.rs::link_batch_reports_ambiguous_atom_ids_and_rejects_a_dangling_existing_graph`
  proves direct-edit and batch paths share the predicate without overwriting the invalid source file.
- `crates/codefire-store/src/lib.rs::validate_sealed_commit_rejects_dangling_trace_graph_endpoint`
  proves sealed snapshots cannot retain an ordinary dangling endpoint.
