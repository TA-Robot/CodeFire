# CFB-065: Remote upload dry-run envelope drops repo and next actions

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | automation-json |
| Area | remote upload dry-run |
| Observed while | checking missing remote upload plan |

## Observation

`codefire upload main cf:///tmp/no/such/remote/org/app --dry-run --json` returns a JSON envelope, but top-level `repo` is `null` even though `data.plan.repo` is set. The plan also contains `next_actions`, while the envelope top-level `next_actions` is empty.

## Reproduction

```bash
codefire upload main cf:///tmp/no/such/remote/org/app --dry-run --json
```

## Why It Matters

Automation expects common envelope fields to be meaningful across commands. If repository and next action metadata are nested inconsistently, command consumers need special cases for remote dry-run plans.

## Workaround

Fixed. Top-level `repo` and `next_actions` are now lifted from operation plans.

## Candidate Fix

Implemented. Plan repo and next actions are propagated into the command result envelope.

## Fix

- `plan_result_envelope` now reads `repo_root`, `repo`, or resolves `open_dir` to find the top-level `repo`.
- `data.plan.next_actions` is copied to top-level `next_actions`.
- Remote upload dry-run plans now expose top-level repository and list-remote next action.

## Acceptance Criteria

- Top-level `repo` is set when a local repository is involved.
- Top-level `next_actions` includes actionable plan next actions or an explicit reason it is empty.
- Regression test covers remote upload dry-run JSON envelope.

## Evidence

- Output had `repo: null`, `next_actions: []`, while `data.plan.repo` and `data.plan.next_actions` were populated.
- Fixed on 2026-06-10 in the global burn-down pass.
- Regression coverage: `legacy_plan_json_outputs_are_wrapped_in_command_result_envelope`, `file_remote_upload_clone_show_diff_and_merge_request_flow`.
