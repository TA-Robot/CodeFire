# CFB-025: Legacy `verification.required` policy wrapper is rejected

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | compatibility |
| Area | Policy YAML |
| Observed while | Upgrading an existing CodeFire-managed repository after limited YAML hardening |

## Observation

Older `codefire.policy.yaml` files used:

```yaml
verification:
  required:
    - id: unit
      command: cargo test
      cwd: .
```

The stricter parser rejected this with unsupported verification indentation.

## Impact

Existing repositories could become unverifiable after upgrading, even though the intended verification command was unambiguous.

## Fix

The core policy parser now accepts both the current direct list form and the legacy `verification.required` wrapper.

## Evidence

- `cargo test -p codefire-core verification_policy_accepts_legacy_required_wrapper -- --nocapture`
