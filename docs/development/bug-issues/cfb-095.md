# CFB-095: status next_actions omit scan when prediction has open fires

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | ux |
| Area | Status / Next actions |
| Observed while | `algorithm-evolution-agent-lab` cycle 10 dogfooding for `ResearchCyclePlanningPacketManifestBuilder` |

## Observation

After sealing `CF-COMMIT-738987cf39675353564e60da`, a follow-up formatting edit changed only the test atom `TEST-research-cycle-planning-packet-manifest-records-artifact-hashes`.

`codefire status --path subprojects/algorithm-evolution-agent-lab --json` returned:

- `state:"open-clean"`
- `open_fires:0`
- `scan_prediction.branch_state:"open-burning"`
- `scan_prediction.changed_count:1`
- `scan_prediction.changed_atom_count:1`
- `scan_prediction.open_fire_count:1`
- `next_actions:[]`

The recomputed preview already proved there was a changed atom and a predicted open fire, so `status --json` should have directed automation to run `scan --json` and `verify --details --json`.

## Reproduction

```bash
codefire commit -m "Add research cycle planning packet manifest" --path subprojects/algorithm-evolution-agent-lab --json
# edit a linked test atom under the open directory
codefire status --path subprojects/algorithm-evolution-agent-lab --json
```

## Why It Matters

AI or scripted automation follows `next_actions`. If `status --json` returns no actions while `scan_prediction` reports pending fires, an agent can incorrectly stop before materializing and extinguishing required trace-change fires.

This is separate from CFB-094: CFB-094 covered pending changes with zero predicted fires and should recommend `commit`. This issue covers pending changes with predicted fires and should recommend `scan` / `verify`.

## Workaround

Run `codefire scan --json --path ...` manually when `scan_prediction.changed_count > 0` and `scan_prediction.open_fire_count > 0`.

## Candidate Fix

Make `status_next_actions_with_prediction` trust the recomputed scan prediction for fire discovery:

- if predicted `changed_count > 0`
- and predicted `open_fire_count > 0`
- and stored `status.open_fires == 0`

then return `scan --json` and `verify --details --json` next actions.

## Acceptance Criteria

- `status --json` recommends `scan` and `verify` when prediction has pending changes and predicted open fires.
- `status --json` still recommends `commit` when prediction has pending changes and zero predicted open fires.
- clean status with no predicted changes still returns no next actions.
- A unit test covers the prediction-only open-fire case.

## Evidence

- Regression test: `automation::tests::clean_status_with_open_fire_prediction_suggests_scan_and_verify`.
- Targeted test run: `cargo test -p codefire-cli automation::tests::clean_status_with_open_fire_prediction_suggests_scan_and_verify`.
- Dogfood context: `algorithm-evolution-agent-lab` cycle 10 after `CF-COMMIT-738987cf39675353564e60da`.

## Fix

Implemented in cycle 10 burn-down.

- `status_next_actions_with_prediction` now returns scan and verify next actions when the preview predicts pending open fires.
- The existing commit prediction path remains unchanged for pending changes with zero predicted open fires.
