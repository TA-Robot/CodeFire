# CFB-125: object-store reuse does not compare a colliding new full digest

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | bug |
| Area | Object store / Truncated public ID collision |
| Observed while | 2026-07-11 canonical identity-invariant audit |

## Observation

`codefire_store::store_object` derives a 24-hex public object ID and returns early when that path already exists. It validates that the existing record is internally consistent with the shared public ID, but it does not compare the existing record's full digest, type, or payload with the newly requested record. The `AlreadyExists` hard-link race branch has the same gap. Two different full digests with the same truncated public ID can therefore make a write report success while the ID still resolves to the earlier payload.

## Reproduction

Use a deterministic digest/public-ID test seam to construct two different records with one public prefix. Store the first, then request the second through both the pre-existing-path branch and the hard-link `AlreadyExists` branch. Observe that current code validates only the first record and returns the shared ID.

## Why It Matters

Public IDs are intentionally shorter than full SHA-256 digests. Even if a natural 96-bit prefix collision is unlikely, identity correctness cannot depend on probability once the implementation encounters one. Silent aliasing can bind commits, evidence, or remote synchronization to a payload other than the caller requested.

## Workaround

Treat object writes from untrusted or independently produced stores as requiring explicit full-record comparison before reuse. Remote copy paths already compare complete records in some cases, but ordinary local `store_object` callers have no complete workaround without changing the store implementation.

## Candidate Fix

Before returning an existing public ID, require the existing and requested records to agree on type, full digest, canonical payload, and supported identity version. Otherwise return a typed collision error without replacing either object. Apply the same predicate to the race branch and use injected deterministic digest vectors rather than brute force in tests.

## Acceptance Criteria

- Idempotent same-record writes still reuse the existing object.
- Same-public-ID/different-full-digest writes fail with a typed collision diagnostic.
- Both the initial `path.exists()` path and the hard-link `AlreadyExists` path use one comparison predicate.
- Tests cover current 24-hex IDs, readable legacy 12-hex records, type mismatch, payload mismatch, and a deterministic artificial collision.
- Local, remote, migration, and sealed-reference consumers cannot turn a collision into silent aliasing.

## Fixed In

- `store_object_with_identity_and_link` now constructs the complete requested record before lookup. Both an already-present destination and the hard-link `AlreadyExists` race call the same `validate_existing_record_for_reuse` predicate.
- That predicate first validates the existing immutable record against its own full digest, public ID, filename, type, and canonical payload. It then calls `require_same_object_identity`, which permits reuse only when requested and existing type tags, 64-hex full digests, and canonical payload bytes all agree.
- A mismatch returns the typed `StoreError::ObjectCollision` without replacing the published object. The diagnostic includes the public object ID, requested/existing types and full hashes, plus whether canonical payloads matched; the CLI exposes it as blocking `object_id_collision` with the object-reference-invalid exit code.
- New objects continue to use the 24-hex public digest prefix, while validated legacy 12-hex records remain readable. Thus compatibility does not weaken the comparison required before a new write reports reuse.

Regression evidence in `crates/codefire-store/src/lib.rs`:

- `store_object_writes_and_reuses_immutable_record` preserves idempotent same-record reuse.
- `object_reuse_requires_type_hash_and_canonical_payload_identity` covers type, full-hash, and payload mismatch through the shared predicate.
- `store_object_rejects_artificial_collision_at_existing_path` and `store_object_rejects_artificial_collision_after_link_race` use an injected digest function to cover both publication branches without brute force.
- `store_object_rejects_canonical_payload_mismatch_even_when_full_hash_matches` proves a full-hash test seam cannot bypass canonical-payload equality, and `store_object_reports_corrupt_existing_record_before_collision` keeps corruption distinct from collision.
- `read_object_accepts_legacy_twelve_hex_object_ids` preserves the documented legacy read policy. `integrity_errors_use_typed_bounded_json_diagnostics_with_subject_context` in `crates/codefire-cli/src/tests.rs` covers the bounded machine-readable collision diagnostic.
