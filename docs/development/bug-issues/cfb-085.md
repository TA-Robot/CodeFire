# CFB-085: context, explain, and migrate top-level help return unsupported errors

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | ux |
| Area | CLI Help / Recovery |
| Observed while | probing command discovery surfaces during CodeFire improvement cycle 2 |

## Observation

Several read-only or recovery commands do not route `--help` to usage text:

```text
codefire migrate --help  -> error: unsupported migrate command: --help
codefire context --help  -> error: unsupported context option: --help
codefire explain --help  -> error: unsupported explain option: --help
```

These commands have non-trivial subcommand/selector syntax, so help is especially important.

## Reproduction

```bash
codefire migrate --help
codefire context --help
codefire explain --help
```

## Why It Matters

AI agents often recover from failed commands by asking for help. If help itself fails, the agent has to search source/docs or guess syntax. This slows dogfooding and increases the chance of repeated invalid commands.

## Workaround

Use known syntax from docs or source:

```bash
codefire migrate check <path> --json
codefire context --changed --path <open-dir> --json
codefire explain verify-failure --path <open-dir> --json
```

## Candidate Fix

Extend shared help routing to `migrate`, `context`, and `explain`, including top-level usage and selector/subcommand examples.

## Acceptance Criteria

- `migrate --help`, `context --help`, and `explain --help` return usage text with exit 0.
- help includes supported path/json flags and examples.
- parser tests ensure help routes before unsupported-option errors.
