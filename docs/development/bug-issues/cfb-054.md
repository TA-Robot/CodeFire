# CFB-054: `context --changed --json` can return a stale clean active scan after edits

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | bug |
| Area | context / active scan freshness |
| Observed while | adding `ExperimentIterationPlanner` in `algorithm-evolution-agent-lab` |

## Observation

After editing algorithm docs and source files, `codefire context --changed --json` returned the previous active scan with `branch_state: open-clean`, empty changed atoms, and empty fires. Running `codefire scan --json --metrics` then updated the active scan to `open-burning` with four changed atoms and six open fires.

## Reproduction

```bash
cd subprojects/algorithm-evolution-agent-lab
# edit files without running scan
codefire context --changed --json
codefire scan --path . --json --metrics
codefire context --changed --json
```

## Why It Matters

`context --changed` is a natural first command for an AI agent after edits. Returning a stale clean snapshot can make the agent believe no CodeFire work is needed, skipping scan, fire resolution, evidence capture, or verify.

## Workaround

Always run `codefire scan --json` before `codefire context --changed --json`.

## Candidate Fix

Context should verify active scan freshness against working tree metadata or current Atom hashes. If freshness is unknown or stale, it should either recompute a preview or emit a diagnostic requiring `scan`.

## Acceptance Criteria

- After file edits, `context --changed --json` never silently reports a stale clean snapshot.
- Result JSON includes `snapshot_fresh: true|false|unknown`.
- Stale context output includes a machine-readable next action to run scan.

## Evidence

- Before scan, context returned active `open-clean` with no changed atoms.
- After scan, the same command returned `open-burning`, four changed atoms, and six open fires.
