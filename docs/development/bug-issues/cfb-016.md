# CFB-016: Status must not report clean when fires are open

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | bug |
| Area | UX / State Label |
| Observed while | Scanning `LearningCurveAnalyzer` and `CandidatePromotionPolicy` changes |

## Observation

After `scan` created open fires, `status` could show `open-clean` with a positive open fire count.

## Impact

`open-clean` strongly implies no action is required, so this state could cause an operator or automation loop to skip fire handling.

## Fix

Status derivation rejects `open-clean` whenever open fires are present.

- Global burn-down state reducer fixes.
