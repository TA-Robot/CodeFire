# CFB-038: Evidence add result lacks captured output summary

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | medium |
| Type | automation-json |
| Area | `evidence add` |
| Observed while | investigating failed command evidence |

## Observation

Evidence add JSON returns IDs and exit metadata but not stdout/stderr summary, truncation, or object path.

## Reproduction

```bash
codefire evidence add --from-command '<command>' --label runbook-test --json
```

## Why It Matters

Automation cannot quickly decide whether the evidence is useful without reading object internals.

## Workaround

Find and inspect the evidence object in `.codefire/objects`.

## Candidate Fix

Include stdout/stderr preview, truncation flags, object path, and artifact_ref status in result data.

## Fix

v0.8 adds `object_path`, bounded stdout/stderr summaries, and truncation flags to `EvidenceAddResult`, `evidence_add_data_json`, and batch evidence result JSON.

## Acceptance Criteria

- Evidence add JSON exposes enough summary to audit the evidence immediately.
- Large output remains bounded with truncation metadata.

## Evidence

- Result contained `evidence_id`, `command_exit_code`, and `command_timed_out`, but no output summary.
- Regression coverage: `evidence_add_records_artifact_ref_and_command_capture`.
- Verification: `cargo test -p codefire-cli --bin codefire-rs -- --nocapture`.
