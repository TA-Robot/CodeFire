# CFB-050: Batch extinguish dry-run JSON is unbounded for large batches

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | medium |
| Type | automation-json |
| Area | extinguish --batch |
| Observed while | extinguishing 427 initial-import fires in `algorithm-evolution-agent-lab` |

## Observation

`codefire extinguish --batch <file> --dry-run --json` emits every item and every nested single-fire validation plan. For 427 fires, the JSON output became extremely large.

## Reproduction

```bash
codefire extinguish --batch /tmp/algorithm_initial_import_extinguish.json --path . --dry-run --json
```

## Why It Matters

Automation needs a bounded dry-run summary to decide whether a batch is valid. Very large JSON can exceed log, terminal, or agent context limits and hides the actual result.

## Workaround

Pipe through `jq` to keep only `item_count` and `operations`, or run non-dry-run only after manually trusting generated input.

## Candidate Fix

Bound batch dry-run output. Include aggregate counts and first N validation examples, with `omitted` metadata and a separate export option for full validation detail.

## Acceptance Criteria

- Large batch dry-run JSON remains bounded by default.
- Output includes `item_count`, validation error counts, and representative examples.
- Full detail remains available via explicit `--full` or `--output`.

## Evidence

- 427-fire dry-run produced tens of thousands of JSON lines and required output truncation by the execution environment.
