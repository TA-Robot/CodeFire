# CFB-110: branch open allows nested open directories

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | Safety bug |
| Area | Branch open / Nested open dir guard |
| Observed while | algorithm branch boundary dogfood |

## Observation

`codefire open` accepts a target path under an existing open directory when the target does not exist yet. The dry-run plan treats this as a normal materialization target.

## Reproduction

From the algorithm main open directory:

```bash
codefire open feature/name-ci-note-section \
  /workspace/project/subprojects/algorithm-evolution-agent-lab/tmp-nested-feature \
  --dry-run --json
```

The command returns `ok:true` and plans to materialize the closed feature branch inside the already-open `main` worktree.

## Why It Matters

If applied, this would create a full branch worktree inside the main open directory. The main branch would then see that nested tree as ordinary unsealed files, producing noisy scans, confusing cleanup, and a high risk of committing unrelated branch contents.

## Workaround

Open feature branches only as sibling directories under the CodeFire repo root, for example `/workspace/project/subprojects/algorithm-evolution-agent-lab-feature-...`.

## Candidate Fix

Before planning or applying `open`, check whether the target path is inside any existing `.codefire-open` directory. Reject nested targets and return a path-aware next action with a safe sibling directory suggestion.

## Acceptance Criteria

- `open <branch> <open-dir-child> --dry-run --json` returns `ok:false`.
- The diagnostic identifies the containing open directory and branch.
- The JSON envelope includes repo and a safe suggested sibling target.
- Tests cover nested target rejection before filesystem writes.

## Evidence

- 2026-06-12 dry-run accepted `/workspace/project/subprojects/algorithm-evolution-agent-lab/tmp-nested-feature` as an `open` target.
