# CFB-114: close trusts stale last_known state and can discard unscanned work

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | bug |
| Area | Branch lifecycle / Close safety |
| Observed while | CodeFire close implementation review after branch-per-feature dogfood |

## Observation

`close_branch` reads `state.last_known` from the open registry and allows a non-discard close when that value is `open-clean`.

It does not recompute scan state, compare the open directory manifest to the sealed head, or check whether files changed after the last status/scan/verify command. If a user edits an open-clean feature directory and immediately runs `codefire close <branch>`, the registry can still say `open-clean`, and close plans removal of the open directory without requiring `--discard`.

## Reproduction

Code path review:

```bash
rg -n "fn close_branch|last_known|remove_open_dir_marker_or_tree" crates/codefire-cli/src/main.rs
```

Control flow:

```text
close_branch:
  registry = read_json(opened/<branch>.json)
  state = registry["state"]["last_known"]
  if state != "open-clean" && !discard: reject
  remove_open_dir_marker_or_tree(...)
```

There is no scan or manifest freshness check between reading `last_known` and removing the directory.

## Why It Matters

The branch-per-feature workflow creates disposable open directories, so close must be conservative. Losing unsealed work because the registry state is stale is worse than forcing the operator to run one extra status or scan. This is especially risky for agents because they often follow next actions and may not inspect the filesystem diff manually.

## Workaround

Before running `close`, explicitly run:

```bash
codefire status --path <open-dir> --json
codefire verify --details --json --path <open-dir>
```

Only close when the recomputed state is clean and there are no pending changes. Use `--discard` only when intentionally deleting unsealed work.

## Candidate Fix

Make `close` perform a freshness check before allowing non-discard close:

- recompute a read-only scan prediction or manifest diff;
- reject non-discard close when any Atom or non-Atom change exists;
- include a `commit` or `discard` recovery next action;
- keep `--discard` explicit and noisy for destructive cleanup.

## Acceptance Criteria

- If files changed after the last registry update, `close <branch>` without `--discard` rejects.
- `close --dry-run` reports the recomputed pending-change state.
- `close --discard` still works but clearly marks that unsealed work will be removed.
- Tests cover stale `last_known: open-clean` with modified files in the open directory.

## Evidence

- `crates/codefire-cli/src/main.rs::close_branch` reads `state.last_known` and gates only on that stored value.
- `remove_open_dir_marker_or_tree` removes the directory after marker/repo validation and does not inspect content changes.
