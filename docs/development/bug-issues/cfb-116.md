# CFB-116: merge trusts stale target open-clean state

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | bug |
| Area | Merge / Target branch safety |
| Observed while | CodeFire merge implementation review after branch-per-feature dogfood |

## Observation

`build_merge_result` requires the target branch to be open and checks `registry["state"]["last_known"] == "open-clean"`. It does not recompute the target open directory state before planning or applying the merge.

If the target open directory has unscanned edits while the registry still says `open-clean`, `merge <source> --into <target>` can plan against the sealed target head and then write source files into the dirty open directory.

## Reproduction

Code path review:

```bash
rg -n "fn build_merge_result|target branch must be open-clean|last_known" crates/codefire-cli/src/main.rs
```

Control flow:

```text
build_merge_result:
  target = load_branch_record(...)
  target_head = target["head"]
  registry = read_json(opened/<target>.json)
  require registry["state"]["last_known"] == "open-clean"
  plan file actions from sealed target_head
```

There is no target worktree scan or manifest freshness check before merge actions are produced.

## Why It Matters

Merge is one of the highest-risk branch lifecycle commands because it writes into the target open directory. A stale clean registry can cause unsealed target work to be ignored or overwritten. This undermines the branch-per-feature workflow where main remains the integration target.

## Workaround

Before merge, always run:

```bash
codefire status --path <target-open-dir> --json
codefire verify --details --json --path <target-open-dir>
```

Only merge into a target that is recomputed clean, not merely recorded as clean.

## Candidate Fix

Make merge recompute or validate target freshness before planning file actions:

- compare target open directory manifest to target branch head;
- reject merge if any pending target changes exist;
- include target status/commit/discard next actions in JSON errors;
- use the open registry only as a pointer to the target directory, not as the source of truth for cleanliness.

## Acceptance Criteria

- Merge dry-run rejects a target with unscanned local edits even if registry `last_known` is `open-clean`.
- Merge apply cannot overwrite unsealed target edits without an explicit destructive option.
- JSON diagnostics identify the target open dir and pending changed files or Atom counts.
- Tests cover stale-clean target registry with modified target files.

## Evidence

- `crates/codefire-cli/src/main.rs::build_merge_result` checks only stored `state.last_known` before planning merge.
- File actions are derived from sealed manifests for base/source/target commits, not from the current target working tree.

## Fixed In

- CFB-105..CFB-119 burn-down: implemented branch lifecycle guards, merge freshness checks, remote clone dry-run/state safety, Markdown process-ID filtering, and non-Atom change visibility.
