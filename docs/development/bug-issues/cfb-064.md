# CFB-064: Remote read commands do not support JSON output

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | automation-json |
| Area | remote list / request-list |
| Observed while | checking remote read command failure paths |

## Observation

`list <remote> --json` and `request-list <remote> --json` reject `--json` as an unsupported option and print plain text errors.

## Reproduction

```bash
codefire list cf:///tmp/no/such/remote/org/app --json
codefire request-list cf:///tmp/no/such/remote/org/app --json
```

## Why It Matters

Remote branch and merge request listing are important for automation. Without JSON, agents cannot reliably inspect remote state or handle remote errors.

## Workaround

Fixed. Use `codefire list <remote> --json` and `codefire request-list <remote> --json`.

## Candidate Fix

Implemented JSON envelopes for remote read commands with structured remote target diagnostics.

## Fix

- `list <remote-project-url> --json` returns `codefire_remote_branch_list`.
- `request-list <remote-project-url> --json` returns `codefire_merge_request_list`.
- Missing/invalid remote JSON mode returns `ok:false` command_result envelopes.
- Text output remains unchanged for existing scripts.

## Acceptance Criteria

- `list --json` returns branches or remote diagnostics.
- `request-list --json` returns merge requests or remote diagnostics.
- Unsupported/failure paths are structured.

## Evidence

- Both commands returned `error: unsupported option: --json`.
- Fixed on 2026-06-10 in the global burn-down pass.
- Regression coverage: `file_remote_upload_clone_show_diff_and_merge_request_flow`.
