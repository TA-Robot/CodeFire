# CFB-134: Rust default doctorがremote URLをlocal pathとして扱う

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Area | Doctor / Remote capability routing |
| Observed while | CFR-162 Retrospect後のnext-discovery replay |

## Problem

Rust defaultの`codefire doctor cf://server/org/app --json`はremote URLをlocal repository探索へ渡し、
`io_error` / exit 1を返す。known-limitationsとrunbookはfile/HTTP remote doctorを実装済みsurfaceとして
列挙し、Python fallbackは同じ引数をremote診断へrouteするため、default CLIのcapability claimと実装が
矛盾する。

## Reproduction Evidence

fresh installed `/tmp/codefire-cfr162-closed.YMG1ed/bin/codefire`で
`doctor cf://example/org/app --json`を実行した結果を
`/tmp/codefire-doctor-remote-candidate.json`へ保存した。process/envelopeはexit 1、diagnostic kindは
`io_error`で、remote URL固有の診断やunsupported capabilityではない。

## Root Cause and Deduplication

top-level doctor dispatchはlocal `parse_doctor_args` / `run_doctor`しか持たず、remote URL capabilityを
registry、parser、file/HTTP transportへ接続していない。RVC-022/032/033/053/055/057/059の
version-capability-conformance rootへ統合し、Python fallbackだけをdefault contractとして扱わない。

## Acceptance Criteria

- `cf://` file remoteとsupported HTTP(S) remoteをURLとしてparseし、local path discoveryへ渡さない。
- healthy/corrupt/missing remoteでtyped JSON envelope、stable exit、bounded diagnosticsを返す。
- remote branch/MR/object sealed-reference validationがlocal doctorと同じsupported semantic profileを使う。
- help、capabilities、runbook、Python compatibility fixtureが実装surfaceと一致する。
- unsupported transport/profileは`io_error`ではなく明示的capability/version errorになる。

## Test Plan

- Python-created remote fixtureとRust default read compatibility。

## Resolution Evidence

Rust top-level Doctorはtargetをlocal discovery前に分類し、`cf://`をshared file-project gate、
`cf+http://` / `cf+https://`を`GET /v1/projects/{org}/{app}/doctor`へrouteする。missing projectも
`codefire.command_result.v1`内の`codefire.remote_doctor.v1` reportとexit 20になり、repoはnullである。

fresh installed `/tmp/codefire-cfr166-final.zpGltd/bin/codefire`でmissing/healthy/corrupt/future file
projectとPython HTTP fallbackを確認した。旧`io_error`経路は再現せず、future branchはtyped
`remote_record_version_unsupported`、stale/corrupt referencesはtyped issuesになる。Rust 613、Python
117、demo、Algorithm 281、docs/install gatesがpassし、証跡は`/tmp/codefire-cfr166-reversal.9AYMuY`にある。

RetrospectでPython Doctorのsealed-ref count回帰を検出し、future versionは意味解釈しない一方、current
versionのinvalid headはsealed-reference diagnosticとして保持するよう修正した。新規issueはない。
