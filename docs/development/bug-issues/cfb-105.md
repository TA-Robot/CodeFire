# CFB-105: close/discard can close the primary main branch open directory

## Summary

| Field | Value |
|---|---|
| Status | fixed |
| Severity | high |
| Type | bug |
| Area | Branch lifecycle / Primary branch safety |
| Observed while | algorithm branch lifecycle dry-run probe after installing branch workflow fixes |

## Observation

`close main --dry-run --json` and `discard main --dry-run --json` both return successful operation plans that remove the main open directory and mark `main` closed.

The plan targets `/workspace/project/subprojects/algorithm-evolution-agent-lab`, which is the normal algorithm development open directory.

## Reproduction

```bash
cd /workspace/project/subprojects/algorithm-evolution-agent-lab
codefire close main --dry-run --json
codefire discard main --dry-run --json
```

Both commands report `ok:true` and include operations like:

```text
remove_open_directory /workspace/project/subprojects/algorithm-evolution-agent-lab
update_branch_state main closed
```

## Why It Matters

Branch-per-feature workflows need a stable primary branch open directory to receive merges and start new feature branches. Accidentally closing or discarding that branch can remove the default working target and leave users without an obvious safe recovery path.

## Workaround

Do not run `close` or `discard` against `main`. Use these commands only for feature branches after their work is sealed and merged.

## Candidate Fix

Add a guard for primary/default branches and possibly for the last open branch in a local repo. Closing or discarding such a branch should require an explicit override such as `--force-primary` and should emit a clear warning in dry-run and JSON diagnostics.

## Acceptance Criteria

- `codefire close main --dry-run --json` rejects by default with a structured diagnostic.
- `codefire discard main --dry-run --json` rejects by default with a structured diagnostic.
- The diagnostic includes a safe next action, such as opening/using a feature branch or passing an explicit force flag.
- A force flag, if added, is documented and tested.

## Evidence

- 2026-06-12 dry-run probe on algorithm repo returned successful plans for both `close main` and `discard main`.
- Both plans included `remove_open_directory` for the main open dir and `update_branch_state main closed`.
