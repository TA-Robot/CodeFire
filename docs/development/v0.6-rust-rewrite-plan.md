# CodeFire v0.6 Rust Rewrite Plan

この計画は、現在のPython MVPを仕様oracleとして残しつつ、v0.6でRust実装へ移行するための開発計画である。

v0.6の目的は「速い同等品」ではなく、CodeFireを実プロジェクト管理に使い続けられる品質へ上げること。特にdogfoodingで見えたUX、診断ノイズ、性能可観測性、object store肥大化リスクを、Rust再設計の初期制約として扱う。

## Goals

- Rustで再実装した `codefire` CLIを提供する。
- 既存Python版のrepository、object store、sealed commit、trace/fire/verify/remote互換性を維持する。
- 主要操作を高速化し、phase別metricsを標準で観測できるようにする。
- fire解消、verify診断、large artifact運用を高機能化する。
- Rust crate分割により、CLI、core model、storage、indexer、remote server、policy engineを独立してテストできるようにする。

## Product Vision

v0.6のCodeFireは、Gitの代替ではなく「仕様、設計、コード、テスト、実験証跡を一貫性のある研究/開発履歴として封印するツール」として位置付ける。

特に以下の利用者を想定する:

- 仕様駆動でソフトウェアを作る開発者
- 自動化された変更や人間の変更に対して、要求と検証の整合性を保ちたい管理者
- ML/研究系プロジェクトで大量の実験、仮説、結果、証跡を扱う研究者
- remote/server上で署名、検証、監査ログを要求するチーム

v0.6では、CodeFireの強みを次の3点に絞って磨く。

- Traceability: `REQ -> DES -> CODE -> TEST -> EVIDENCE` を機械的に追える。
- Consistency: open fire、stale resolution、duplicate Atom、policy violationをcommit前に止める。
- Operability: CLIだけで診断、解消、性能測定、storage管理、migration確認ができる。

## Success Metrics

| Metric | v0.2 observed / current | v0.6 target |
|---|---:|---:|
| `status` on small repo | about 0.4s | under 0.1s |
| `scan` on small repo | about 0.45s | under 0.2s |
| `verify --details` on small repo | about 1.2s | under 0.5s excluding user verification commands |
| batch fire extinguish | manual shell commands | one interactive or batch session |
| diagnostics noise | missing links mixed with blockers | blocker/warning/info grouped output |
| object store visibility | manual `du` / `find` | `codefire storage report` |
| Python/Rust compatibility | not applicable | golden fixture parity for every object type |
| release confidence | Python unittest/demo | Rust tests + Python parity + migration check |

## v0.6 User Stories

| User | Story | Acceptance |
|---|---|---|
| Repository owner | I can migrate an existing Python-created CodeFire repo to Rust tooling without changing object IDs | `codefire-rs migrate check` reports compatible and no object hash drift |
| Project manager | I can see only commit blockers when early specification work creates many non-blocking missing links | `codefire verify --details --blocking-only` hides non-blocking diagnostics |
| Implementer | I can extinguish a batch of related fires using one rationale and test evidence | batch extinguish updates all matching fires and records shared evidence |
| Researcher | I can keep model/checkpoint artifacts outside `.codefire` while preserving hashes and references | external artifact refs are sealed and `storage report` excludes payload bytes |
| Maintainer | I can tell why scan is slow | `codefire scan --metrics` prints phase timings and cache stats |
| Server operator | I can audit remote mutation requests and GC decisions | server audit log has stable schema and signature verification result |

## Non-Goals

- v0.6でGUIを完成させること。
- 既存object formatを破壊的に変更すること。
- Git互換の全機能を目指すこと。
- ML実験artifact本体をCodeFire object storeに無制限保存すること。
- AI agentの起動、編成、分業、実行管理、プロンプト管理、reviewer/implementer orchestrationをCodeFire機能として実装すること。
- plugin marketplace、policy marketplace、template marketplace、artifact marketplaceなどのmarketplace機能を実装すること。

## Permanent Product Exclusions

以下はv0.6だけでなく、今後のCodeFire本体機能としても扱わない。

- AI agent orchestration
- AI agent workspace management
- AI prompt / role / task marketplace
- plugin marketplace
- policy marketplace
- hosted template marketplace

CodeFireは、外部ツールや人間が行った変更をAtom、Trace Link、Fire、Verification、Sealed Commitとして管理する。外部AI agentを使う場合も、CodeFireはその実行基盤や運用UIにはならず、整合性管理と履歴封印だけを担当する。

## Compatibility Policy

v0.6 Rust版は、既存Python版で作成したrepositoryを読み書きできることを必須にする。

- object ID、canonical JSON、branch head、open registry、sealed commit validationは互換。
- Rust版で作ったcommitをPython版が最低限 `doctor` / `show` できる状態を維持する。
- format変更が必要な場合は、object payloadにversioned extensionを追加し、既存fieldの意味を変えない。
- Python版はv0.6期間中、reference implementation / migration checkerとして残す。

Compatibility levels:

| Level | Meaning | Required by |
|---|---|---|
| Read compatibility | Rust can read Python-created repo and validate object graph | v0.3 |
| Display compatibility | Rust can `status` / `show` / `diff` Python-created repo | v0.3-v0.4 |
| Write compatibility | Rust can create objects Python can validate | v0.4 |
| Remote compatibility | Rust CLI and server can exchange bundles with Python fixtures | v0.5 |
| Operational compatibility | installer, completion, docs, runbook support Rust default + Python fallback | v0.6 |

Compatibility fixtures:

```text
fixtures/
  compat/
    python-v0.2-empty/
    python-v0.2-local-commit/
    python-v0.2-merge-fire/
    python-v0.2-remote-mr/
    python-v0.2-signed-remote/
    rust-v0.6-local-commit/
```

## Rust Workspace

想定workspace:

```text
crates/
  codefire-cli/          CLI entrypoint, shell completion, human output
  codefire-core/         Atom, TraceGraph, Fire, Resolution, Verification domain model
  codefire-store/        canonical JSON, object IDs, immutable object store, GC
  codefire-index/        Markdown/code/OpenAPI/SQL extractors
  codefire-policy/       required links, commit policy, verification planning
  codefire-remote/       file/http/https remote protocol, auth, signatures
  codefire-server/       hosted/server-side verification boundary
  codefire-testkit/      fixtures, parity harness, golden repository helpers
```

Crate responsibilities:

| Crate | Owns | Must not own |
|---|---|---|
| `codefire-cli` | argument parsing, output formatting, editor prompts, shell completion | object hashing, policy decisions |
| `codefire-core` | domain structs, typed IDs, graph model, common errors | filesystem layout |
| `codefire-store` | canonical JSON, object IDs, object graph traversal, locks, GC primitives | CLI formatting |
| `codefire-index` | Atom extraction, incremental cache, extractor diagnostics | policy evaluation |
| `codefire-policy` | required links, commit policy, diagnostics severity, remediation hints | command execution side effects |
| `codefire-remote` | remote bundle protocol, auth/signature verification, MR state | HTTP server framework |
| `codefire-server` | HTTP/HTTPS routes, request limits, server-side verification sandbox | core object semantics |
| `codefire-testkit` | fixtures, parity runner, golden object assertions | product behavior |

依存方針:

- CLI: `clap`
- serialization: `serde`, `serde_json`
- diagnostics: `miette` または `anyhow` + structured error enum
- hashing/signature: vetted crates only; object hash algorithmは既存仕様に合わせる
- async server: `tokio` + `axum` はremote serverが必要になった段階で導入する
- YAML: `serde_yaml` か `yaml-rust2` を比較し、既存limited YAMLとの差分を明示する

## Architecture Flow

```text
workspace files
  -> codefire-index
      -> AtomIndex + extractor diagnostics
  -> codefire-policy
      -> TraceGraph + PolicyDiagnostics
  -> codefire-core
      -> FireLedger + ResolutionLedger + Verification
  -> codefire-store
      -> content-addressed objects + sealed commit
  -> codefire-cli / codefire-remote / codefire-server
      -> human output, JSON output, remote protocol, audit log
```

Write path rules:

- domain objects are built before filesystem writes
- object hashing happens only inside `codefire-store`
- branch head updates are atomic and lock-protected
- remote apply validates sealed commit ancestry before mutation
- server-side verification never trusts client-provided verification status

## Data Model Enhancements

v0.6 should preserve current object payloads and add extension objects where needed.

Candidate additions:

| Object / Record | Purpose | Compatibility approach |
|---|---|---|
| `diagnostic_report` | structured verify/scan diagnostics with severity and remediation | new optional root reference |
| `performance_report` | phase timings and cache stats for operations | active state and optional commit metadata |
| `artifact_ref` | external artifact URI/path/hash/size metadata | new object linked from evidence or verification |
| `migration_report` | compatibility check result | command output and optional object |
| `policy_profile` | named policy overlays for early spec / release modes | parse from policy config; do not alter old booleans |

Structured diagnostic shape:

```json
{
  "rule_id": "trace.required_link.missing",
  "severity": "warning",
  "blocking": false,
  "atom_id": "REQ-PRODUCT-018",
  "message": "Missing verified_by test link",
  "next_actions": [
    {"command": "codefire link add ...", "kind": "add_link"}
  ]
}
```

v0.6 targets:

- `codefire extinguish --interactive`
- `codefire extinguish --batch fires.yaml`
- 複数fireを同じrationale/evidenceで解消する `--all-matching`
- 直近verification/test commandの結果をevidence候補として提示
- editor連携: `$EDITOR` でrationale/evidence draftを編集

Target CLI examples:

```bash

  --resolution changed \
  --evidence-from last-verify

```

Batch file draft:

```yaml

  resolution: changed
  evidence: "cargo test --workspace: passed"
```

### 5. Indexer Reliability

v0.6 targets:

- tree-sitter-based optional extractors for common languages
- fallback lightweight extractors for no-dependency mode
- extractor diagnostics per file
- stable derived Atom IDs with owner/context namespace
- incremental scan cache keyed by file path, mtime, size, and content hash

Extractor modes:

| Mode | Behavior | Use |
|---|---|---|
| `fallback` | regex/lightweight parser, no heavy dependencies | default portable install |
| `tree-sitter` | syntax-aware extraction for supported languages | high accuracy mode |
| `explicit-only` | only `cf-atom` comments and Markdown headings | emergency or huge repo mode |

### 6. Policy Engine

v0.6 targets:

- policy evaluation as structured rule results
- rule IDs and user-facing remediation text
- profile support:

```yaml
profiles:
  early_spec:
    require_trace_completeness: false
  release:
    require_trace_completeness: true
```

- per-branch and per-remote policy overlays

Policy result requirements:

- every rule has stable `rule_id`
- every failed rule has severity
- every commit blocker identifies the policy key that made it blocking
- `verify --json` exposes the same rule results used by human output
- non-blocking diagnostics are preserved for reports but do not obscure blockers

### 7. Remote and Server Hardening

v0.6 targets:

### 9. Automation-Friendly Interface

This is not AI agent orchestration. CodeFire does not start, schedule, supervise, or coordinate agents. This feature set only makes CodeFire safe and predictable for any external automation tool, script, CI job, editor integration, or human wrapper.

v0.6 targets:

- stable `--json` output for state, diagnostic, context, plan, and result commands
- schema version for every JSON output
- stable exit code taxonomy
- `codefire context`
- machine-readable `next_actions`
- dry-run / operation plan output for mutating commands
- batch file support for links, fires, extinguish, evidence, and artifacts
- idempotency keys for mutating local/remote commands
- lock-safe automation through `--wait-lock` and `--lock-timeout`
- evidence capture API
- read-only `codefire explain`

Core commands:

```bash
codefire status --json
codefire verify --details --blocking-only --json
codefire context --fire FIRE-001 --json
codefire context --atom REQ-PRODUCT-018 --depth 2 --json
codefire commit --dry-run --json
codefire extinguish --batch fires.yaml --dry-run --json
codefire evidence add --from-command "cargo test --workspace" --json
codefire explain verify-failure --json
```

JSON output envelope:

```json
{
  "schema": "codefire.command_result.v1",
  "command": "verify",
  "ok": false,
  "exit_code": 10,
  "repo": "/workspace/example",
  "data": {},
  "diagnostics": [],
  "next_actions": []
}
```

Exit code taxonomy:

| Code | Meaning |
|---:|---|
| 0 | success |
| 1 | generic user-facing failure |
| 2 | invalid CLI usage or invalid config |
| 10 | open fires block operation |
| 11 | blocking required links are missing |
| 12 | stale resolution blocks operation |
| 13 | duplicate Atom ID blocks operation |
| 14 | verification command failed |
| 15 | merge conflict blocks operation |
| 20 | repository corruption detected |
| 21 | object hash or object reference invalid |
| 22 | sealed commit validation failed |
| 30 | lock contention |
| 31 | remote rejected request |
| 32 | authentication or signature failure |
| 33 | idempotency conflict |
| 40 | migration incompatibility |
| 50 | external artifact missing or hash mismatch |

Automation safety rules:

- human output may change; JSON schema changes require versioning
- every mutating command has either `--dry-run` or an explicit plan/apply path
- same idempotency key + same payload returns the previous result
- same idempotency key + different payload returns exit code 33
- lock timeout returns exit code 30 with lock owner metadata where available
- batch files validate all items before mutation unless `--continue-on-error` is explicitly supported

### 10. Diff and Merge Intelligence

Current CodeFire diff/merge is intentionally minimal: common ancestor search, file-level 3-way merge, conflict markers, and merge fires. This is enough for MVP consistency, but it is not as rich as Git's mature diff machinery.

Git is stronger today in:

- Myers/patience/histogram-style line diff quality
- rename/copy detection
- binary file handling
- patch generation and apply workflows
- decades of merge heuristic hardening
- interactive staging and review ergonomics

CodeFire should not try to clone all Git behavior. v0.6 should combine a credible text diff baseline with CodeFire-specific semantic and trace-aware analysis.

v0.6 targets:

- pluggable diff algorithms: Myers baseline, patience diff, histogram-style diff
- word-level and intra-line highlights for human review
- rename and copy detection using similarity score
- directory move detection as a derived diagnostic
- binary file classification and external artifact diff summary
- structured diff output with `--json`
- Atom-level diff: added/removed/changed Atom IDs
- TraceGraph diff: added/removed/changed links and missing-link impact
- Fire impact diff: which fires would be created, obsoleted, or refreshed
- Policy impact diff: which policy rules changed blocker status
- semantic conflict candidates without automatic semantic merge
- merge prediction: dry-run merge summary before writing files
- patch export/import for review and remote workflows
- review pack: combined file diff, Atom diff, TraceGraph diff, verification summary, and next actions

Target commands:

```bash
codefire diff main feature --algorithm patience
codefire diff main feature --rename-detection --json
codefire diff --atoms --json
codefire diff --trace --json
codefire impact --from main --to feature --json
codefire merge feature --dry-run --json
codefire review-pack feature --output review-pack.json
```

Diff algorithm policy:

| Algorithm | Use | Notes |
|---|---|---|
| Myers | default exact text diff baseline | predictable and widely understood |
| Patience | human review of refactors | better for moved unique lines |
| Histogram | large noisy files | often cleaner than Myers on repeated blocks |
| Binary summary | binary/artifact paths | hash, size, MIME guess, no payload diff |
| Atom diff | CodeFire semantic layer | Atom ID and content hash changes |
| Trace diff | CodeFire consistency layer | link and policy impact |

Structured diff output must include:

- file path before/after
- change kind: added, modified, deleted, renamed, copied, binary, conflicted
- similarity score for rename/copy
- hunks with stable line ranges
- affected Atom IDs
- affected links
- expected fires
- policy impact
- suggested next actions

Merge intelligence rules:

- CodeFire may suggest semantic conflict candidates but must not auto-resolve semantic conflicts in v0.6.
- textual auto-merge is allowed only when file-level 3-way merge is clean.
- Atom or TraceGraph conflicts create fires and must be explicitly extinguished.
- merge dry-run must report files to be modified before writing.
- review-pack output must be reproducible from sealed commits.

## Milestones

| Milestone | Target | Scope | Exit Criteria |
|---|---|---|---|
| v0.3 | Rust foundation | workspace, canonical JSON, object store, repository init/open/status | golden object tests; Python parity for init/status |
| v0.4 | Local workflow parity | scan, fire, extinguish, verify, commit, branch/clone/merge | existing local demo passes through Rust CLI |
| v0.5 | Remote parity and diagnostics | file/http remote, MR review/apply, signatures, doctor/gc, verify diagnostics | Python remote E2E parity subset passes |
| v0.6 | High-function Rust release | interactive/batch extinguish, metrics, storage report, artifact refs, migration checks | Rust CLI is default; Python CLI retained as fallback/reference |

Detailed milestone acceptance:

### v0.3 Rust Foundation

Must pass:

- `cargo test -p codefire-store`
- golden canonical JSON fixtures from Python
- `codefire-rs status` on Python-created empty and committed repos
- `codefire-rs doctor` detects known corrupted object fixture

Must not:

- update branch heads
- create incompatible object IDs
- replace installed `codefire`

### v0.4 Local Workflow Parity

Must pass:

- local `init -> open -> scan -> extinguish -> verify -> commit`
- `clone -> merge -> extinguish -> commit`
- duplicate Atom ID blocker
- stale resolution blocker and refresh flow
- Python can `doctor` a Rust-created local commit

### v0.5 Remote Parity

Must pass:

- file-backed upload/list/clone
- MR create/list/review/apply
- HTTP upload/list/show/diff/clone
- HTTPS smoke
- commit/request signature gates
- remote GC and retention tests
- server-side verification isolation smoke

### v0.6 High-Function Rust Release

Must pass:

- interactive extinguish smoke
- batch extinguish smoke
- `verify --details --blocking-only`
- `scan --metrics`, `verify --metrics`, `storage report`
- stable `--json` schemas for status, scan, verify, doctor, context, explain, storage, migrate
- stable exit code taxonomy tests
- context, next_actions, dry-run, batch, idempotency, evidence capture, lock timeout, and explain smoke tests
- Myers, patience, histogram, rename/copy, Atom diff, TraceGraph diff, merge dry-run, and review-pack tests
- external artifact reference sealing
- migration check for all compatibility fixtures
- installer installs Rust binary as `codefire` and Python fallback as `codefire-py`

## Governance

Development rules:

- no Rust write path before canonical JSON golden tests
- no installer switch before migration check supports all fixtures

## Risks

- canonical JSON incompatibility can corrupt object identity. Mitigation: golden tests before any write path.
- YAML parser behavior may drift from current limited subset. Mitigation: compatibility fixtures and explicit migration diagnostics.
- Rust rewrite can stall feature work. Mitigation: milestones preserve Python fallback until Rust reaches parity.
- tree-sitter dependencies can complicate packaging. Mitigation: optional feature flags and fallback extractors.
- external artifact refs can weaken reproducibility. Mitigation: store artifact hash, size, URI, timestamp, and retention policy in sealed objects.
- machine-readable interfaces can become accidental public APIs. Mitigation: version every schema and require compatibility review.
- rich diff heuristics can produce misleading confidence. Mitigation: report similarity scores and keep semantic conflicts as candidates.

## Risk Register

| Risk | Severity | Signal | Mitigation |
|---|---|---|---|
| Object ID drift | critical | golden hash mismatch | block write path until fixed |
| Rewrite scope creep | high | v0.4 parity slips while new features grow | enforce milestone gates |
| YAML behavior drift | high | existing config fixtures parse differently | compatibility parser tests |
| Remote security regression | high | signature/nonce tests fail | shared security crate and server tests |
| Slow scan on large repo | medium | metrics threshold exceeded | incremental cache and extractor profiling |
| Artifact reproducibility gap | medium | external artifact missing or hash mismatch | artifact ref validation and warnings |
| Packaging complexity | medium | install smoke fails on target env | binary + Python fallback installer |
| JSON schema churn | medium | external wrappers break between releases | schema versioning and snapshot tests |
| Idempotency collision | medium | same key used with different payload | payload hash comparison and exit code 33 |
| Misleading rename/copy detection | medium | review pack suggests wrong moved file | similarity threshold, raw diff fallback, user-visible confidence |
| Semantic conflict overreach | high | tool auto-resolves meaning-level conflict | no automatic semantic merge in v0.6 |
