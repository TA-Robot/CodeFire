# CFB-140: stale resolutionのrefresh導線がfire IDを提示せず、新規利用者が初回commitで行き止まる

## Summary

| Field | Value |
|---|---|
| Status | open |
| Severity | high |
| Type | bug / UX regression of CFB-001 |
| Area | Verify / Explain / next_actions / Extinguish refresh |
| Observed while | 2026-11-05 初回利用者walkthrough（`demo.sh` のfixtureをRust CLIで手動実行） |

## Observation

全fireをextinguishした後に `codefire.policy.yaml` とテストファイルを修正すると、`verify` は
`Blocking checks: stale resolutions` / `Stale resolutions: 6` でcommitを拒否する。
このとき:

- `scan` / `status` は `Open fires: none` / `0` を表示する。
- `verify --details` は `res_22023298dfc2: policy changed` のようにresolution UIDだけを表示する。
- `verify --json` の `data.stale_resolutions` も `resolution_uid` と `reason` だけで、fire IDを含まない。
- `explain verify-failure` と `next_actions` は `codefire extinguish <fire-id> --refresh ...` を提示するが、`<fire-id>` を埋める情報をどこにも出さない。
- `extinguish res_... --refresh` は `unknown fire` で失敗する。
- `extinguish --batch-template` は `requires at least one open fire` で失敗する。
- `--refresh` は `extinguish --help` のusageに載っていない。

以前の `scan` 出力からFIRE-IDを控えていた場合だけ、`extinguish FIRE-... --refresh` で復旧できた。

## Reproduction

```bash
# demo.sh の write_demo_files で fixture を作り、init / open / scan / 全fire extinguish の後に:
sed -i 's|command: .*|command: "python3 -m unittest discover -s tests -t ."|' codefire.policy.yaml
codefire verify --details        # stale resolutions、fire IDなし
codefire explain verify-failure  # <fire-id> placeholderのみ
codefire verify --json           # data.stale_resolutions[*] に fire_id なし
```

## Why It Matters

CFB-001の修正（`--refresh`）は、利用者がその時点でfire IDを知っていることを前提にしていた。
open fire 0件なのにcommitできず、CLIの出力だけでは次の操作を特定できない。初回利用と自動化の両方で
行き止まりになる。

## Candidate Fix

- stale resolutionのtext/JSON/explain diagnosticにfire display ID・fire UID・Atom pairを含める。
- `next_actions` を `ready=true` の完全なargvにする（fire IDを埋める）。
- `extinguish --refresh --all-stale` またはstale分を含む `--batch-template` を用意する。
- `extinguish --help` のusageに `--refresh` を載せる。

## Acceptance Criteria

- 上記の再現手順で、CLI出力だけを使ってcommitまで到達できる。
- `verify --json` のstale diagnosticごとに、実行可能な `refresh_resolution` actionが付く。
- CFB-001の既存テストを維持する。

## Related

- 同じwalkthroughで見つけた付随事項（別issue候補）:
  - `demo.sh` の `open main "$workdir/main"` はRust CLIでは `open target must not overlap repository root` で失敗する（demoはPython版前提）。
  - demo fixtureの `python3 -m unittest discover -s tests` はpytest形式の関数を検出できず、Python 3.12+では `NO TESTS RAN`（exit 5）になる。
  - `verify` のdefault出力は失敗したcheck名を示さず、`--details` でもexit codeを表示しない。
  - YAMLの引用符が壊れた `command` 値が `secret-like inline metadata` と誤診断される。
